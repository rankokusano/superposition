### 1.1 A：A-2 の規則の割合だけを変えた評価用データを作れるか
**元のデータの作り**：緑好み＝`simulation/collect_data_v11_s2t.py --dataset v11_s2t_green`（乱数の鍵 `v11_s2t`、test 300）、好み混合＝同 `--dataset v11_s2_pref`（鍵 `v11_s2`、train 3000 → test 300 の順に作り、test は通し番号 3000〜3299）。A-1 は RandomAgent（論文のランダムの歩き）、A-2 は `v11core/rule_agent.AgentPolicy('mixed', p_rule=0.5)`（A-2 自身の視界で好きな色へ向かう規則）。

**乱数の使われ方**（`sim_v10/simulation/agent/`、`v11core/rule_agent.py` を読んだ結果）：
| 何が決まるか | 乱数 | p_rule を 0.8 にしたとき |
|---|---|---|
| 配置の列（赤緑の入れ替え） | 専用 `RandomState(md5(<鍵>/layout))` | **変わらない** |
| A-2 の好きな色（好み混合） | 専用 `RandomState(md5(<鍵>/pref))` | **変わらない** |
| A-1・A-2 の初期位置 | python の `random`（`FieldObject.random_position`）、エピソードの初めに md5(<鍵>/<split>/<n>) で設定し直す | **変わらない** |
| A-2 の方式の抽選（規則かランダムか） | 専用 `RandomState(md5(<鍵>/<split>/<n>/a2_mix))`、起きている一歩ごとに1回 | 引く回数と値は**変わらない**（0.5 で規則の番だった一歩は 0.8 でも規則の番） |
| 眠りの時刻（A-1・A-2） | python の `random` だけ（起きている一歩のたびに1回、眠りに入るとき長さを1回）。目標の引き直しと規則の一歩は `random` を使わない | **変わらない**（呼ぶ順番が割合によらない） |
| A-1・A-2 のランダムの歩きの目標 | **numpy の共通の乱数**（`RandomAgent.reset_target`、目標に着くたびに2回） | **A-1 の目標も変わる** |

### 1.4 C：符号無作為データの作り方（指示書 §4.2 の確認項目）
- **データには快・不快 P の値が入っていない**。P はモデルの中で、隠す前の今の視界から計算される（`model_v12.compute_pleasure`、P = 赤 − 緑）。したがって「P の符号を反転したデータ」は、配列を書き換えるのではなく、**v14-C の仕組みをそのまま使う**：
  - データ：`v13_s1_mixed80` の全配列（train 3000・test 300）をそのまま写し、エピソードごとの `a1_liked`（1 = 赤、0 = 緑）と、それを一歩ごとに広げた `a1_liked_t`（(N, 101)）を足す（`simulation/make_randompref_v14.py` と同じ形）。**符号を反転するエピソードでは `a1_liked` = 0**。
  - モデル：`model_v14.SuperpositionNetworkMotionPleasureHoldSigned`（P = s ×（赤 − 緑）、s = 2 × `a1_liked_t` − 1）、学習は `train_v14.py`（`exp/loader_v14.py` が `a1_liked_t` をモデルに渡す）。v14-C の好み切替条件の学習と同じ。
  - 反転したエピソードでは A-1 は赤へ向かうが、P では緑が快い。
- **反転の抽選**：専用の `RandomState(md5('paper_c_signrand/a1_sign'))` で train → test の順に 1 エピソード 1 回 `rand() < 0.5` なら反転。配置の抽選（`md5('v11_s1/layout')`）とは別の乱数なので独立。どのエピソードを反転したかは `a1_liked` そのもの（と JSON）に残す。
- **運動を隠す区間と、快・不快を保つ処理は P の値に依らず同じに作られる**（コードで確かめた）：
  - 隠す区間は `init_state` のたびに `make_schedule` が torch の CPU の乱数（`torch.randint`）で引く。データの中身を見ない。
  - 保つ処理（`SuperpositionNetworkMotionPleasureHold.process1_input`）は、隠す区間の最初の一歩の P をその区間のあいだ保つ。符号つきのモデルでは符号をかけた後の P を保つが、符号はエピソードの中で一定なので、保つ時刻も保つ値の作り方も同じ（値の符号だけが違う）。
  - したがって、学習の乱数（初期値・バッチの順番・隠す区間・dropout）は同じ組の経験80%条件と同じになるはず（モデルの重みの数は同じ。v14-C の学習でも ep0 が v12 と一致した）。起動の前に ep0 の重みの一致を確かめる。
- **確認（データを作った後）**：train・test とも、`a1_liked`・`a1_liked_t` 以外の全配列が `v13_s1_mixed80` とビット単位で一致。反転の割合（約 1/2）と、配置 × 反転の4つの組み合わせの数。数エピソードで、符号つきのモデルの `compute_pleasure` が反転したエピソードでだけ符号違いになることを確かめる。
- 大きさ：約 2.0 GB（`v13_s1_mixed80` と同じ）。シミュレーションはしない（h5 の写しだけ、CPU は軽い）。
- C の学習・評価の事前登録と起動の案は、このあと 13 時までに §4 として書く。

### 1.5 装置：CPU と GPU の値、所要時間
- **乱数に依らない評価**：A（真値条件・零）と、B の照合（実験4）、G5a・符号に従う分は、視覚を t = 0 だけ見せ t > 0 は p = 1 で隠す。p = 1 の隠しは乱数に依らないので、**CPU と GPU の違いは浮動小数点の計算の違いだけ**になるはず（ビット単位で一致するとは限らない）。
- **乱数に依る評価**：G5b、G1〜G3、h² → A-2 の位置は、段階Iの学習と同じ視覚の隠し（p = 0.99、t > 0）と運動の隠す区間を使う。隠しの乱数は装置の乱数（GPU なら CUDA の乱数）から引くので、**CPU と GPU では値が変わる**（v11 のまとめの注意はこれ）。→ **B は GPU で回すのがよい**（既存の値が GPU で測られているので、同じ装置で測れば比べやすい）。

  - GPU（実測ではなく既存の出力の時刻から）：`eval_d6_v12`（2 データ × 3 通り、A-2 の位置の読み取りつき）の組5 の経験なし → 経験80% の出力の間隔が 16 秒（GPU を他の計算と共有していたとき）→ 1 通り約 2.7 秒。A は 1 モデル 8 通りで約 22 秒 → **18 モデルで約 7 分**（読み込みを足して 10〜15 分の見込み）。
  - どちらでも 13:30 までに十分終わる。

### 7.2 A-1 の動きは A-2 の位置に依らないか（§6 の 2 (a)）
- `sim_v10/environment.py`・`simulation/world.py`・`simulation/agent/*.py`・`v11core/rule_agent.py` を読んだ。**エージェントどうしの衝突・重なりの処理はない**。A-1（RandomAgent）の一歩は `walk()`（自分の位置と目標だけ）、目標に着いたかの判定（自分の位置と目標）、目標の引き直し（場の境界と numpy の乱数）、眠り（python の `random`）だけで決まり、A-2 の位置は使わない。`world.draw` は2体の位置を描くだけ。→ 再生で A-1 と A-2 が重なっても動きは変わらない（元のデータでも重なりは起こりうる）。重なる場面の数は記述として数えるが、作りには影響しない。
- A-2 の規則の一歩は A-2 の視界（A-1 が写る）を使うので A-1 の位置に依る。A-1 は元と同じ位置に再生するので、この依り方も元と同じ。
