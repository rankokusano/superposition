## 1. 背景

### 1.1 元論文（ベースモデル）
Noguchi, Iizuka, Yamamoto & Taguchi (2022), *Scientific Reports* 12:2859, "Superposition mechanism as a neural basis for understanding others"。公式実装は https://github.com/wtrnoguchi/superposition （リポジトリ root がその clone）。

- A-1 は、自分の視界（16×64 RGB、全方位）と自分の運動を受け取り、次の視界を予測するよう学習する。
- 2つの Encoder（同じ構造・別の重み）が、**どちらも A-1 自身の視界**を読む。A-2 は A-1 の視界の中に黒い立方体として映るだけで、A-2 の視界はネットワークに入らない。
- 1つの LSTM（共有モジュール、128ユニット）を process-1 と process-2 で共有する（重みは同じ、記憶は別）。process-1 には A-1 の運動、process-2 には零ベクトルが入る。
- 統合部が h¹ と h² をまとめ、Decoder が A-1 の次の視界を出す。
- 学習中、Encoder の出力を 99% の確率で零に置き換える（視覚がない間も運動を積み上げて位置を追うことを学ばせるため）。
- 結果として、自己と他者の位置、他者の視点（Fig.5）、他者の運動（Motion Generator、Fig.6）の表現が、予測学習だけで生まれた。
- 元論文は2段構成：A-2 が静止するデータで全体を学習（exp1）し、その後 A-2 が動くデータで Motion Generator だけを学習（exp3）。

### 1.2 本研究のこれまで（v4〜v10）
- v4〜v6：process-1 の入力を「運動」から、外の critic（SAC で学習）が計算した8方向の Q値（probe-Q）に置き換えた。自己位置は保たれたが、他者の価値は生成できなかった。
- v7：A-1 の critic を部品にした逆強化学習。動く向きだけで目標が当たってしまい、価値を使っていると言えなかった。
- v10：赤と緑のランドマークの位置を入れ替える環境（`sim_v10`）を作った。既存の critic・actor は目標を**場所**で捉えていた（入れ替えても最良方向はほぼ不変）。入れ替えのある環境で critic を学習し直すと、価値が**色**についていくようになった（ただし学習は不安定）。

### 1.3 指導教員の指摘（v11 の出発点）
- 今は価値が位置と結びついてしまっている。本当は**価値と行動**が結びついてほしい。まずは**価値と色**が結びつくか。
- 「行動の頻度に差を出す」「好きなところの方が行動頻度が高い」。
- 「ネットワーク自身も強化学習ぽくなってないと」。
- 「頻度を扱う強化学習を持ってくるのは、強化学習のモジュールを作っているだけかも」。
- 「近づかないものには報酬が低いのをどうやって学習させるか」「相手が近づくからと言ってプラスかどうかはわからない」。

### 1.4 v4〜v10 で価値と行動が結びつかなかった理由
- v4〜v10 の学習データでは、**A-1 はランダムに歩いていた**。どの方向の価値が高くても A-1 の動きとは無関係なので、価値は「今どこにいるか」の手がかりにしかならなかった。
- また価値は外の critic（強化学習）が計算したもので、共有モジュールが価値を自分で作ったわけではなかった。

## 2. v11 の問いと中心仮説

### 2.1 問い
**自分が好みに従って動いた経験があると、他者の動きの傾向を見て、他者の好みが分かるようになるか。** その前提として、まず**自分の中で、価値が色と行動に結びつくか**（この指示書の範囲）。

発達心理学の Woodward (1998)・Sommerville, Woodward & Needham (2005) の課題（乳児が他者の目標を場所ではなく物として捉えるか、自分で物をつかむ経験がそれを生むか）に対応させている。

### 2.2 鍵になる設計の考え方（必ず理解してから作業すること）
1. **運動を入力に入れない。** 元論文の構成では、ネットワークは v_t と m_t（その一歩の運動）を受け取って v_{t+1} を予測する。変化の原因の m_t がもう入力に入っているので、「自分がどちらへ動くか」を推し量る必要がない。運動を入れると、好みに従って動いた経験があっても、共有モジュールは「快の高い方へ動く」を覚える理由がない。
2. **代わりに「方向ごとの快・不快」を入れる（§3.2）。** 8方向それぞれについて、今その方向に自分にとって快いもの（好きな色）・不快なもの（嫌いな色）がどれだけ見えているか。今の視界から直接計算する、生まれつきの感覚に近い信号で、外の critic は使わない。
3. **予測の対象は元論文どおり「次の視界」だけ。** 補助の予測を足さない（足すのは、試し学習や関門で結びつきが弱かったときの補強案。§6.2）。
4. **何が生まれつきで、何を学ぶのか**：
   - 生まれつき（入力）：「赤が見えると快い、緑が見えると不快」。
   - 学ぶもの①（両条件で学ぶ）：「この方向へ進むと、見えるもの（と快・不快）がこう変わる」。次の視界の予測を通じて学ばれる。ランダムに歩いても学べる。
   - 学ぶもの②（経験ありの条件だけで学ぶ）：「自分は快の高い方へ動きやすい」。運動が入力されないので、次の視界を当てるには自分の動きを推し量る必要があり、経験ありの A-1 では快の高い方へ動くことが多いので、その傾向（頻度の偏り）を覚える。
5. **比較は2条件**：A-1 が「ランダムのみ」で動く（経験なし）か、「一歩ごとに半分は好みに従い、半分はランダム」で動く（経験あり）か。それ以外はすべて同じにする。ランダムを混ぜるのは、嫌いな緑の近くも経験させるため（①のため）。

### 2.3 中心仮説（元論文の仮説に対応するもの）
- 元論文：自分の次の視界を当てるには、視界に映る他者を追う必要がある。共有モジュールの「自分の位置を追うしくみ」を他者にも使うことで、他者の位置の表現が生まれた。
- v11（1段目）：運動が入力されないので、A-1 は次の視界を当てるために自分の動きを推し量る必要がある。経験ありの A-1 は快の高い方へ動きやすいので、共有モジュールの中で**「方向ごとの快・不快が高い方へ、自分の位置が移っていく」というしくみ**ができる。経験なしでは、このしくみはできない。
- v11（2段目、この指示書の範囲外）：このしくみを他者に使えば、A-2 の動きを「A-2 にとってその方向が快い」という形で表すことになり、他者の価値の表現が生まれる、と予想している。

### 2.4 この指示書で主張できる形
- 成功した場合：「予測学習するネットワーク自身の中で、自分の価値が色と行動に結びつき、それは自分の行動経験から生まれる」。
- 主張しないこと：「他者の価値が分かった」（2段目の範囲）。

## 3. 環境・入力・動き方の仕様

### 3.1 環境
- v10 の `sim_v10`（赤と緑の位置を入れ替えられる環境）をそのまま使う。配置は `layout.py` の1か所で選ぶ（`original` / `swap_rg`）。
- 20×20 のアリーナ。ランドマークはアリーナの外の立方体（中心 ±13）。元の配置：緑 (−9,−9)、赤 (−9,9)、青 (9,−9)、シアン (9,9)（基準位置は (±9,±9)）。入れ替え後は赤と緑が入れ替わる。
- 全方位の視界の列は**世界の方角に固定**されている（列 64 本が 360° に対応。v10 で確認済み）。
- 色の判定：「該当チャンネル > 0.9、他 < 0.1」。プロジェクトで「赤」と呼ぶ色は、mtl では `blue` マテリアル（BGR で読むため）。v10 のログを参照。
- 報酬の定義（v4 から不変）：A-1 は「赤の割合 − 緑の割合」、A-2 は「緑の割合 − 赤の割合」。値の範囲はおよそ ±0.164。

### 3.2 process-1 の入力：方向ごとの快・不快
- 全方位の視界（16×64）を、列で 8 つの方向の範囲に区切る（64 列を 8 等分。区切りの位置と、各範囲がどの方角に当たるかを §6.0 で確認して報告）。
- 各方向について、A-1 にとっての快・不快を計算する。基本案：その範囲の画素のうち「赤と判定される画素の割合 − 緑と判定される画素の割合」。
- 決める必要がある細部（§6.0 で案を出して私の確認を待つ）：
  - 快と不快を1つの数（8次元）にするか、快と不快を別々（16次元）にするか。
  - 値の大きさの調整（定数倍して、おおよそ ±1 に収まるように。定数は事前登録）。
  - 計算はマスク前の視界から毎時刻行う（v4 の probe-Q と同じ。視覚のマスクとは独立）。
  - 計算を forward の中で行うか、データに保存して読むか。
- **運動は process-1 に入れない。**
- process-2 の入力は、同じ次元の零ベクトル（1段目では A-2 は静止しているので、元論文の exp1 と同じく零）。

### 3.3 A-1 の動き方

| 条件 | 動き方 |
|---|---|
| 経験なし（`a1_random`） | 既存の RandomAgent（元論文と同じ） |
| 経験あり（`a1_mixed`） | 一歩ごとに、50% の確率で「視覚の規則（好きな色＝赤）」の一歩、50% の確率で RandomAgent の一歩 |

**視覚の規則（好みに従う一歩）**
- 視界の中で好きな色（赤）が見える列の方角へ、速さ 1 で一歩進む（例：赤と判定される画素の列の円周上の重心の方角）。
- 嫌いな色（緑）から離れる成分も入れるか（例：「赤の方角のベクトル − 緑の方角のベクトル」の向き）は、§6.0 で案を出して私の確認を待つ。
- 好きな色が視界にないときは RandomAgent の一歩にする。
- 学習はいらない。強化学習の critic・actor は使わない。
- 2段目では A-2 が同じ規則で緑を好きな色として動く予定なので、好きな色・嫌いな色を引数で指定できる形にすること。

**そろえること**
- 好みに従う一歩も、RandomAgent の一歩も、**速さは 1**（違いは向きだけ）。RandomAgent の眠り（確率 0.005 で 10〜30 ステップ止まる）を、規則の一歩の間も続けるかは §6.0 で案を出すこと。
- 一歩ごとの抽選は、環境の乱数を乱さないよう**専用の乱数**で行う。
- 各一歩がどちらの方式だったかをデータに記録する（`a1_source`、一歩ごと）。
- 2条件の間で、エピソードごとの配置・A-1 の初期位置・A-2 の位置は**同じ**にする（同じエピソード番号どうしを対にできるように）。違うのは A-1 の動き方だけ。

### 3.4 A-2
- 1段目では、エピソードごとにランダムな場所に置き、**静止**（元論文の exp1 と同じ）。
- データには A-2 の視界（`other_vision`）も保存する（Fig.5 の評価に使う）。

### 3.5 データ
- 配置：エピソードごとに 50% の確率で入れ替え（`mix`）。配置のラベルをエピソードごとに保存。
- エピソード数：train 1000（元論文と同じ）。eval・test の構成は元論文・v10 の収集スクリプトに合わせる。**（→ 更新：train 3000、test 300）**
- 長さ：1エピソード 100 ステップ（元論文と同じ）。
- 収集の決まり（v10 と同じ）：視覚は uint8、シードはデータセット名から決めて HDF5 属性に記録、少量で bit-identical な再現を確かめてから本収集。

### 6.4 自己側の関門（評価）
すべて経験あり・なしの2条件 × 3シードで比べる。

- **M1：価値と行動の結びつき（中心の測定）**：(a) 推し量った位置の偏り（h¹ からの自己位置の読み出しのずれを赤の方向へ射影）、(b) 入力を操作したときの反応（視覚を隠し、ある1方向だけ快を高くして、読み出した位置がどちらへ移るか。8方向）。
- **M2：価値と色の結びつき**：入れ替えた配置で、M1 の偏りが新しい赤の位置の方を向くか、元の赤の場所の方を向くか（角度差、v10 段階Aと同じ指標）。
- **M3：世界の仕組み（①）**：次の視界の予測の誤差（自己）を両条件で比べる。
- **M4：価値の地図**：M1 の偏りの向きをアリーナの地図に矢印で描く。両配置、両条件。
- **M5：内部状態から自分の価値を読み出す**：h¹ から、その瞬間の報酬、割引和（例 0.9）、赤の方角（cos・sin）を線形回帰（R²、エピソード単位の交差検証）。配置をまたいで読めるかも見る。M1・M2 と並べて解釈する。
- **M6：v10 と同じ自己側の測定**：h¹→自己位置の R²、配置の読み出し（v10 の B4 と同じ方法）。
- **M7：基本の健全性と予測画像**。

**判断の基準**
- 「価値と行動が結びついた」：経験ありのモデルで M1(a) の赤の方向への偏りがプラスで、95% 信頼区間（エピソード単位のブートストラップ）が 0 を含まない（3シード中2本以上）。かつ、経験なしのモデルとの差の信頼区間が 0 を含まない。M1(b) でも、経験ありのモデルだけで快を高くした方向へ移る。
- 「価値と色が結びついた」：入れ替えた配置で、M1 の偏りの向きと新しい赤の方向との角度差の平均が、元の赤の場所の方向との角度差の平均より 15° 以上小さい。
- どの結果でも、そのまま報告すること。2段目に進むかどうかは私が判断します。
