## 1. 目的
- **段階1**：いちばん大きなリスク（自他の揃いと色の区別の両立）を、本体の学習の前に確かめる。元論文と同じ作り（運動だけ）を、新しい環境のデータ（A-1 が好みに従って動く）で一から学習する［§8.3、方針の段階1］。
- **段階2**：新しい環境で、自分側の見込み（食べた後に次に好きな色へ向かう）と、他者の好みの推定が出るかの見込みをつける［§15.1、§16］。
- **本命の検査**：食べた後に、さっき食べた色（相手の好み）を覚えておき、次の向かう先の予測に使えるか。方角と色と順位の結びつけを問う検査として使う［§10.1 の 1］。

## 2. 作業場所と運用の約束
1. 作業場所は worktree `.worktrees/v15`、ブランチ `feature/v15-preference-order`。v11〜v14 のコード・データ・結果は変えない。結果は `data/result/v15/` と `v15_*` にだけ書く［§2、指示書 §2］。
2. **GPU**：空きを確かめ、何をどこで回すかと見込み時間を報告してから起動する［§15.1］。論文の実験を優先する［指示書 §2 の 10、§8.1 の 2］。GPU0 は使わない［§13］。論文のための学習が終わった後（2026-10-26）は、空いている GPU を使ってよい［§15.1］。
3. CPU の作業は `nice -n 10` を付け、並列の数を控える。sklearn などは `OMP_NUM_THREADS=2`［§1、§10.1］。
4. **ディスク**：空きが 15 GB を切りそうになったら報告する。次の三つは確認なしで消してよく、消したらログに記録する：`v15_s1_p80_3000`（灰色は毎回）、段階0 の全エピソードの 2 回目の生成（`data/result/v15/datacheck/*_full_repeat.h5`）、試しのデータ（`data/result/v15/devtest`）。段階2 の前の案のデータ（`v15p_*`）は、消す前に確認を取る（2026-10-26 の草野さんの指示。ログ §17 に記録）。
5. 判定の基準は、計算の前にログに事前登録としてコミットする。結果を見た後に加えた確認は「事前登録外」と書く［指示書 §2 の 5］。
6. データの生成は乱数を固定し、2 回生成してビット単位で一致することを確かめる［指示書 §2 の 6、§12.2、§15.2］。
7. 図は目視してから報告する。図の一覧に、パス・目視確認の有無・何を示すかを書く［§10.1 の 3、§14.6］。
8. 記録とコミットと push は区切りごとに行い、報告にはコミットの番号を書く。報告は日本語で、何が分かったか → 根拠の数値 → 判断してほしいこと、の順に書く［指示書 §2 の 8・9］。

## 3. 環境の変更：灰色は「半分の回だけ」［§12］
- 段階1・段階2 の両方で、各エピソードで 1/2 の確率で灰色をなくす（全色がそろう）。灰色にする回の色は、前と同じ列から引く［§12.1、§12.2］。
- 理由：4 色がそろった景色を Encoder に見せるため、学習の材料（次の目標がある食べた直後の場面）を 0.49 回から 0.70 回 / エピソードに増やすため［§11.1、§12.1］。
- 配置は 10 通り（配置 2 × 灰色 5）［§12.2］。生成する組と ③ の作り（灰色の色を決めて作る）は変えない［§11.1］。
- 段階2 の 2 段目のデータは 6000 エピソード。1 段目（自分）のデータは 3000 のまま［§12.1 の 3］。

## 4. 段階1

### 4.1 作り［§8.3、§12.3］
- データ：`v15_s1_p80_half_3000`（train 3000 + test 300、灰色は半分の回）。Fig.5 の Decoder は `v15_s1_p80_half_first1000`［§12.2］。
- v12 の E1 と同じ作り：元論文の `SuperpositionNetworkFeaturePrediction`（運動だけ）を一から学習する。mse 段 200 エポック → l1 段 200 エポック（Decoder だけ）、seed 0。
  - (i) 普通の損失：`v15_s1_plain_{mse,l1}`
  - (ii) 色の誤差を重く見る損失：`v15_s1_colour_{mse,l1}`。普通の損失 + λ = 10 × 色み（RGB − 3 チャンネルの平均）の誤差
- Fig.5 の Decoder：mse 段の ep100・150・200 で、Encoder を凍結して 100 エポック学習する。

### 4.2 測るものと判定［§8.4、§8.5］
- M1 自他の揃い（v15 の test。v11 の共通の test も参考に出す）。M2 Fig.5 のマージン（記述）。M3 Encoder-2 から各隅の状態を線形に読む精度。M4 取り出した視点での赤と緑の分離 sep。
- 合格：どちらか 1 本が mse 段 ep200 で、M1 ≥ 0.70、M3 がどの隅も ≥ 0.90、M4 sep ≥ 1.0 かつ画像で描き分けられる（目視）。

### 4.3 結果［§14］
- **2 本とも不合格**。
  - (i)：M1 0.692、M3 の最小 0.644、sep −0.002
  - (ii)：M1 0.216、M3 の最小 0.786、sep −0.044
- 考察の材料として残すこと［§15.1］：
  - 「揃いと色の区別が、新しい環境でも両立しない」こと。
  - (i) で A-1 が好みに従うデータにしただけで、色の読み取りが上がったこと（左上 0.84、v4 0.70、E1 0.57）。
- 図の一覧は §14.6。

### 4.4 追加の探索（事前登録外、段階2 と並行）［§15.1、§15.3］
- 色の損失の重みを 1 と 3 にした 2 本（`v15_s1_colourl1`、`v15_s1_colourl3`。ほかは (ii) と同じ）。重み 0 と 10 の間に、揃いと色が両立する点があるかを見る。
- (i) を 6000 エピソードで学習する 1 本（`v15_s1_plain6k`、データは `v15_s1_p80_half_6000`）。
- 測るものと目安は段階1 と同じ。**どれかが目安を満たしたら報告する**（その Encoder で段階2 をもう一度回すかは草野さんが判断する）。
- GPU1（重み 1）、GPU2（重み 3）、GPU3（6000）［起動は 2026-10-26。ログ §17 に記録］。

## 5. 段階2

### 5.1 作り［§16.1、§16.7 の 3］
- ネットワークは v12 の作りのまま、快・不快だけを v15 の形（Σ 価値 × 画素 / 128、A-1 の価値は赤 1・青 0.5・シアン 0・緑 −1、灰色 0）にする（`model/model_v15.py`）。
  - 1 段目は `...HoldV15`。2 段目は `...HoldOtherV15` で、部品 G は v12 の正式の形（8 次元の tanh を process-2 の快・不快の枠に入れる。出力の制限なし）。
- Encoder（凍結）：**主 v4**、**比較 v15 (i)**。**どちらの Encoder で結果が出ても、除かずに報告する**。
- 経験あり（`v15_s1_p80_half_1000t`）・経験なし（`v15_s1_random_half_1000t`）［§15.2］。
- 試しの規模、seed 0。1 段目は mse 150 エポック、2 段目は G だけを l1 150 エポック（データ `v15_s2_c2_p80_half_1000t`）。合わせて 8 本。共有しない対照（NS）は試しでは入れず、本番で入れる［§15.1］。
- GPU4〜7（経験あり v4、経験なし v4、経験あり v15 (i)、経験なし v15 (i)）［ログ §17 に記録］。

### 5.2 事前登録（測るものと合格の形）［§16.2〜§16.5、§16.7］
- 読み出し：位置は隠れ状態から線形に読む（h1 → A-1、h2 → A-2。Ridge、エピソード単位で 2 分割）。K = 10 ステップの予測の変位 d と、次の目標への向きの cos（c_next）、および正解率［§16.2］。
- **1 段目**［§16.3］（test = `v15_s1_p80_half_3000` の test）：
  - P1-a 自己位置：運動が見えるフレームで R² ≥ 0.80（前提）
  - P1-b 相手の位置：記述
  - P1-c 食べた後の見込み：視界と運動を隠し、快・不快を t_e の値に保つ。経験ありの c_next > 0、かつ 経験あり − 経験なし > 0（95% 区間）
- **2 段目**［§16.4］（test = `v15_s2_c2_p80_half_6000` の test、A-2 が食べた瞬間）：
  - P2-a 相手の本当の快・不快を与えたときの食べた後の予測（1 段目のモデル）：経験ありの c_next > 0、かつ 経験あり − 経験なし > 0
  - P2-b 逆推論（1 段目のモデル、候補 X・Y）：主は**食べた後**の 10 ステップの誤差で選ぶ。方角の外挿や位置で当たりうるので (a)・(b0) を並べ、食べる前のフレームで選んだ値も記述として出す［§16.7 の 2］
- **本命**：
  - **P2-c**（書き出す形、2 段目のモデル）［§16.4］：生成する組（963 組、食べた後の視界が完全に同じ）。t_e より後は入力の視界を t_e のフレームで止め、h2 から読んだ A-2 の変位が青（X）とシアン（Y）のどちらに近いかを見る。
  - **P2-c′**（当てて選ぶ形、1 段目のモデル）［§16.7 の 1］：同じ組で、**食べる前のフレームだけ**の予測の誤差で候補 X・Y を選び、選んだ候補の次の目標を予測とする。
  - 合格の形（どちらも、Encoder ごと）：経験ありで組の正解率が 0.5 を、経験あり − 経験なしが 0 を、組単位の 95% 区間で超える。(a)・(b0) は作りの上で 0.5。
- **③ の対照**：P2-c と同じ手順を ③ の組に当てる。0.5 程度のはずで、0.6 を大きく超えたら漏れを疑う［§16.4］。
- 記述：② の test のすべての食べた瞬間での P2-c と同じ正解率と (a)。Q2 の形（範囲ごとの分散の割合、Q2 と本当の P_A2 の相関、Q2 から候補を読む精度）［§16.4、§16.7 の 3］。
- 判定のまとめ［§16.5］：主は v4。v4 の経験ありで P2-c（と P2-c′）が合格の形なら「本命の見込みあり」とし、本番（3 組、NS を含む）に進むかを草野さんが判断する。試しは 1 組なので、合格の形は「見込み」として扱う。
