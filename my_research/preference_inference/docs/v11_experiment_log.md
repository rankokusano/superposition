## 1. 背景の要約（指示書 §1）

- **元論文**（Noguchi et al., 2022）：A-1 は自分の視界（16×64、全方位）と自分の運動から、次の視界を予測する。
  - 2つの Encoder がどちらも A-1 の視界を読む。
  - 共有 LSTM（128）を process-1（自己、入力＝運動）と process-2（他者、入力＝零）で使う。重みは同じで、記憶は別。
  - 学習中は視覚を 99% の確率で隠す。予測学習だけで、自他の位置・他者の視点・他者の運動の表現が生まれた。
  - 2段構成：exp1（A-2 静止、全体を学習）→ exp3（A-2 が動く、Motion Generator のみ学習）。
- **v4〜v6**：process-1 の入力を、外の critic による 8 方向の probe-Q に置き換えた。自己位置は保たれたが、他者の価値は生成できなかった。
- **v7**（逆強化学習）：動く向きだけで目標が当たってしまい、価値を使っているとは言えなかった。
- **v10**：赤と緑を入れ替える環境 `sim_v10` を作った。既存の critic・actor は目標を**場所**で捉えていた。入れ替えのある環境で学習し直すと、critic の価値は**色**についていったが、学習は不安定だった。
- **指導教員の指摘**：
  - 価値が位置に結びついている。本当は**価値と行動**が結びついてほしい。まずは**価値と色**が結びつくか。
  - 「好きなところの方が行動頻度が高い」。
  - 「ネットワーク自身も強化学習ぽく」。ただし「頻度を扱う強化学習を持ってくるのは、モジュールを作っているだけかも」。
  - 「近づかないものには報酬が低いのをどう学習させるか」。
- **v4〜v10 で結びつかなかった理由**：
  - A-1 はランダムに歩いていたので、価値は「今どこにいるか」の手がかりにしかならなかった。
  - 価値は外の critic が計算したもので、共有モジュールが自分で作ったものではなかった。

## 2. v11 の問いと中心仮説（指示書 §2）

- **問い**（この指示書の範囲）：自分の中で、価値が色と行動に結びつくか。最終的な問いは「自分が好みに従って動いた経験があると、他者の好みが分かるか」（2段目）。発達心理学の Woodward (1998)、Sommerville et al. (2005) に対応する。
- **設計の要点**：
  1. 運動を入力に入れない（入っていると、自分の動きを推し量る必要がない）。
  2. 代わりに「方向ごとの快・不快」（今の視界から直接計算する、生まれつきの感覚）を process-1 に入れる。外の critic は使わない。
  3. 予測の対象は次の視界だけ。
  4. 両条件で学ぶもの①：「この方向へ進むと見え方がこう変わる」。経験ありの条件だけで学ぶもの②：「自分は快の高い方へ動きやすい」。
  5. 2条件（ランダムのみ／一歩ごとに 50% 好み・50% ランダム）の違いは、A-1 の動き方だけ。
- **中心仮説**：運動が入力されないので、A-1 は次の視界を当てるために自分の動きを推し量る必要がある。経験ありの A-1 は快の高い方へ動きやすいので、共有モジュールの中に「方向ごとの快・不快が高い方へ、自分の位置が移っていく」しくみができる。経験なしでは、このしくみはできない。
- **主張できる形**（成功した場合）：「予測学習するネットワーク自身の中で、自分の価値が色と行動に結びつき、それは自分の行動経験から生まれる」。**主張しない**：「他者の価値が分かった」。

### 3.1 元論文の1段目（exp1）の学習設定
- `exp1_mse(_1000)`：

- `exp1_l1(_1000)`：

### 3.2 列と方角の対応（既存の `grid` を読み取りだけで解析）
- **列 c の中心の方角 = (c+0.5)·5.625° − 180°**（アリーナ座標の atan2(dy,dx)。y は世界の z）。441 点 × 4 ランドマークで、立方体の中心への方角との残差は平均 2.4°、最大 8.7°。
- 各ランドマークは**ちょうど 16 列の象限を1つ**占める。元の配置で、緑 0〜15（−180°〜−90°、南西）、青 16〜31（南東）、シアン 32〜47（北東）、赤 48〜63（北西）。8 列が1台のカメラに当たる。
- ランドマークが見えなくなるのは、そのランドマークに接する角（例：赤なら (−10,10)）だけ（格子の 441 点中1点）。

### 3.3 描画なしの幾何計算による見込み（スクラッチパッド、2000 エピソード）
- 赤を「立方体の中心 (−13,13) の方向」で近似した。赤の基準位置 (−9,9) から 5 以内にいるフレームの割合と、最初に 5 以内に入る時刻の中央値は次のとおり。

## 4. 設計判断とその理由（2026-10-17、草野さんの了承による。Methods 用）

**4.1 作業場所を git worktree で分ける。** v10 のチャットが同じリポジトリで学習と評価を続けているので、同じ作業ツリーでブランチを切り替えると v10 を壊す。コンテナのマウントは `/home/kusano/superposition → /work` の1本だけなので、worktree はリポジトリの中（`.worktrees/v11`）に作った。

**4.2 1段目の train は 3000 エピソード、test 300**（指示書の受け取り後の更新と、草野さんの了承）。
- train の 3000 は v4〜v10 と同じ規模。元論文の 1000 より学ぶことが多いため。
- test を元論文の 100 から 300 にしたのは、M1・M2 の信頼区間に十分なエピソード数（配置ごとに約 150）を確保するため。
- viz20 は、train の配置ごとの先頭 10 エピソード（v10 と同じ作り方）。

**4.3 方向ごとの快・不快の区切りは、8 台のカメラの境目とする**（範囲 k＝列 8k〜8k+7、中心の方角 −157.5°+45k）。
- どちらの配置でも、赤と緑が同じ範囲に入らない（それぞれ1象限＝2範囲を占めるため）。
- 中心を 0°, 45°… に合わせると、西の範囲に赤と緑の端が両方入って打ち消し合う（例：(0,0) で西の範囲が 0 になる）。

**4.4 値は1方向に1つの数（8次元）：(範囲内の好きな色の画素数 − 嫌いな色の画素数) / 128、定数 c=1。**
- 4.3 の区切りでは、好きな色と嫌いな色が同じ範囲に重ならないので、16 次元に分けても情報は増えない。
- 値は構造的に [−1, 1] に収まる。格子では |値| の最大が 1.0、0 でない値の 99 パーセンタイルが 0.90。中央付近では ±0.09、(−8,8) では 0.37。
- 計算は**マスク前の v_t から forward の中で毎時刻**行い、データには保存しない（v4 §4.6 と同じ考え方）。
- 好きな色と嫌いな色は引数で指定できる（2段目で A-2 にとっての値を計算するため）。
- process-2 には同じ次元（8）の零ベクトルを入れる。

**4.5 嫌いな色は行動には表れず、入力（快・不快のマイナス）にだけ表れる。** 視覚の規則は「好きな色に近づくだけ」とした。
- 「赤のベクトル − 緑のベクトル」にすると、元の配置で赤（北西）と緑（南西）の差がほぼ真北を向き、「赤へ向かう」から大きくずれるため。
- このため経験ありの A-1 が緑から離れるのは、赤へ近づくことの結果としてだけである。嫌いな色は process-1 の入力の負の成分として、両条件で同じように入る。

**4.6 視覚の規則の一歩。**
- 好きな色と判定された画素の、列ごとの数を重みにした**円周上の重心の方角**（3.2 の対応）へ、速さ 1 で一歩進む。
- **壁では滑る**：アリーナの外へ出る軸の成分を消し、長さ 1 に直す（必要なら繰り返す）。
  - 何も残らない場合（角）と、好きな色が見えない場合（角に接したとき・A-2 に隠れたとき）は、RandomAgent の一歩にする。
  - 理由：赤の立方体はアリーナの外にあるので、規則の一歩は壁へ押しつける。位置を切り詰めるだけだと、速さが 1 未満の一歩が約 8% 生じ（3.3）、「違いは向きだけ」にならない。
- どちらの方式の一歩の後でも、RandomAgent と同じ目標到達の判定（目標から 1.5 以内なら目標を引き直す）をかける。RandomAgent の「一歩の前は目標から 1.5 以上離れている（だから行き過ぎない）」という性質を保つため。

**4.7 眠りはエージェント全体の状態とする。**
- 眠っている間は、どちらの方式でも動かない（`a1_source`＝3）。
- 眠りに入る抽選（確率 0.005、10〜30 ステップ、元と同じ python の `random`）は、動いた一歩のたびに方式によらず行う。
- これで両条件の眠りの割合が期待値で同じになり、速さの分布の違いは向きだけになる。

**4.8 エピソードごとに乱数を設定し直し、2条件で共通のキー `v11_s1` を使う**（v10 の「データセット名の MD5 から決める」という決まりからは外れる）。
- 理由：経験ありの条件は、RandomAgent の目標の引き直しや眠りの抽選の回数が変わるので、乱数を1回だけ設定すると、2つ目以降のエピソードの初期位置・A-2 の位置が2条件でずれる。
- 方法：エピソード n の開始時に `random.seed(s)`、`numpy.random.seed(s)` とする。s = md5(`v11_s1/<split>/<n>`)。
- これで、同じエピソード番号では、初期位置・最初の目標・A-2 の位置が2条件で一致する。
- 配置の列は `RandomState(md5('v11_s1/layout'))`（train → test の順に全エピソード分、両条件で共通）。
- 方式の抽選は専用の `RandomState(md5('v11_s1/<split>/<n>/a1_mix'))` で、経験ありの条件だけが使う。
- キーと条件は HDF5 の属性に記録する。

**4.9 `a1_source`（一歩ごと、int8）**：0＝ランダムの一歩、1＝規則の一歩、2＝規則の番だったが使えずランダムの一歩（見えない・角）、3＝眠り。ランダムの条件では 0 と 3 だけになる。

**4.10 新しいファイルで動かす。** 既存の `model/model.py`・`model/__init__.py`・`train.py`・`exp/runner.py` には触れない。新しく作るのは次のファイル。
- `model/model_v11.py`（`SuperpositionNetworkPleasure`）
- `train_v11.py`（`train.py` のコピーで、v11 のクラスも探す）
- `v11core/`（快・不快の計算と視覚の規則）

学習には、既存の `PredictionFeaturePredictionRunner` を変えずに使う。

**4.11 学習は元論文の1段目の手順に合わせ、一から学習する**（pretrain なし）。
- mse 段：全部品、200ep。
- l1 段：Decoder のみ、200ep、同じシードの mse ep200 から。l1 段の pretrain のシードを合わせるため、config をシードごとに分ける。
- 同じシードなら、2条件で初期値・バッチの順番・マスクの乱数列が一致する見込み（6.2 で確認する）。2条件の違いはデータだけになる。

**4.12 M1(a) の回帰器は、各モデルについて、ランダム条件の train のエピソードをそのモデルに通して得た h¹ で、そのモデル専用に作る**（草野さんの確認済み）。
- 理由：経験ありの条件の train で作ると、train の位置が赤の近くに偏っている。Ridge は推定を学習データの平均位置へ縮めるので、モデルと無関係に「赤の方への偏り」が出てしまう。
- 位置がほぼ一様なランダム条件のデータで作って当てれば、この縮みは赤の方を向かない。
- 回帰器が偏りの一部を吸収する可能性はあるので、この設計は保守的である。

**4.13 Fig.5 の Decoder は、両条件ともランダム条件の train の先頭 1000 エピソードで学習する**（v10 §5.22 (3) と同じく、両条件の差を Encoder の違いだけに帰着させるため。規模は v4・v10 の Fig.5 と同じ 1000）。
- 設定は `fig5_v4_exp1l1000` と同じ（Autoencoder、100ep、batch 100、wd 3.0、L1、`vision_encoder`・`share_lns` を凍結）。pretrain だけを各モデルの l1 段 ep200 に替える。

**4.14 試し学習（6.2）**：train 3000 の先頭 1000 エピソード、mse 段 60ep、2条件 × seed0、GPU7。

**4.15 限界（記録）**
- **カメラは回転しない**。ランドマークはアリーナの外の角にあるので、どこにいても赤はほぼ同じ象限に見える（元の配置では北西、入れ替え後は南西）。
  - このため「快の高い方へ動く」は、実質「赤の象限の方へ動く」として学ばれる。学習データで快が正になるのは、配置ごとに決まった2つの範囲（元：範囲 6,7、入れ替え：範囲 0,1）だけで、その中の方向の幅は約 90°。
  - 配置がエピソードごとに入れ替わるので、**どちらの象限へ動くかは、快・不快の入力（または視界の色）を見ないと決まらない**。
  - M1(b) で範囲 2〜5 に快を入れる操作は学習データにない入力なので、一般化の検査として分けて報告する。
- **視覚は実質 t=0 だけ**：評価のマスク（p=0.99）では、視覚が入るのは実質 t=0 だけである。位置の推定は、主に快・不快の入力の時間変化と、推し量った自分の動きから作られる。
- **経験ありの A-1 の位置は赤の角へ偏る**（3.3 の見込みで 34%、到達の中央値 t≈28）。「赤の方へ動く」一歩は、主にエピソードの前半にある。
- **収束判定の閾値**：v10 §5.23 の閾値（1.05 / 0.05）は L1 の run で決めたもので、MSE の段には較正されていない（比の形なので単位にはよらないが、曲線の平らさは違いうる）。

### 5.0 共通の定義
- 座標はアリーナ座標 (x,y)。赤の基準位置は、元の配置で (−9,9)、入れ替えで (−9,−9)。参考として立方体の中心 (±13,±13) での値を併記する。
- 色の判定：該当チャンネル > 0.9、かつ他の2チャンネル < 0.1（配列のチャンネル0＝プロジェクトの「赤」）。A-1 の報酬 r_t ＝ 赤の割合 − 緑の割合（v4 から不変）。

### 5.4 自己側の関門（6.4）
**データ**
- 共通の評価データ：`v11_s1_random` の test（300 エピソード、A-1 ランダム、配置は混在）。
- 回帰器を作るデータ：各モデルに `v11_s1_random` の train（3000 エピソード）を通して得た h¹ で、そのモデル専用に作る（4.12）。
- 各条件の自分の test も参考として評価する。

**M1(a) 推し量った位置の偏り**
- 回帰器：Ridge(α=1)、h¹（128）→ 自己位置（2）。t=1〜100 の全フレームで作る。ここで h¹_t は、入力フレーム t−1 を処理した後の状態、正解は self_position[t]。
- 共通の test で、各フレームについて e_t = 読み出した位置 − 本当の位置、u_t = 本当の位置から赤の基準位置への単位ベクトルとし、b_t = e_t·u_t を求める。赤の基準位置から 2 以内のフレームは除く。
- エピソードごとに t で平均し、さらにエピソードで平均したものを b とする。時刻ごとの曲線も出す。
- **合格**：経験ありのモデルで b > 0 かつ信頼区間が 0 を含まないものが **3シード中2本以上**。かつ、同じシード番号の組（経験あり s − 経験なし s）の差の信頼区間が 0 を含まないものが **3組中2組以上**。

**M1(b) 入力を操作したときの反応**
- 共通の test の各エピソードで、t=0〜19 は本当の入力（canonical のマスク）を与える。
- t=20〜29 の 10 ステップは、視覚を隠したうえで、P を「範囲 k だけ a、ほかは 0」にする（操作）。対照は、同じ 10 ステップに P を全部 0 にしたもの。
- d_k(s) ＝（操作したときの読み出し位置 − 対照の読み出し位置）を θ_k の方向へ射影した値（s＝1〜10 ステップ目）。回帰器は M1(a) と同じ。
- 指標は2つ：10 ステップ後の値 d_k(10)、ステップに対する OLS の傾き。8 方向の平均と、範囲ごとの値を出す。学習データで快が正になりうる範囲（0,1,6,7）と、それ以外（2〜5）は分けて報告する。
- **合格**：8 方向の平均の d(10) について M1(a) と同じ形の条件（経験ありで正・信頼区間が 0 を含まないものが 2/3 シード以上、差の信頼区間が 0 を含まないものが 2/3 組以上）を満たし、かつ経験ありのモデルで傾きの平均が正であること。
- 解釈の注意：「ある方向の快が強い」は、ランダム条件のモデルにとっても位置の手がかり（その方向のランドマークに近い）になる。位置の手がかりなら最初の一歩でずれて止まり、動きの推し量りならステップごとに積み上がる。傾きはこれを区別するために見る。
- a は 5.1 の 6 で、学習の前に固定する。

**「価値と行動が結びついた」と言う条件**：M1(a) と M1(b) の両方の合格。

**M2 価値と色の結びつき**
- 共通の test のうち、入れ替えたエピソードを使う。アリーナを 5×5 の区画（各 4×4）に分け、区画ごとに e_t の平均ベクトルを求める（区画のフレームが 50 未満なら除く）。

- **前者が後者より 15° 以上小さければ「価値と色が結びついた」**、逆なら「場所」、どちらでもなければ「中間」。
- 元の配置のエピソードでも同じ値を出す（記述）。v10 段階Aの A-1 の critic の値（110.9° / 26.5°）と並べる。

- **評価スクリプト**：`analyze/v11/eval_trial_v11.py`。runner と同じ手順でモデルを1歩ずつ動かす（`model.eval()`、t=0 はマスクなし、その後は `p_mask_vision`、各パスの直前に `util.seed_all(0)`、cudnn deterministic）。
  - 確認用に ep1 のチェックポイントで動かした（結果は使わず削除した）。
  - **bit-identical の確認の訂正**：最初は確認用に 20 エピソードだけ流し直していたが、マスクの乱数はバッチの大きさで変わるので、50 エピソードのバッチで流した本評価とは一致しない（false）。共通の test 全体を2回流して比べる形に直したところ、h と誤差が一致した（true）。
- **R² の時刻の対応**：v4 の R² は「入力フレーム t を処理した後の h¹」と「その時刻の位置 p_t」を対にしている（`regression_baseline_v4.py` は `self_position/input` を使う）。0.906 と比べる R² はこの取り方で出す。M1(a) は登録どおり（入力フレーム t−1 を処理した後 ↔ p_t）で、その取り方の R² も併記する。
- **懸念（重要、判定の方法に関わる）：M1(a) は回帰器の縮みで、動きの推し量りがなくても正になる。**
  - Ridge の推定は、学習データの平均位置（ランダム条件ではアリーナの中心付近）へ縮む。赤の基準位置は角にあるので、「中心へ向かうずれ」を赤の方向へ射影すると、平均すると正になる。
  - ep1 の動作確認では、ランダム条件のモデル（R² 0.02）で b = +1.21 だった。同じ射影を、赤の代わりに緑・青・シアンの基準位置へ向けても、+1.28〜+1.87 と正になった。
  - 2条件の差でも、R² が違えば縮みの大きさが違うので、偏りが残りうる。§4.12 で「保守的」と書いたのは、この点で誤りだった。
  - 対称性から、縮みによる偏りはどの角に向けて測っても（位置が一様なら）同じ程度になる。動きの推し量りによる偏りは赤に特有のはずである。そこで、**比較対照として「ほかの色の角への射影」と「赤 − 緑」を試し学習の報告に並べる（事前登録外）**。判定の方法を変えるかどうかは、草野さんが試し学習の結果を見る前に判断する（試し学習の結果は判定に使わない段なので、ここで直すことができる）。

### 7.5 試し学習の結果と解釈（2026-10-17。数値は `v11_results_log.md` §3。**判定には使わない段**）

- **自己位置の追跡**：運動を入力しなくても、h¹ から自己位置が R² 0.83（random）・0.89（mixed、自分のデータで in-sample）で読める。v4 の R3-A_400（0.906、400ep・3000 エピソード）よりやや低いが、60ep・1000 エピソードで、学習曲線はまだ下がっている。
  - mixed のモデルは、共通のランダムの test では 0.71 に下がる。学習データ（赤の角に偏る）と違う歩き方では、位置を追う精度が落ちる。
- **M1(a)（登録どおり）は、見かけ上「合格」の形になる**：mixed で b=+0.44（CI が 0 を含まない）、差 +0.14（CI が 0 を含まない）。
- **しかし対照（事前登録外）では、この偏りは赤に特有ではない。** 同じ射影を緑・青・シアンの基準位置に向けても同じ程度に正で、mixed の方が全体に大きい。赤 − 緑、赤 − ほか3つの平均は、両条件とも 0 と区別できず、mixed ではむしろわずかに負である。
  - 解釈：b の正の値と2条件の差は、主に回帰器の縮み（§7.4）による。mixed のモデルは共通の test での R² が低い（0.71 対 0.83）ので、縮みが大きい。
  - **試し学習の時点では、「赤の方へ動くだろう」という推し量りの兆し（②）は、対照を入れると見えない。**
- **補助（予測の赤の画素数）**：両条件とも赤を少なめに描く（正解の約半分。ぼやけのため）。mixed の方が 1.5 画素多く描く（CI は重ならない）。ただし、ほかの色で同じ比較をしていないので、赤に特有かどうかは分からない。
- **M3**：自分の test では mixed の方が誤差が小さく（0.087 対 0.096）、共通のランダムの test では大きい（0.106 対 0.096）。①（世界のしくみ）は両条件で学ばれつつあるが、mixed はランダムの歩き方への一般化が弱い。
- **予測画像**：両条件とも、入れ替えた配置で赤・緑を正しい列に描く（Encoder を一から学習したため、色が学ばれている。v10 の凍結 Encoder とは違う）。
- **限界**：60ep・1000 エピソード、単一シード、単一チェックポイント。学習は収束していない。②の兆しが見えないことは、「本番でも出ない」ことを意味しない。
