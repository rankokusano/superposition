## 0. 背景（`docs/v6_instructions.md` §0 要約）

v4/v5 で判明したこと（確定・変更しない）：
- (a) A-1 の視覚予測：できる（h¹→self 0.907）
- (b) A-2 の視覚予測（base 段）：できる（h²→other 0.95〜0.98）
- (c) **A-2 の価値予測：できない**。原因は2つ、いずれも構造的
  1. Q値が自他で通約不可能（A-1 std 0.63 vs A-2 std 0.009。値域を揃えても益にならなかった＝P1.75）
  2. 位置を流すほうが視覚予測の損失に有利（`Q̂²→A-1位置 0.387 ≫ →A-2位置 0.097`、v5_r4_move）

v6 の狙い：推定対象を Q値（8次元）から**報酬パラメータ（4次元）**に変える。教授のメモの「ステップ2（逆強化学習）」に相当。狙いは上の2問題を設計レベルで同時に解消すること：
- 報酬は同じ尺度で定義される → 通約可能性が構造的に保証される
- 4次元しか出力できない → 位置情報を符号化する帯域がない
- 報酬を間違えると Q値が全部狂う → VE に「正しく推定する動機」が生まれる（v4/v5にはなかった）

失敗しても「報酬レベルまで降りても他者の価値は推定できない」という v4/v5 より強い境界の主張になる。**どちらに転んでも論文に書ける。**

```
v4/v5:  VE → Q̂²（8次元）を直接出力 → SM
v6:     VE' → r̂²（報酬パラメータ 4次元）→ 報酬条件付き critic Q(s,a,r̂²) → 8方向プローブ → Q̂²（8次元）→ SM
```

- Encoder は v5 と同じくスクラッチ学習（元論文Encoder凍結では収束しないことがv5で判明済み）

### 2026-09-13: 報酬パラメータ `r` のサンプリング分布 → 連続一様＋L1正規化（ユーザ判断）

**判断**：`r`のサンプリングは離散（2点／12通りの軸ペア）ではなく**連続一様**とする。手順：

1. `w_k ~ Uniform(-1, +1)` を4次元 i.i.d. にサンプル
2. **`Σ_k |w_k| = 2` に正規化**：`w' = w * (2 / Σ_k |w_k|)`（`Σ|w_k|`が0近傍に落ちる縮退ケースはリサンプル）

**正規化方式に `Σ|w_k|=2`（L1）を選んだ理由**：候補として `‖r‖₂=1`（L2）も検討したが、L1を採用した。A-1の真値`(+1,-1,0,0)`・A-2の真値`(-1,+1,0,0)`はどちらも**既に`Σ|w_k|=2`を満たしている**ため、L1正規化なら真値がそのまま不動点になり、正規化後も値を書き換える必要がない。L2正規化だと真値が`(1/√2,-1/√2,0,0)`のように変換され、以後のオラクル実験（S4）・VE'の相関評価（S5）で「どちらの値を真値として使うか」の二重管理が発生する。実装の単純さでL1を選んだ、というユーザの指示に沿う。

**留意点として記録**：この手順（立方体から一様サンプル→L1シェルへ動径方向に射影）は、L1球面上の一様分布ではない（頂点付近に僅かな偏りが生じ得る）。これは意図的な簡略化であり、rigorousな一様性を主張しない。問題が生じれば再検討する。

**S1の判定基準に追加**（ユーザ指示）：学習時にサンプルしなかった`r`（例：`(0,+1,-1,0)`=緑好き・青嫌い）でQ値が妥当な空間分布を示すこと＝**未知の`r`への汎化**。§3.0のS1判定基準に正式追加。

### 2026-09-13: Actor も `r` で条件付ける（ユーザ判断）

**判断**：`ActorLSTM`も`r`を入力に含める（`π(a|s,r)`）。

**理由**：SACのターゲットQ計算 `r_reward(s,a) + γ·(Q'(s',a') - α·logπ(a'|s'))` で `a'` はActorからサンプルされる。Actorが`r`を無視すると、その`r`に対応しない行動でターゲットが計算され、critic学習が歪む。

**副次的な利点（記録）**：条件付きActor `π(a|s,r)` は、A-2の軌跡生成にもそのまま使える。現状A-2は専用actorを持つが、v6では単一の`π(a|s,r)`で自他両方をカバーできる可能性がある。

**論文上の位置づけ（重要、Methods/Discussionに書ける主張）**：「同じ方策機構に異なる報酬パラメータを入れることで他者を再現する」という構図になり、元論文の中核主張「同じモジュール（Shared Module）で自他を処理する」を、**方策・価値計算のレベルまで拡張**したことになる。§0の「superpositionの思想との整合」の節（`docs/v6_instructions.md` §2.3参照）と合わせて、v6の新規性の説明に使う。

## 4. 調査フェーズの結果（§7、コード変更なし）——2026-09-12

### 4.1 現行報酬関数は4次元形式の特殊ケースか

**確認：YES。** `my_research/preference_inference/simulation/train_rl_v3.py` の `get_reward()`:

```python
def get_reward(vision_np):
    r, g, b = vision_np[:, :, 0], vision_np[:, :, 1], vision_np[:, :, 2]
    red_pixels   = int(((r > 0.9) & (g < 0.1) & (b < 0.1)).sum())
    green_pixels = int(((g > 0.9) & (r < 0.1) & (b < 0.1)).sum())
    ...
    return red_fraction - green_fraction
```

これは `reward = Σ_k w_k · fraction_k`（`w=(+1,-1,0,0)`, k∈{red,green,blue,cyan}）の特殊ケース。A-2用（`train_rl_v3_a2.py`）も対称で `w=(-1,+1,0,0)` に一致。

**拡張に必要なもの**：blue・cyan の pixel fraction 計算が現状コードベースに存在しない（`blue_pixels`/`cyan_pixels` 相当は grep で0件）。しきい値は red/green と同じパターン（該当色チャンネル>0.9、他<0.1）で機械的に追加できるはずだが、**cyan ランドマークは "Yellow" マテリアル（Kd=(0.8,0.8,0)、field.mtl）なのに実測RGBがシアンだった**という v4 の既知の食い違いがある（`v4_experiment_log.md` §2.1 該当箇所）。実装前に实際の `other_vision`/`self_vision` データでピクセルのRGBヒストグラムを取り、4色のしきい値を実測で確定させる必要がある（1時間程度の作業、大きなコストではない）。

**結論**：構造的には自明な拡張。**実装コストは小**（既存パターンの複製＋しきい値の実測確認）。

### 4.2 SAC critic を報酬条件付きに拡張する実装コスト

現行実装：`my_research/rl_agent_sac.py`（88行）の `CriticLSTM`：
```python
self.q = nn.Sequential(nn.Linear(hidden_dim + 2, 64), nn.ReLU(), nn.Linear(64, 1))
def forward(self, v, action, hidden=None):
    ...
    x = torch.cat([lstm_out, action], dim=-1)
    q = self.q(x)
```

**ネットワーク自体の変更は小さい**：`nn.Linear(hidden_dim + 2, 64)` → `nn.Linear(hidden_dim + 2 + 4, 64)`、`forward` に `r` 引数を追加して `torch.cat([lstm_out, action, r], dim=-1)` にするだけ。

**訓練ループ（`train_rl_v3.py`、227行）側の変更点**（中程度のコスト）：
1. エピソード開始時に `r` をランダムサンプル（サンプル分布は未決定 — §5 未解決の懸念を参照。**これは設計判断であり、結果を見る前に固定すべき事項**）
2. 報酬計算を4次元一般形に変更（4.1のfraction計算を利用）
3. `ReplayBuffer` の transition に `r`（4次元）を追加保存
4. ミニバッチ更新時、`critic1/2`・`critic1/2_target` の全呼び出しに `r` を渡す
5. **Actor も `r` を条件に含める**（2026-09-13決定、§3参照）：`ActorLSTM`の`forward`/`sample`にも`r`を追加し、`nn.LSTM`への入力もしくは平均・log_std出力層の手前で`r`を連結する。ネットワーク変更コストはCriticと同程度に小さい。

**周辺コードへの波及**（軽微〜中程度）：
- `model/model.py` の `compute_probe_q()`（2箇所、301行台・459行台）：`self.probe_critic(v_rep, a_rep, hidden=None)` → `r_rep` を追加で渡す必要。呼び出し元（VE'または オラクル実験でのr固定値）から`r`が来る経路を新設する必要がある
- `analyze/check_critic_health.py`：健全性チェックに `r` を通す引数を追加し、`r=(+1,-1,0,0)` と `r=(-1,+1,0,0)` の両方でチェックする必要（§3.0のS1判定基準が要求）

**重要な発見（実装コストに直結）**：`my_research/rl_agent_sac.py` は `my_research/preference_inference/` 以外に **`my_research/step3/`（別研究ライン、保護対象）を含む70以上のファイルから import されている共有モジュール**。直接編集すると step3 に影響しうるため、**`my_research/preference_inference/` 配下にコピーしてから拡張する**方針とした（§3の設計判断ログ参照）。コピー自体はコストではなくむしろ安全策。

**総合見積もり**：ネットワーク変更自体は数十分〜1時間。訓練ループ・health check・model.py配線を含めた実装全体で**半日〜1日**（設計判断が先に固まっていることが前提）。指示書 §6.1 の見積もり（S1に5〜10h、うち大半は学習時間そのもの）と整合的。

**微分可能な価値計算が必要か、条件付きcriticで足りるか**：指示書の設計（VE'→r̂²→条件付きcritic→8方向プローブ→Q̂²→SM、§2.1）は、**critic自体は凍結して使う**（S2以降、生成段でcriticは学習しない、§3.0の表「生成モジュール：VE'のみ学習」）。したがって学習時にはVE'の勾配がcriticの中を通ってprobe Q̂²まで伝播する必要があり、**criticはPyTorchモジュールとして微分可能である必要がある**（数値ブラックボックスでは不可）。現行`CriticLSTM`はニューラルネットなのでこの要件は自動的に満たされる。追加の微分可能性対応は不要。

### 8.2 条件付き critic / Actor の実装

**`r`の連結位置**：LSTM出力の後、actionと同じ段（`torch.cat([lstm_out, action, r], dim=-1)`、Actorは`torch.cat([lstm_out, r], dim=-1)`）。LSTM入力（CNN特徴量）には混ぜていない。

**理由**：`r`はエピソード内で不変な定数であり、LSTMが担う「時間方向の統合」を必要としない（視覚観察には時間構造があるが`r`にはない）。LSTM入力に混ぜると、各タイムステップで同じ値を冗長に見せることになり、CNNEncoderの入力次元設計にも影響が及ぶため、actionと同じ場所で連結する方が構造として素直と判断した。

**入力次元の変更箇所**：
- `CriticLSTM.q`の最初の線形層：`nn.Linear(hidden_dim + 2, 64)` → `nn.Linear(hidden_dim + 2 + R_DIM, 64)`（`R_DIM=4`）
- `ActorLSTM.mean`/`.log_std`：`nn.Linear(hidden_dim, 2)` → `nn.Linear(hidden_dim + R_DIM, 2)`
- 両者の`forward`/`sample`シグネチャに`r`引数を追加

**動作確認**（Docker内、シミュレータ環境なしのテンソル形状チェック）：`ActorLSTM.sample(v, r)` → action shape `(B,2)`、logp shape `(B,1)`。`CriticLSTM(v, action, r)` → q shape `(B,1)`。バッチサイズ2で確認済み。

**⚠️ 設計上の懸念（2026-09-13、ユーザ指摘）：`r`と視覚特徴の相互作用が浅い可能性**

現行設計は`r`を最終層（`nn.Linear`1枚）でのみ`lstm_out`・`action`と連結している。`Q(s,a,r)`は本来「報酬`r`のもとで状態`s`がどれだけ良いか」を表すべきで、「赤の角にいる」という状態は`r=(+1,-1,0,0)`なら高価値・`r=(-1,+1,0,0)`なら低価値と、**状態と`r`が掛け合わされる**必要がある。線形層1枚がこの乗算的な相互作用を十分表現できるかは未知数（線形層は`lstm_out`と`r`それぞれに独立な重みをかけて足し合わせるだけで、`lstm_out × r`のような積の項を直接表現しない。後段のReLU+Linearである程度の非線形合成は可能だが、保証はない）。

**判断**：まず現行設計（浅い連結）でS1を実施し、§3.0のS1判定基準（`r`を変えるとQ値の空間分布が明確に変わるか）で経験的に検証する。**「`r`を変えてもQ値の空間分布がほとんど変わらない」という結果が出たら、この設計が原因である可能性が高く、以下の代替案に進む**：

1. **`r`をLSTMの入力側（視覚特徴と連結）に入れる**：`nn.LSTM(256 + R_DIM, hidden_dim, ...)`とし、CNN特徴量と`r`を毎ステップ連結してLSTMに入力する。`r`はエピソード内定数なので冗長ではあるが、LSTM自体（ゲート機構）が`r`と特徴量の非線形な相互作用を学習する余地が生まれる
2. **FiLM的な条件付け**：`r`から線形写像で`γ(r)`・`β(r)`を計算し、`lstm_out`（またはCNN特徴量）を`γ(r) * feature + β(r)`で変調する。状態表現そのものを`r`に応じて変形するため、乗算的相互作用を明示的に導入できる
3. **中間層を1枚増やす**：`nn.Linear(hidden_dim+2+R_DIM, 64) → ReLU → nn.Linear(64, 64) → ReLU → nn.Linear(64, 1)`のように深くし、非線形合成の余地を増やす

優先順位は2（FiLM）→1（LSTM入力に混入）→3（層を増やすだけ）。2は「`r`が状態表現を変調する」という意味的にも明確な設計であり、3は最も安易だが効果が薄い可能性がある。

**Q値空間マップ**（`data/result/v6_baseline/q_map_v6_seed0.png`ほか、20×20グリッド、共有カラースケール）：3条件（A1/A2/unseen）の空間パターンが**視覚的にほぼ同一の形状**（上半分＝Red/Cyan側で高く、下半分＝Green/Blue側で低い。(x,y)≈(4,-5)付近に3条件共通の局所的な暗点あり）で、**`r`を変えても空間パターンがほぼ変わらず、全体の明るさ（オフセット）だけがシフトしている**ように見える。

### 9.3 解釈：2つの候補原因

**候補1（§8.2で予測した設計上の懸念が的中）**：`r`を最終層でのみ線形結合しているため、`Q(s,a,r) ≈ f(s) + g(r)`のような加法的分離に留まり、「状態の価値がrによって符号反転する」といった乗算的な相互作用を表現できていない。3条件のマップが同一形状でオフセットだけ違う、という観察はこの仮説と整合する。

**候補2（学習不足／SAC実行上の問題）**：**action_stdが全rでFAILしている**——これはrの条件付けの成否と独立な、より基本的な「criticがactionに十分反応しない」という信号であり、v4で警告されていた「critic崩壊」の部分症状に近い。学習ログを見ると、SACのentropy係数`alpha`がep300で0.049、ep550で0.0041と急速に減衰しており、**方策が早期に探索を止めた（分散の小さい行動に収束した）可能性がある**。replay bufferの行動分布が偏ると、criticは異なる行動間の差を学習する機会が減る。また`r`はエピソードごとに1回サンプルするため、1000エピソードでも1000通りの`r`しか経験しておらず、4次元空間・かつ状態空間との組み合わせを考えると**サンプル数が不足している可能性**もある。

**両者は排反ではない**：仮に候補1（アーキテクチャの限界）が真の上限だとしても、候補2（学習不足）が同時に効いていれば、その上限にすら到達していない可能性がある。現状の結果だけでは、どちらが支配的か切り分けられない。

### 9.4 推奨：FiLM実装の前に、安価な追加学習で候補2を切り分ける

**§8.2の合意（「rを変えてもQ値の空間分布がほとんど変わらなければFiLM方式に進む」）はまだ発動しない。** 理由：action_stdの全条件FAILは、rの条件付け以前の問題（候補2）である可能性を示しており、これを解消しないままFiLMに切り替えても同じ理由で失敗しうる。

**次の一手（着手前にユーザ判断を仰ぐ）**：

- (b) 同時に、SACのハイパーパラメータ（`TARGET_ENTROPY=-2.0`固定、alpha減衰が速すぎる可能性）を見直す
- (c) (a)(b)で改善しなければ、§8.2のFiLM案に進む

### 11.2 hindsight relabeling の実装

**ユーザ提案**：報酬が状態（視覚）のみから計算できるため、1つの軌跡の`(s,a,s')`は任意の`r`のもとで有効。同じ`(s,a,s')`に対して複数の`r`で報酬を計算し直し、それぞれ独立した遷移としてreplay bufferに追加する（Hindsight Experience Replayと同じ論理：Q学習はoff-policyなので、実際に行動を生成した`r`と異なる`r`で学習しても妥当）。

**実装**（`simulation/train_rl_v6.py`）：
```python
memory.push(state, action_t, r_param_np, reward, next_state, done)
for _ in range(K_RELABEL - 1):
    r_relabel = sample_reward_param()
    reward_relabel = reward_from_vision(v_next_raw, r_relabel)
    memory.push(state, action_t, r_relabel, reward_relabel, next_state, done)
```
`K_RELABEL=10`（実1＋relabel9）。1000エピソード×100ステップの環境相互作用は変えずに、`(s,a,r)`の経験数を10倍（実質10000通りの`r`経験）にする。

**副作用と対応**：relabelingにより1環境ステップあたりのbuffer push数が10倍になるため、`MEMORY_SIZE`を50000→100000に増量した（それでも保持エピソード数は500→100に減る計算——relabeling前は1状態=1r経験だったのに対し、relabeling後は1状態=10r経験になるため、同じメモリ容量でも「異なる状態」の保持数は減る。r被覆と状態被覆のトレードオフとして意図的に許容）。

**着手前確認**：60秒のスモークテストで動作確認（エラーなし、ep0出力確認）。GPU7・disk空き容量（65GB）を再確認してから起動。

### 17.1 記録：非定常性仮説（ユーザ提示、有力候補）

対照（固定報酬）と「rあり」の違いは、rありでは**エピソードごとに報酬関数が変わる非定常な学習**になる点でもある。SACは「固定された報酬関数のもとで最適方策を学ぶ」設計であり、エピソードごとに報酬（=価値のターゲット）が変わり続けると学習が不安定になりうる。r入力の構造（浅い連結）とは別の、**学習則そのものに由来する原因候補**。

**もし(i)で「r単独でaction_stdが下がる」と確認された場合、この非定常性が最有力の原因候補になり、その場合FiLM（アーキテクチャ変更）ではaction感度は解決しない可能性がある。**

対処の候補（**今は実施しない。記録のみ**）：
1. rのサンプリング範囲を狭める（学習初期はA-1/A-2近傍のみ、徐々に広げるカリキュラム）
2. rをエピソードごとではなく、より長い区間で固定する
3. 学習率を下げる

### 17.3 (ii) FiLM条件付けの実装と、2軸の判定基準

**仕様（実装前に固定）**：
- **変調箇所**：CNN特徴量（256次元、LSTM入力の直前）を`γ(r)⊙feature + β(r)`で変調。critic・actorの両方。
- **γ, β**：`γ(r) = 1 + W_γ r`、`β(r) = W_β r`（rの線形写像、§8.2の仕様。重みとバイアスは0初期化で、学習開始時は恒等変換）。
- **現行のr連結（後段のlstm_out・actionとの連結）は残す**——FiLMは現行設計の上位互換（容量を減らさない）。
- **他は全て「rあり・リラベリングあり」の現行レシピと同一**（K_RELABEL=10、MEMORY_SIZE=100000、1000ep、GAMMA/TAU/LR/BATCH_SIZE/TARGET_ENTROPYも同一）——**FiLMの有無だけが違う**ようにして、既存の3 seed（seed0/1/2、試行2＋seed1・2）と直接比較する。seed 0/1/2、`--film`、保存名`_film`。
- **選択理由**：(a) 線形のγ,βは`f_j·(Σ_k u_jk r_k)`という双線形の相互作用を直接表現でき、`Q≈Σ_k w_k G_k(s,a)`（報酬重み×各色の将来割引割合）という構造に合う。(b) エンコーダprobe（§13.2）でCNN特徴量に4色の情報が高R²で含まれると確認済みなので、変調の対象は色識別情報そのもの。(c) LSTMの前で入れることで、後段のLSTMとヘッドが相互作用を利用する深さを確保する。
- **選ばなかった案（FiLMが部分的にしか効かなかった場合の次の候補）**：LSTM出力（128次元）の変調、γ,βをMLPで計算、§8.2の案1（rをLSTM入力に連結）・案3（中間層を増やす）。

**判定は2軸を分けて行う**：

| 軸 | 指標 | 定義（事前登録） |
|---|---|---|
| 軸1：action感度 | action_std | seedが「健全」＝A1・A2・unseenの3条件すべてでaction_std>0.05（§14.1）。**FiLM 3 seedのうち2本以上が健全ならPASS**。対照（0.077〜0.162）にどれだけ近いかも併記（判定には使わない） |
| 軸2：rへの応答 | 全グリッド空間マップ＋隅のQ | **§14.2の基準A・B・C・D（そのまま）を、健全性に関係なく3 seedすべてに適用**（§14.2の「健全なseedのみ」からの拡張。軸1がFAILでも軸2を評価する必要があるため）。**3 seedのうち2本以上が基準A・B・C・Dをすべて満たせばPASS**。A〜Cは`check_critic_health_v6.py`の隅のQ（action=(1,0)固定）で判定し、Dは全グリッドの目視で「ランドマークの色を識別したパターンか、単なる座標軸勾配か」を明記する（Dが座標勾配と判断されたseedはPASSにしない）。「符号反転で軸が切り替わらない」は基準A・Bが両方成り立つことで担保する（重み0の2ランドマークの相対順位は本来不定なので、4隅の完全な逆順は要求しない）。補助として`corr(Q_A1, -Q_A2)`も報告するが判定には使わない |

**4通りの結果と解釈・次の手（ユーザ提示の表をそのまま採用）**：

| 軸1 | 軸2 | 解釈・次の手 |
|---|---|---|
| PASS | PASS | FiLMで解決。S2へ進む |
| FAIL | PASS | rへの応答は直ったがaction感度は低いまま。別の対処が必要（学習量、SACの設定、§17.1の非定常性への対処など） |
| PASS | FAIL | action感度は戻ったがrを使えていない。より深い設計変更が要る（§17.3の「選ばなかった案」など） |
| FAIL | FAIL | FiLMでは解決しない。設計の再検討 |

**(i)との関係**：(i)が第1行（r単独で低下）なら、軸1のFAILはFiLMの効果がなかったというより非定常性に由来する可能性が高く、その読み方をする。

## 19. (c) 8方向プローブQの方向情報の測定：事前登録（2026-09-22、v3・FiLMの数値を計算する前）

**結果を見てからこの節を書き換えない。**

### 19.1 目的

action_stdの低さ（§18）が下流（S2のprocess入力＝8方向プローブQ）で致命的かを、再学習なしで確かめる。S2はSMへの入力として`tanh((Q(s,a_k)-μ)/σ)`の8成分ベクトルを使う（`model/model.py` `SuperpositionNetworkProbeQ`、k=8、方向は角度2πk/8の単位ベクトル）。方向間の差が状態間の差に比べて小さいと、入力が状態価値のスカラーにほぼ支配される。

### 19.2 測定条件（ユーザ指定：実際の実験で使うrとデータ）

| 条件 | 用途 | criticへのr | データ・視覚 |
|---|---|---|---|
| c1 | base段のprocess-1入力 | A-1 (+1,-1,0,0) | `r3_stay` test split（300ep×101step=30,300フレーム）の`self_vision` |
| c2 | オラクル実験のprocess-2入力 | A-2 (-1,+1,0,0) | `r2_a1random_a2rl` test split（同サイズ）の`other_vision` |

視覚は`uint8/255`で[0,1]（criticのnative scale。`model.py`の`(sv+1)/2`と同じ）。プローブ方向はモデルと同一（k=8、角度2πk/8）。任意のrでの性能はS5まで問題にならないので測らない。

### 19.3 指標（固定）

フレームi、方向k=1..8のプローブQを`Q_ik`とする。
- **D = mean_i Var_k(Q_ik)**（フレーム内で8方向の間のばらつき、母分散）
- **S = Var_i( mean_k Q_ik )**（フレーム間での、方向平均Qのばらつき）
- **R = D / S**（方向間の分散 ÷ 状態間の分散）

**判定統計 ρ = R(候補) / R(基準)**。基準は**同じフレーム・同じ条件**で測る。

**基準critic**：`data/model/v3_rl_critic.pth`（v3 A-1 critic）。**v4/v5のconfig（`config/model/SuperpositionNetworkProbeQ*/…yml`の`probe_q.critic_path`）が実際に読んでいるファイルで、`v3_rl_critic_seed0.pth`とmd5が一致（b4fec257d3dd、同一ファイル）することを確認済み**（ユーザの指定「seed0」と一致）。健全性はaction_std=0.119（健全域の下側）。c2でも同じcriticを基準にする（同じフレームでの、健全なcriticが持つ方向情報の量として）。

**候補critic**：FiLM seed1・seed2（軸2を満たした2本）。c1はr=A-1、c2はr=A-2で評価。

### 19.4 判定（事前登録）

seedごとのスコア＝2条件のρの小さい方（`min(ρ_c1, ρ_c2)`）。S2で使うcriticは1本なので、**最良のseedのスコアで判定**する：`max_{seed∈{1,2}} min_c ρ_{seed,c}`。

| 最良seedのスコア | 判断 |
|---|---|
| **≥ 1/2** | action感度の低さは下流で致命的でない。S2に進む（そのseedのcriticを使う） |
| **< 1/5** | 方向情報が失われている。§17.1の非定常性対処（(a)）に進む |
| 1/5 〜 1/2 | 判断困難。基準をユーザと相談する |

**閾値はユーザの仮提案（1/2、1/5）をそのまま採用する。** 根拠：Rは分散比なので、健全なv3 A-1のseed間のaction_std（0.119と0.202、比1.7）は分散比で約2.9倍の幅がある。ρ≥1/2は「健全なv3のseed間のばらつきの範囲内」に相当し、ρ<1/5（標準偏差比でおよそ0.45未満）は健全なv3のどれよりも明確に小さい。基準のseed0は健全なv3の中で弱い側（0.119 < 0.202）なので、基準が甘いわけではない。

## 24. actorがrに応答しているかの検証（2026-09-28、ユーザ仮説：「A-1がランダム歩行」ではなく「actorがrを無視している」）

### 24.1 仮説（ユーザ提示）

学習中、rで報酬は変わる（§8.1で確認済み）が、行動を決めるのはactor。**actorがr=A2（Green選好）のときに実際に緑へ向かう行動を取れなければ、criticは「緑に近づく経験」を学習データとして得られない。** これはcriticの問題ではなくactorの問題であり、当たっていればFiLMによるactor側の条件付けが効いていないことになる。

**§23の「A-1がランダム歩行だから」という表現は不正確だった点を訂正**：v6設計ではA-1の軌跡はSACのactorが生成する（元論文/v4のRandomAgentとは異なる、§1.4はQ値の意味論の話であり、v6のS1段階の学習ロールアウトはactor自身が動く）。真に検証すべきは「actorがrに応じて訪問分布を変えられているか」。

### 24.2 検証方法（事前登録、既存チェックポイントのみ使用、再学習なし）

**方法2（最優先、最も直接的）**：学習済みactor（FiLM+リラベリングなし、seed0・seed2）を用い、`self_random_other_stay`環境で`env.reset()`（学習時と同一、事前の位置上書きなし）から、r=A1固定・r=A2固定それぞれ50エピソード×100stepのロールオウトを実施。各stepで`self_agent.p`を記録し、目標ランドマーク（r=A1→Red、r=A2→Green）への距離の推移を測定。比較対象として「目標でない方」のランドマークへの距離も測定（選択性の確認）。

**方法3（actorの健全性）**：グリッド状の複数状態（vision）を固定し、r=A1とr=A2でactorの出力（行動平均・log_std）がどれだけ異なるかを測定（L2距離、相関）。rを完全に無視していれば出力はほぼ同一になるはず。

**方法1（学習中の軌跡分析）は実施不可**：学習ログには50エピソードごとのavg_reward/alphaのみが記録されており、各エピソードのr・軌跡は保存されていない。**元の学習実行を再現することはできないため、方法1は代替として「最終的な学習済みactorでのロールアウト」（方法2）で置き換える。** これは学習の全過程ではなく最終時点のactorの挙動であり、学習初期の訪問分布とは異なりうる点に留意する。

### 24.3 判定基準（事前登録）

- **仮説を支持**：r=A2ロールアウトがr=A1ロールアウトと比べて有意にGreenへ近づかない（Green距離の改善が乏しい）、かつactorの出力がr=A1/A2でほとんど変わらない（L2距離が小さい、または無相関）
- **仮説を棄却**：r=A2ロールアウトが明確にGreenへ接近する（r=A1がRedへ接近するのと同程度）、かつactorの出力がrで明確に異なる → 訪問経験自体はあったことになり、critic側の学習（TD更新・非定常性等）に原因を絞り込む

## 25. カリキュラム学習：設計と判定基準の事前登録（2026-09-28、実装・起動の前）

### 25.1 方式の選定理由（ユーザ指示：固定順序ではなく「範囲を徐々に広げる」）

**当初案（A1固定→A2固定→ランダム）を採用しない理由（ユーザ指摘、記録）**：最後に学習した区間の内容が強く残る（破滅的忘却）ため、最終のランダム区間が短いと偏る。またA1を先にするかA2を先にするかで結果が変わりうる、という新たな交絡を生む。

**採用する方式**：`ep<200`は2点のみ、`200≤ep<500`は2点サンプルと全範囲一様サンプルの**混合比を線形に遷移**、`ep≥500`は全範囲一様。区間境界での連続性を重視した設計：

```python
def sample_r_curriculum(episode):
    two_point = [A1_TRUE_R, A2_TRUE_R]
    if episode < 200:
        return two_point[np.random.randint(2)].copy()          # 100% 2点
    elif episode < 500:
        t = (episode - 200) / 300.0                             # 0→1 線形
        if np.random.random() < t:
            return sample_reward_param()                        # 全範囲一様
        else:
            return two_point[np.random.randint(2)].copy()       # 2点
    else:
        return sample_reward_param()                             # 100% 全範囲一様
```

**この方式を選んだ理由**：
1. **境界で連続**：`ep=200`の直前直後はどちらも「100%2点」、`ep=500`の直前直後はどちらも「ほぼ100%全範囲」——位相の切り替わりで急激な分布の変化が起きない
2. **各episodeでA1・A2どちらかが50%の確率で選ばれる**（2点区間では直接、混合区間では「2点」側を引いたとき）ため、**順序の交絡が生じない**（固定順序案と違い、"どちらを先に学習するか"という選択自体が存在しない）

## 27. c2の弱さの原因検証：距離別の方向情報分析（2026-09-28）

### 27.1 仮説（ユーザ提示）

## 31. S2追加検証：canonical protocolでのh¹→self低下幅がv5より大きい件（2026-09-30、ユーザ指摘）

**ユーザからの懸念**：本研究の主張は「A-1の自己視覚・自己価値だけから他者を理解する」ことであり、superpositionは「自己の機構を他者に流用する」仕組みである。その自己表現（h¹→self）がcanonical protocol（r2_a1random_a2rl）で0.4878まで落ちており（元論文0.967、v5 0.716）、かつS3・S4ではSM側が凍結されるためh¹は改善しない。この状態でS4/S5に進んでよいかの判断材料が必要、との指摘。

**結果の解釈**：
- **飽和率はほぼ同じ**（6.97% vs 7.96%）。「σが小さすぎてcanonicalで広範囲に飽和する」という候補(b)の素朴な形は**支持されない**——飽和自体はcanonicalで劇的には増えていない。

**総合判断**：候補(b)は「部分的に真」（较正はr3_stay限定で、canonicalには系統誤差がある）が、**それ単独ではR²低下の規模を説明できない**。候補(a)「A-2静止条件への過適合」も、本検証はcritic自体の出力（D項）のみを見ており、SM/LSTM/デコーダ側がr3_stay固有の状態分布にどう最適化されているかは見ていないため、**未確定のまま**。§31.1の非対称性（h¹→selfのみ選択的に悪化）と合わせて考えると、**probe-Qという信号そのものの質の劣化よりも、「process-1のLSTM/デコーダがr3_stay固有の自己位置↔Q値の対応関係を学習し、それがr2_a1random_a2rlの自己位置分布（A-1がランダム歩行でr3_stayより広い範囲を訪れる可能性がある）に汎化しない」という、消費側（h¹のLSTM）の汎化不足という第三の説明の方が、現時点のデータとより整合的**である。ただしこれも未検証の仮説であり、確定的な結論ではない。

### 31.5 単一時刻プローブQ→自己位置の直接回帰（LSTM無し、ユーザ提案の切り分け検証）

**方法**：`analyze/probe_q_direct_regression.py`を拡張（`--dataset`引数を追加、既定値`r2_a1random_a2rl`で後方互換を維持）し、v6 S2チェックポイント（ep400）のprobe-Qベクトル（8次元、LSTM・SM通さず）を、r3_stay・r2_a1random_a2rlそれぞれ3000エピソード×100stepで直接Ridge回帰してself_position/other_positionへのR²を測定。v4の同一スクリプトによる既存値（`r3_a_direct`、v3の素のcritic、r2_a1random_a2rlで測定、`data/result/baseline_v4/r3_a_direct_probe_q_direct_regression.json`）と並べる。

| | v4 (r3_a_direct, v3 critic) | v6 S2 (curriculum FiLM critic) r3_stay | v6 S2 r2_a1random_a2rl |
|---|---|---|---|
| q1_vec→self_position R² | 0.5989 | 0.4051 | 0.3038 |
| q1_vec→other_position R² | 0.0436 | 0.0504 | 0.0730 |

保存先：`data/result/baseline_v4/v6_s2_base_mse_probe_q_direct_regression_{r3_stay,r2_a1random_a2rl}.json`。

**判定（事前登録された表に対する結果）**：ユーザの事前登録は「両データで同水準→消費側confirmed」「r2で明確に低い→入力側の問題」の二択だったが、実際の結果は**どちらにもきれいには当てはまらない中間的な結果**だった：

- 入力側（LSTM無し）の相対低下：0.4051→0.3038 で **-25%**（同水準とは言えないが、後述のLSTM後の低下ほど激しくもない）
- LSTM後（h¹→self、§30.3/§31.1）の相対低下：0.8215→0.4878 で **-41%**
- もしLSTMが入力側の劣化をそのまま素通しするだけなら、canonicalのh¹→selfは 0.8215×0.75 ≈ **0.616** 程度になるはずだが、実際は**0.4878**とそれよりかなり低い

**解釈**：入力（probe-Q）自体もr2_a1random_a2rlで確かにいくらか劣化しており（候補(b)的な要素はゼロではない）、「入力は完全に健全」とは言えない。しかし観測されたLSTM後の低下幅は、入力側の劣化だけでは説明できないほど大きく、**LSTM/デコーダ側が入力の劣化を増幅している**（消費側の寄与が主要因）という、これまでの仮説と整合する結果になった。ただし事前登録した二択のどちらでもない以上、「確定」とは言えず、**入力側の部分的劣化と消費側の増幅の両方が effect を持つ複合的な結果**として記録する。

**副次的な発見**：v6 S2のprobe-Qは、in-distribution（r3_stay, 0.4051）で測ってもv4の参照値（0.5989、ただしv3の素のcriticかつr2_a1random_a2rl上）より低い。これは「v6のr条件付きFiLM criticのQ値は、v3の単純なcriticよりも自己位置の直接情報を担う純度が低い」ことを示唆し、r条件付け・FiLM変調・カリキュラム学習によってcriticの価値関数がより複雑（r・状態・行動が絡み合う）になったことの副作用である可能性がある。これ自体は今回のcanonicalでの低下幅の主因ではない（in-dist/canonical間の比較が本題のため）が、v6の設計そのものに内在する特性として記録しておく。

### 31.3 候補4「baseをr2_a1random_a2rl（移動データ）で学習し直す」の是非についての検討

ユーザが引用したv4の先例（R3-A移動データ base: h¹→self=0.906 vs R3-stay静止 base: 0.768）を`docs/research_plan_v4_v5.md` §7で確認したところ、**この0.768という数字はv4当時、運動レジーム用に学習した凍結Encoderを流用した条件のものであり、「静止データそのものが自己表現を劣化させる」という説は同文書内で明示的に反例により棄却されている**（該当箇所：「報酬配置説・価値入力説・静止データ説はすべて反例で棄却」）。実際、Encoderを価値入力用にスクラッチ学習し直した結果（＝v5、そして本v6 S2も同じ方針）ではR3-stay系列でも収束し、h¹→self≈0.80（v5_base_mseのin-distribution値0.7958、v6 S2は0.8215）に回復しており、R3-Aの0.906とほぼ同水準まで縮まっている。

**含意**：v6 S2の問題は「in-distributionでの自己表現の質」ではない（0.82はv5の0.80より高く、健全）。問題は**canonical protocol（r2_a1random_a2rl）への汎化**であり、これはv4のR3-A/R3-stay比較が扱っていた問題（Encoder凍結流用の可否）とは別種の問題である。したがって、v4の先例をそのままv6 S2の根拠として「baseをr2_a1random_a2rlに変更すれば解決する」と結論するのは**早計**と考える。

さらに概念的な懸念として、baseの訓練データをr2_a1random_a2rlに変更した場合、**r2_a1random_a2rlはもはや「canonical protocol（held-out的な共通評価点）」ではなくin-distributionになってしまう**——汎化ギャップを埋めたのではなく、「何をin-distributionと呼ぶか」を付け替えただけになるリスクがある。真に確認すべきは「学習に使っていない分布への汎化」であり、その意味でr3_stay→r2_a1random_a2rlの現行構成（元論文の静止base→移動generalizationという構造とも整合）を維持したまま原因を特定する方が筋が良いと考えられる。ただし、この判断はユーザの最終判断に委ねる（本ロジックの妥当性も含め要検討）。

### 31.4 現時点での推奨（ユーザ判断待ち、S3は並行して安価に進める）

- §31.1-31.2の検証は「なぜv6がv5よりcanonicalで大きく落ちるか」を完全には特定できていない。飽和ではなく、消費側（LSTM/デコーダ）のr3_stay過適合が有力候補だが未確定。
- §31.3より、baseをr2_a1random_a2rlに変更する動機（v4のR3-A先例）は、その数字が生まれた文脈（凍結Encoder問題）がv5/v6にはそもそも当てはまらないため、見た目ほど強くない。
- S3（L1損失版、SM側は同じくfreeze、~8h、安価）は本件と直交するため並行して進めてよい。S4（オラクル実験）の着手前に、上記の切り分け（値域比較、併合校正での再テスト）を追加で行うか、このまま進めてh²→other（本研究の主目的の軸）がcanonicalで劣化していない（むしろ改善している、§31.1）ことを踏まえて許容範囲と判断するか、ユーザの判断を仰ぐ。

### 31.6 独立した知見として記録：「価値の通約可能性を得る代わりに、価値の状態特異性を失う」というv6設計内在のトレードオフ（2026-09-30、ユーザ指摘）

§31.5で判明した「v6のprobe-Qは、in-distribution（r3_stay）で測ってもv4の参照値より自己位置情報の純度が低い（0.4051 vs 0.5989）」という副次的発見について、**canonicalでの低下幅の説明としてではなく、v6の設計そのものに内在する独立したトレードオフとして記録する**（ユーザ指摘、2026-09-30）。

**メカニズムの説明**：
- v4のcritic（`r3_a_direct`が使う単一の「赤好き専用」A-1 critic）は、**常に同じ好みの下で評価される**。したがって、その出力Q値は実質的に「赤との位置関係」だけを表現すればよく、状態（位置）と価値の対応が一意に近い形で学習される→**位置情報が濃く出る**（single-timestep R²=0.5989）。
- v6のcritic（`Q(s,a,r)`、任意のrに対応する条件付きcritic）は、**同じ状態でもrによって価値が変わる**。位置だけでは価値が決まらず、価値は「状態×r」の関数になる。**プローブQベクトルに含まれる自己位置の直接情報が薄まるのは、この設計の構造的な帰結**である（single-timestep R²=0.4051）。

**トレードオフとして整理**：

| | 利点 | 代償 |
|---|---|---|
| 条件付きcritic（v6） | 値域が構造的に揃う（v4/v5の70倍のstd比 → v6は約2.5倍、§9・§28参照） | プローブQの自己位置情報が薄まる（single-timestep R² 0.60 → 0.41） |

**v4での構成概念妥当性の議論との関係（両面を記録、どちらか一方の解釈に寄せない）**：v4では逆に、「単一時刻のprobe-QからR²=0.60で位置が読める」こと自体が**構成概念妥当性への脅威**として扱われていた——h¹→selfの高いR²（LSTM統合後0.91）が「A-1が自身の状態価値を理解した」ことの証拠なのか、それとも「Q値が単に自己位置の代理変数（位置センサ）として機能しているだけ」なのかを区別できない、という懸念である。

- **有利な面**：v6ではこの代理性が弱まっている（0.60→0.41）ため、「価値を理解したのではなく位置を読んだだけでは」という上記の反論を、v4よりは受けにくい。
- **不利な面**：一方でQ値は（v4では意図せずであれ）自己位置情報を供給する副次的な役割も担っていた。v4は単一時刻で0.60、LSTM統合で0.91まで伸びた。v6は単一時刻の土台が0.41であり、これがh¹→selfの低さ（in-distribution 0.8215はv5の0.7958より高く健全だが、canonical 0.4878はv5の0.7159より明確に低い、§31.1）と何らかの形で関係している可能性がある。

**結論**：この件は「バグ」でも「解決すべき問題」でもなく、**条件付きcriticという設計選択が構造的に持つ性質**として記録する。構成概念妥当性の観点からは望ましい方向の変化だが、位置情報の供給源としては弱くなっており、これがh¹→selfのcanonicalでの汎化の弱さと無関係とは言い切れない。今後（S4以降、特にS5でVE'の推定精度を評価する際）、「v6のh¹→selfがv4/v5より低いのは、構成概念妥当性が改善した代償として理解可能な範囲か、それとも別の問題（§31.2/31.5で見た消費側の汎化不足）が支配的か」を区別する視点を持ち続ける。

## 33. S4（オラクル実験）設計の事前登録（2026-09-30、結果を見る前に記録。S3完了後に着手）

### 33.1 何を「オラクル」とするか——アーキテクチャ上の決定

§19.2で既に事前登録されていた条件表（c1/c2、§19の8方向プローブQ方向情報測定用）を確認したところ、**c2（「オラクル実験のprocess-2入力」）は`r2_a1random_a2rl`の`other_vision`（実際の他者視覚データ）に対し、r=A-2の真値でcriticを評価する、と明記されていた**（§19.2表）。これはS4のオラクルが「A-1の自己視覚だけから」ではなく、**実際の他者視覚データへの特権的アクセスを許した上で、かつ報酬パラメータも真値を与える、という二重に寛大な天井（ceiling）テストである**ことを意味する。

これは一見、本研究の核心的主張（「自己視覚・自己価値だけから他者を理解する」）と矛盾するように見えるが、S4の位置づけを踏まえると整合的である：**S4は「VE'が将来どれだけうまく`r̂²`を推定できるか」とは独立に、「たとえ完全な情報（真の他者視覚＋真のr）を与えたとしても、この条件付きcritic経由のQ̂²という仕組み自体が視覚予測の改善に使えるのか」という、メカニズムそのものの健全性を確かめる関門である**。v4/v5のP0-4（`true_q2 < zero`が不成立だった）と同じ位置づけ——「正解を入れても損をする」という設計破綻がないかどうかを、最も甘い条件（真の視覚＋真のr）でまず確認し、通らなければS5（自己視覚のみからの推定、より厳しい条件）に進む意味がない、という順序である。

**この解釈をもってS4のモデル設計を次の通りとする**：

```
process-1（変更なし）: sv_enc = self_vision_encoder_module(sv)
                        q1_vec = compute_probe_q(sv_raw, r=A1_TRUE_R)   # 既存のcompute_probe_q

process-2（オラクル、新規）:
  ov_enc = other_vision_encoder_module(ov)      # 実際のother_visionを使用（base段のsvではない）
  q2_vec = compute_probe_q_for(ov_raw, r)        # 実際のother_visionにr条件付きcriticを適用
    - true_r  : r = A2_TRUE_R  (-1,+1,0,0)       # 期待：最も良い
    - wrong_r : r = A1_TRUE_R  (+1,-1,0,0)        # 期待：悪い
    - zero    : q2_vec = zeros_like(q1_vec)       # 期待：中間（S2/S3の元の設計）
    - constant: q2_vec = mean_k(true_rのq2_vec)を8方向に複製（方向情報だけ除去）  # 期待：悪い
```

μ・σ（tanh正規化）は**process-1と同じ`q_mu`・`q_sigma`を流用**する（S2で校正済みの値をそのまま使う）。理由：§2.4の「通約可能性が構造的に保証される」という設計思想そのものが、同一のcritic・同一の正規化を異なるrに対して使い回せることを前提にしているため、process-2専用に別の正規化を新設するのは設計の趣旨に反する。

**副次的な確認事項（本番）**：ov_encを「実際のother_vision」ではなく「S2/S3と同じくself_visionから計算」した場合（q2_vecの中身だけをオラクル化し、ov_encはbase段のまま据え置く、より控えめな設計）でも同じ4条件アブレーションを計算し、**主結果（other_vision版）と並べて報告する**。もし両者で判定が食い違う場合（例：other_vision版はtrue_r<zeroが成立するがself_vision版は不成立、など）、それ自体が「ov_encが実際の他者視覚を捉えているかどうか」が結果を左右するという重要な追加知見になる。これは事前登録の主判定を置き換えるものではなく、副次的な頑健性チェックとして扱う。

### 33.2 実装方針

新しいモデルクラスは作らず（学習が発生しないため）、**評価スクリプト内でS3チェックポイントを読み込み、forward()の一部（`superposition_module`以降）を手動で再現し、process-2への入力だけを4条件で差し替える**——v4の`analyze/r4_ve_eval.py`のアブレーション手法（`apply_ablation()`関数）と同じパターン。新規`analyze/oracle_eval_v6.py`として実装する。

**測定する損失**：v4のR4アブレーション（`r4_ve_eval.py`）に合わせ、`self_vision`のL1再構成損失を4条件で比較する（`true_r`が最小＝最良であることを期待）。

**測定するデータ**：`r2_a1random_a2rl`のtest split（§4.7のcanonical protocolと同一）、3000エピソード。

**併せて測定（§30.3と同じ4軸R²、`regression_baseline_v4.py`と同じ方法論を4条件それぞれに適用）**：`h²→self`が上昇するか（v4ではbase 0.06→VE段0.53〜0.63に上昇＝位置優先の症状、という逆説的な悪化パターンだった。v6のtrue_r条件でも同様の逆説が起きないかを確認する）。

### 33.3 判定基準（事前登録、結果を見る前に記録）

**主判定**：4条件のself_vision L1損失を比較し、
- `true_r < zero`：期待通り（設計は機能している）→ §28.2の距離別アブレーションを実施し、S5へ進む
- `true_r ≥ zero`：v4/v5と同じ「正解を入れると損をする」失敗パターン→ §28.2の距離別アブレーションで「遠い領域でのみ成立」を確認し、それも不成立ならS5に進む前に設計を見直す

**副次判定**：`wrong_r`・`constant`が`zero`より明確に悪ければ（「間違った/無意味な情報を入れると、何も入れないより悪い」）、この仕組みが入力の質に対して感受性を持っている証拠として記録する（true_rが良いことの必要条件ではないが、メカニズムの感受性の傍証にはなる）。

**§28.3で記録した留保を適用**：`true_r < zero`が不成立の場合、「原理的困難」と「h¹→self=0.4878という弱い土台」のどちらが主因かはこの結果だけでは区別できない。区別が必要になった場合は§28.3の優先順位（h²→other側の指標確認→§31.4の追加切り分け）に従う。

この節はS4着手前（S3完了前）の事前登録であり、結果を見てから追加したものではない。

### 37.1 未知r（連続値）への汎化——座標勾配の疑いを解消する確認

**背景**：§26.5以来、「未知r=(0,+1,-1,0)」の空間マップが、GreenとBlueが共にy=-9にあるため、座標軸勾配（x軸の明暗）と区別できないという懸念が留保されていた（§22で平面フィットのR²でも区別できなかった）。S5のVE'は連続値のr̂²を出力するため、**単一の軸整合的なrではなく、座標勾配では原理的に説明できないrで確認する必要がある**。

**方法**：新規`analyze/check_unseen_r_generalization_v6.py`（`plot_q_map_v6.py`の既存コードを再利用）で、seed2 curriculum FiLM criticに対して3条件を追加測定：

| r | 好むランドマーク | 嫌うランドマーク | 備考 |
|---|---|---|---|
| diag_RB (1,0,-1,0) | Red(-9,9) | Blue(9,-9) | 対角（x,y両方で異なる）だが単独では線形勾配でも説明可能 |
| diag_GC (0,1,0,-1) | Green(-9,-9) | Cyan(9,9) | 同上、逆対角 |

**結果**（corner読み取り）：

| | Red | Green | Blue | Cyan |
|---|---|---|---|---|
| checkerboard | 0.907 | -0.457 | 0.563 | -0.261 |

`(Red+Blue)/2 = 0.735`、`(Green+Cyan)/2 = -0.359`——**差は1.094**。線形モデルならゼロになるはずの差が、効果量と同オーダーで存在する。これは**座標勾配では説明できない、ランドマークの色そのものに基づく評価**であることの数学的に厳密な証拠である。

**方法**：新規`analyze/check_selfvision_q2_v6.py`。S4と同じS3チェックポイント・r2_a1random_a2rlデータで、q2の計算にother_visionではなく**self_vision**を使う点だけを変えて、true_r/zeroの2条件を比較。

**結果**：

| | 全体 | <5 | 5-10 | 10-15 | ≥15 |
|---|---|---|---|---|---|
| true_r − zero | **-0.0083** | -0.0081 | -0.0087 | -0.0098 | -0.0166 |

**全体でもtrue_r < zeroが成立する**（§35のother_vision版では全体は不成立だった）。かつ距離とともに単調に効果が強まるパターンは維持されている（-0.0081→-0.0087→-0.0098→-0.0166）。

**解釈**：self_vision由来のq2は、S4のother_vision由来のq2よりも全体として良い結果になった。推測される理由（未検証の仮説として記録）：SM・encoderはS2/S3を通じて`ov_enc`が常に自己視覚由来である環境で学習されており、q2もまた自己視覚由来の統計に従う方が、凍結された下流にとって「分布内」であるため——真に異なる視覚ソース（本物のother_vision、S2/S3では一度も見ていない入力分布）をq2計算にのみ使うS4のオラクル設計は、むしろ不利な条件だった可能性がある。

**判定：PASS、S5の前提はS4より有利な条件で追加確認された**。S5が実際に使う計算方式で、S4の核心的発見（true_rが効く、特に遠方で）が再現するどころか、全体判定も成立することを確認した。S5の学習に進んでよい。

## 38. S5（VE'による推定）：設計・実装・事前登録（2026-10-02、結果を見る前に記録）

### 38.1 アーキテクチャ

`docs/v6_instructions.md` §2.1・§2.7の構造をそのまま実装：

```
VE'（LSTMCell、入力=ov_enc）→ r̂²（4次元、tanh拘束）
    ↓
同一の凍結済み条件付きcritic Q(s,a,r̂²)（process-1と同じprobe_critic）
    ↓
8方向プローブでQ̂²（8次元）→ SMのprocess-2入力
```

**新規モデルクラス`SuperpositionNetworkProbeQV6ValueEstimation`**（`model/model.py`、`SuperpositionNetworkProbeQV6`を継承）：

- VE'自体は新規クラスを作らず、v4の`ValueEstimatorModuleR4`（LSTMCell＋tanh出力、`model/modules.py`）を**そのまま再利用**し、`config.value_estimator_module.output=4`（v4は8）とするだけで済んだ。
- `ov_enc = other_vision_encoder_module(self_vision)`——**自己視覚由来のまま**（S2/S3の規約を継承、実際のother_visionは使わない）。VE'はこのov_enc（未マスク、v4のMG/VEと同じ規約）からr̂²を推定する。
- **r̂²→Q̂²の計算に使う視覚も自己視覚**（`sv_raw`）——§37.2で確認した通り、これはS4のオラクル（実際のother_vision使用）より**性能の良い**設定である。
- μ・σはprocess-1と共用（S2で校正済みの値、§2.4の通約可能性の思想に従う）。
- r̂²への直接教師は一切なし。学習信号は視覚予測損失のみ（`docs/v6_instructions.md` §3のS5記述と同じ）。

**実装上の技術的な注意点（スモークテストで発見・修正）**：r̂²→Q̂²の計算で、process-1の`compute_probe_q`と異なり`torch.no_grad()`で包んではならない（包むとVE'に勾配が届かず、学習が一切進まない）。これにより`probe_critic`内部の`nn.LSTM`（cuDNN実装）が「eval()モードのままbackwardを呼べない」というcuDNNの制約に抵触し、`RuntimeError: cudnn RNN backward can only be called in training mode`が発生した。`probe_critic`にはBatchNorm・Dropoutが存在しないため、train()/eval()の切り替えは数値的に無害——`compute_probe_q2_from_r_hat`内で一時的に`self.probe_critic.train()`に切り替えてforwardし、直後に`.eval()`に戻すことで解決（グローバルに`cudnn.flags(enabled=False)`で回避する案も試したが、CNN部分の高速化も失われ約40%遅くなったため不採用）。

**新規config**：`config/model/SuperpositionNetworkProbeQV6ValueEstimation/default.yml`（S2/S3のモデルconfigと同一＋`value_estimator_module: {input:64, hidden:128, output:4}`）、`config/exp/v6_s5_ve.yml`（`v5_r4_move.yml`と同一構成：pretrain=`v6_s3_base_l1` ep200、`superposition_module`含め`value_estimator_module`以外すべて凍結、データは`r2_a1random_a2rl`——**A-2が静止しているr3_stayではVE'に推定すべき行動情報が存在しないため**、v5_r4_move/r4_move_exp3parityの先例通りr2_a1random_a2rlを使用、l1_loss、400ep）。

**動作確認**：90秒のスモークテストで(1) pretrainが`v6_s3_base_l1` ep200から正しくロードされること（`value_estimator_module.*`はcheckpoint側に存在しないため新規初期化のまま保持される、既存の`util.load_pretrain`のマージロジックで自動的に処理される）、(2) freezeリストが意図通り（`value_estimator_module.*`のみ学習対象）であること、(3) 上記cuDNNバグ修正後、学習ループが1.69it/s（300 batch/epoch）で進むことを確認。400ep×300batch/1.69it/s ≈ **19.7時間**の見込み。

### 38.2 判定基準（事前登録、結果を見る前に記録）

`docs/v6_instructions.md` §3のS5基準に加え、ユーザから2点の追加指示があった。

**① 2段階判定（S4と同じ構造）**：

| | 判定 |
|---|---|
| 全体 | `r̂²`が真値（A-2: (-1,+1,0,0)）と相関するか |
| 距離別 | 遠い領域（§27/§28と同じ境界の≥10＝10-15と≥15ビンを合算、またはそれぞれ）で相関が強まるか |

**解釈規則（S4の§28.2・§33.3をそのまま適用）**：全体で不成立でも、遠い領域で相関が成立し、かつ`constant`相当の対照（後述）がその距離トレンドを共有しなければ、「原理的には機能するが、A-2の行動特性（Greenに張り付く）により実データでは効きにくい」と判定する。全体・遠方の両方で不成立なら設計の見直しを検討する。

**② 自己投影指標**：

- `r̂²`とA-1の真値`(+1,-1,0,0)`の相関
- `r̂²`とA-2の真値`(-1,+1,0,0)`の相関
- **どちらに近いか**（A-1寄り＝自己投影、A-2寄り＝他者理解）

これは研究の主張そのものに関わるため、全エピソード平均だけでなく**学習の経過（エポック）に沿って**算出し、自己投影からの脱却（あるいはその欠如）が見えるかを確認する（具体的には、late-5だけでなく代表的な中間エポック——例えば50, 100, 200, 300, 400など save_interval=10の倍数——でも同じ相関を計算し、推移をプロットする）。

**③ `docs/v6_instructions.md` §3オリジナルのS5基準（そのまま維持）**：

- `r̂²`と真値の相関（赤成分が負、緑成分が正になるか）——②に包含
- `true_r`アブレーション（S4・§35-37）との比較：VE'の推定が、真値を与えた場合にどれだけ近づくか
- `Q̂²→A-2位置 > Q̂²→A-1位置`（v4では逆転していた）
- 方向cos_sim（Q̂²の最大値方向とGreenへの真の方向の一致度）が正

**④ v4の「位置優先」病理の継続監視**：S4同様、`h²→self`が不自然に上昇しないかを引き続き確認する（§35.2で基準ラインは確認済み：zero条件でh²→self=0.0114）。

**⑤ 対照条件**：S4の`constant`に相当する対照として、**r̂²をランダムな固定値（学習されない、各エピソードで同じ分布からサンプルするが教師なし学習の結果ではない）に置き換えた場合**、または**r̂²の時系列をシャッフルした場合**を検討し、「r̂²が実際に有用な情報を持っているか」を、①の距離別パターンの比較と合わせて判定する（詳細はS5学習完了後、結果を見てから設計するのではなく、本節の枠組みの中で遂行する）。

この節はS5着手前の事前登録であり、結果を見てから追加したものではない。

## 39. S5結果（2026-10-03）——混合した結果、総合判定は保留してユーザに提示する
