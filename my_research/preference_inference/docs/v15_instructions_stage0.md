## 0. 背景（新しいチャットのための要点）

- これまで（v11〜v14）の環境：20×20 のアリーナの四隅に赤・緑・青・シアンのランドマーク。赤と緑の位置はエピソードごとに 1/2 で入れ替え（`sim_v10`）。A-1 は赤好き・緑嫌い、A-2 は緑好き（または赤好き）。好きな色へ一歩ごとに 50% の確率で向かい、残りはランダム。快・不快 P は「8 方向の範囲ごとの（赤の画素 − 緑の画素）」。
- 分かったこと：他者の好みの推定は、どの方法でも「A-2 が直近に進んだ方角」で止まった（v14 ログ §18〜§21）。A-2 は好きな色へまっすぐ進むので、方角を外挿すれば予測でき、好みを持つ必要がない。
- v15 の考え方：好みは一貫させたまま、**選べるもの（どの色がまだあるか）を場面で変える**。好きな物に着くと「食べて」灰色になり、次に好きな物へ向かう。**食べた直後にどこへ向かうかは、方角の外挿では決まらず、好みの順位でしか決まらない。**

## 1. 段階0 の目的

学習の前に、次の三つをデータだけで確かめる。
1. 「食べる」が十分な回数起き、食べた後に向かう方角が変わること。
2. 食べた後の行動を、方角の外挿や位置・配置だけでは当てられず、**それまでの A-2 の行動から順位を推す観察者**（§5.3 の (d)）ならはっきりよく当てられること。本当の順位を外から教えた予測 (c) は上限として並べるだけで、主の比較には使わない（ネットワークは本当の順位を知らないため）。
3. 評価する時点の位置と直近の方角はそろっているが、**それより前の行動（好みを示す証拠）が違い**、そのために次の向かう先が違う場面（以下「食い違いの組」）を、十分な数作れること。後の段階で「方角や位置では区別できない場面」の評価に使う。

## 2. 作業場所と運用の約束

1. **GPU は使わない（CPU のみ）**。学習もしない。
2. **v11〜v14 のコード・データ・結果は変えない**。v15 のコードは新しいファイル（または子クラス、設定）として分ける。結果は `data/result/v15/` と `v15_*` にだけ書く。
3. 作業場所：v13・v14 のチャットが同じ worktree（`.worktrees/v11`、ブランチ `feature/v11-self-experience`）で動いている。段階0 は既存データを使わないので、**新しいブランチ（または worktree）で作業する案と、同じ worktree で v15 のファイルだけを足す案を比べて提案し、私の確認を取ってから始める**。後の段階で v4 の Encoder の重みや v12 のコードを使うことも考慮すること。同じ worktree を使う場合、コミットは v15 のファイルを名指しで追加する。
4. 未決事項（§4.2）は**案を出して私の確認を取ってから実装する**。
5. 判定の基準（§6）は、計算の前にログに事前登録としてコミットする。結果を見た後に加えた確認は「事前登録外」と書く。
6. データの生成は乱数を固定し、2 回生成してビット単位で一致することを確かめる。
7. 図は目視で確かめてから報告する。目視していない図は「未確認」と書く。
8. 記録とコミットと push は区切りごとに行い、報告にはコミットの番号を書く。
9. 報告は、何が分かったか → 根拠の数値 → 判断してほしいこと、の順で、平易な日本語で書く。
10. 段階1以降で GPU を使うときは、論文の実験（v13・v13-NS・シードの追加とその評価）を優先する。v15 は空いている GPU だけを使い、使う前に空きを確かめ、私の確認を取ってから起動する。

## 3. 環境の設計（決まっていること）

方針の「今の設計との違い」の表に従う。要点：

| 項目 | v15 |
|---|---|
| ランドマークの位置と数 | 今と同じ（四隅に 4 個）。自己位置の手がかりを変えない |
| 赤と緑の入れ替え | 今と同じく、エピソードごとに 1/2 |
| 色がない回 | エピソードごとに 1 色を灰色の立方体にする（その色がない回）。**立方体は消さない**（見え方の構造を変えないため） |
| 食べる | エージェントが、向かっている好きな物に一定の距離まで近づくと、その物は灰色になる。灰色は以後そのエピソードの間ずっと灰色 |
| ランドマークが変わる時 | エピソードの間（配置・灰色の色）と、エージェントが食べたときだけ。それ以外はエピソードの中で変えない（元論文の「自分の運動で説明できない変化は他者だけ」という分化の圧力を保つため） |
| A-1 の好み | **一貫した順位で、全エピソードで同じ**（例：赤 > 青 > 緑） |
| A-1 の動き（1段目のデータ） | 一歩ごとに割合 p で「まだある中で一番好きな物」へ向かい、残りはランダム（v11 のルールエージェントの延長。壁で滑る、眠りあり）。食べたら次に好きな物へ |
| 1段目の A-2 | 静止（今と同じ）。**食べるのは A-1 だけ** |
| 2段目の A-1 | ランダム（今と同じ）。食べない |
| 2段目の A-2 | A-1 と同じルールで、A-2 の順位に従って動き、食べる。**食べるのは A-2 だけ** |
| 快・不快 P | 8 方向の範囲ごとに Σ（色の画素 × その色の価値）。灰色は価値 0。視界は今と同じ非回転の全方位カメラ |

### 3.1 指示の土台からの修正点（このチャットの決定に合わせた）

- **A-2 の順位はエピソードによって変える必要がある**。A-2 がいつも同じ順位なら、推し量る必要がなく、§1 の 3（好みの順位だけが違う組）も作れない。v12 の ① と ② に合わせて、2 段目のデータは二つ作る：
  - ①：A-2 の順位はいつも同じ（A-1 と違う順位）。
  - ②：A-2 の順位がエピソードごとに変わる（少数の順位の中から選ぶ）。**段階0 の主の分析は ②**。
  - ③（対照）：A-2 の順位の候補を「一番好きな物は同じで、二番目が違う」ものにし、同じ乱数のキーで二つのエピソードを作る。食べる瞬間まで軌跡が完全に同じなので、**食べた直後の向かう先は、どんな観察者にも予測できない（推す材料がない場面）**。後の段階で「推す材料がない場面では偶然並みになる」ことを確かめる対照として使う。
- **② の順位の候補の選び方（指摘2 を受けて）**：観察から順位を推せるように、次を満たす組み合わせにする。
  - **一番目の色がすべての候補で違う**。一番目に何を食べたか（または食べる前にどこへ向かったか）で、候補が一つに決まる。
  - **二番目の色も候補によって違い**、それぞれの二番目が違う隅にある。一番目を食べた直後の向かう先が候補で分かれる。
  - 赤と緑の入れ替えを使うと、「赤を一番目に食べる候補」と「緑を一番目に食べる候補」が、配置によって同じ隅で同じ向きから食べる場面ができる。§5.5 の主の組はこれを使う。
  - 例（案）：候補 A＝赤 > 青 > …、候補 B＝緑 > シアン > …。この場合シアンにも価値を持たせる必要がある。
  - 1 色が最初から灰色の回では、一番好きな物がない候補が出る。そのとき「一番目に食べた物」から候補が一つに決まるかを確かめ、決まらない場合の扱い（その組み合わせを作らない、など）を案として出す。
- **自分（A-1）の好みは一貫させる**（順位を変えない）。エピソードごとに変えるのは A-2 の順位だけ。
- 好きな物をすべて食べた後（またはまだある物に価値が正のものがないとき）の動きを決めておく（案：ランダムに歩く）。

## 4. 実装

### 4.1 v15 の環境とルールエージェント
- v11core の環境（`sim_v10` 系）とルールエージェントをもとに、§3 を実装する。v12〜v14 のコードは書き換えない。
- エピソードごとのキーで、配置・灰色の色・初期位置・A-2 の位置（1段目）・眠りの時刻を揃えられるようにする（v11 と同じく、経験あり・なしの 2 条件を対にできるように）。
- 出力：v11 と同じ形のデータ（視界、運動、P、位置）に加え、各ステップの「どの色がまだあるか」「エージェントの今の目標」「食べた時刻」「A-2 の順位」を記録する。

### 4.2 まず案を出して確認を取るもの（実装の前に）
1. **好みの順位と価値の値**：A-1 と A-2 の順位、各色の価値（例：A-1 は赤 +1、青 +0.5、緑 −1、シアン 0）。② で A-2 がとる順位の候補（2〜3 種類。§3.1 の条件を満たすもの）と、③ の対照の候補。シアンの扱い（② の条件のために価値を持たせるか）。A-1 の順位と ② の候補の関係（A-1 と同じ順位の候補を入れるか）。
2. **灰色にする色の選び方**：毎回 1 色か、全色がある回も混ぜるか。どの色を灰色にしやすくするか（例：好きな物が一つもない回を作らない）。
3. **食べる条件**：どれだけ近づいたら食べたことにするか（距離のしきい値）。四隅にあるので、壁に沿って滑る動きとの兼ね合いも考えること。
4. **規則で動く割合 p**：50% と 80% の両方でデータを作る（§5 の比較のため）。A-2 についても 50% と 80% を作り、90% も参考に作る。
5. **食い違いの組の作り方（§5.5）**：主の組（評価時点の位置と方角がそろい、それより前の行動が違う組）の取り出し方と、③ の対照の組の作り方の案。
6. **(d) 理想の観察者の作り方（§5.3）**：尤度の作り方（A-2 が規則で動く割合 p を既知とするか）、使う証拠の範囲。

以上を一つの報告にまとめて私の確認を取ってから実装すること。

## 5. 計算すること（段階0 の表の全項目と追加）

データの規模は、段階0 では各条件 1000 エピソード（100 ステップ）を目安にする（後の学習にそのまま使える形で作る）。

### 5.1 食べる回数
- 1段目の A-1、2段目の A-2 について、1 エピソードあたりの食べた回数の分布、最初に食べた時刻の分布、食べた後のステップが全体に占める割合。p ごと。

### 5.2 食べた後に向かう方角が変わる割合
- 食べる直前 k ステップの進行方向と、食べた直後 k ステップの進行方向の角度の差（k = 3、5、10）。45° より大きく変わる割合。p ごと。

### 5.3 (a)(b)(c)(d) による予測の当たり方（主に ② の A-2、1段目の A-1 も）
- 予測の対象：食べた直後 k ステップの変位の方向（k = 3、5、10）と、次に着く（食べる）ランドマーク。
- (a) 直前の進行方向の外挿：食べる直前 k ステップの変位の方向をそのまま延ばす。
- (b) 位置と配置だけ：その時点の位置、直近の進行方向、配置（入れ替え・最初からの灰色）、今まだある色を入力とし、**順位も、それより前の A-2 の行動の履歴（どこへ向かったか、何を食べたか）も使わない**最良の予測器。履歴を入れると (d) と同じになるため入れない。
  - 注意：「今まだある色」には、食べた物が灰色になったことが含まれるので、それだけで何を食べたかが分かる場合がある（環境の状態が行動の証拠を運ぶ）。(b) にこれをどう渡すかの案と、「今まだある色」だけで順位がどこまで分かるかを別に報告すること。
- (c) 本当の好みの順位（上限）：まだある中で一番好きな物の方向。**ネットワークは本当の順位を知らないので、主の比較には使わない。**
- **(d) 観察から推す理想の観察者（主）**：② の順位の候補それぞれについて、そのエピソードの食べる前までの A-2 の行動（各ステップの移動、向かった先、食べた物）の尤度を計算し、候補に確率を割り振る（事前分布は ② での出現割合）。その確率で、まだある中で一番好きな物を予測する。
- 指標：角度の誤差の中央値と、次の目標のランドマークの正解率。**主の比較は (d) − (a)、(d) − (b)**。(c) は上限として並べる。差の信頼区間はエピソード単位のブートストラップ。
- (d) の確率が、食べる前の観察ステップ数とともにどう立ち上がるか（何ステップ見れば順位が分かるか）も描く。

### 5.4 好みに従う割合 50% と 80% の比較
- 5.1〜5.3 と 5.5 を p ごとに並べる。v13 で見つかった「角にとどまる」問題（好きな物に着いた後に角に滞在する）がないかも確かめる（後半に角から 5 以内にいる割合）。

### 5.5 追加：食い違いの組
後の段階で、方角や位置では区別できない場面での評価に使う。

**主の組：評価時点の位置と方角はそろい、それより前の行動（好みを示す証拠）が違う**
- ② のデータで、食べた直後の場面どうしのうち、次の条件をすべて満たす組を数える。
  - 食べた隅が同じ（現在位置の差が d 以内、d = 1、2）。
  - 直前 k ステップの進行方向の差が θ 以内（θ = 15°、30°）。
  - 食べた物の色が違う（例：赤と緑の入れ替えにより、同じ隅で「赤を食べた A-2」と「緑を食べた A-2」）。つまり、それより前の行動が好みの違いを示している。
  - そのために、次の目標（まだある中で一番好きな物）が違う。
- 組の数、関わるエピソードの数を出す。各組で、(a)・(b) が二つの場面に同じ予測を出すこと、(d) が違う予測を出して当たることを確かめる。
- 自然に起きる組が少なければ、配置と初期位置をそろえて組を作るように生成する案を出す（同じ隅に同じ向きから着くように）。

**対照の組（③）：推す材料がない**
- §3.1 の ③ のデータ（一番好きな物が同じで二番目が違う候補、同じ乱数のキー）。食べる瞬間まで軌跡が完全に同じになる。
- 軌跡が食べる瞬間まで本当に一致するか（ビット単位）、食べた後に分かれるまでのステップ数を確かめる。
- (d) を含むどの予測器も、食べた直後は 50% 程度になることを確かめる（作りの上でそうなるはず）。後の段階で、学習したネットワークがこの組で 50% を大きく超えたら、何かの漏れを疑う材料にする。

## 6. 判定の基準（事前登録の土台。計算の前にコミット）

方針の段階0 の表に従う。具体的なしきい値は §4.2 の確認のときに一緒に決める。案：

| 確かめること | 合格の目安（案） |
|---|---|
| 食べる回数 | 選んだ p で、エピソードの 80% 以上で 1 回以上 |
| 向かう方角が変わる割合 | 食べた前後で 45° より大きく変わる割合が 50% 以上 |
| (a)(b)(c)(d) | 食べた直後 k = 5 で、**(d) の正解率が (a)・(b) を上回り**、差の信頼区間が 0 を含まない（差の大きさも書く）。(c) は上限として並べる |
| p の比較 | 上の三つを満たし、角への滞在が少ない方を選ぶ |
| 配置の種類と出現回数 | すべての配置が学習データ 3000 エピソード換算で十分な回数（案：各 100 回以上）出る |
| 主の食い違いの組（§5.5） | 評価に使える組が十分な数（案：300 組以上）。その組で (d) が (a)・(b) を上回る |
| 対照の組（③） | 軌跡が食べる瞬間までビット単位で一致し、食べた直後の (d) が 50% 程度 |

すべて満たせば段階1（Encoder だけの試し）に進む。**(d) が (a) を上回らなければ、観察から順位を推す材料が環境にないので、学習に進まず設計を直す案を出すこと。** (c) が (a) を上回っても (d) が上回らない場合も同じ。
