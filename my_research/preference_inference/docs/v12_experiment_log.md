## 1. 指示と背景（2026-10-19、草野さん）

**v11 で他者に伝わらなかった理由**（草野さんのまとめ）
- 経験ありのモデルの「快の高い方へ動く」見積もりは、毎ステップ快・不快の入力から作り直されるだけで、LSTM の中で積み上がる仕組みになっていなかった（入力停止の検査）。
- そのため、他者側に A-2 の本当の快・不快を入れても A-2 の予測に使えなかった（D6）。見積もりは自分の景色を描く経路の中にだけあったと考えられる。
- 運動を入れなかったことで、自他の書き方の揃い（Fig.5）も失われた。

**v12 の考え方**
- process-1 の入力を「運動（元論文と同じ）＋ 方向ごとの快・不快（8 次元）」にする。運動を積み上げて位置を追う仕組みと、自他の書き方の揃いを取り戻すため。
- 運動は区間ごとにときどき隠す（零にする）。隠れている間、LSTM は自分の動きを推し量るしかない。経験ありのモデルなら、快・不快から「快の高い方へ動いている」と推し量り、その見積もりが LSTM の中の運動を積み上げる仕組みに入ると期待する。
- 2 段目では、process-2 の運動の枠は零のまま、他者用の部品（元論文の MG と同じ作り）に快・不快の枠を埋めさせる。
- 部品や損失は足さない。それ以外（環境、2 条件、1 段目・2 段目の手順、評価の指標）は v11 と同じ。

**依頼**：1. v11 のデータに A-1 の運動があるかの確認、2. v12 のモデルの実装（案と理由を添えて）、3. GPU7 での小規模な試し学習、4. 本番・関門・2 段目の計画と所要時間・GPU の案。**試し学習の結果と計画の案を報告して、確認を待つ。本番は確認の後。**

## 2. 確認：v11 のデータの A-1 の運動（2026-10-19。コード変更なし）
- `v11_s1_random`・`v11_s1_mixed`（1 段目）、`v11_s2_green`・`v11_s2_pref`（2 段目）、`*_first1000` のすべてに `self_motion`（(N, 101, 2)、float32）がある。2 段目のセットと T2・T5 の test セットには `other_motion` もある。
- 中身（各 train の先頭 300 エピソードで確認）：
  - `self_motion[t] = p_{t+1} − p_t`（最大誤差 1e-6）。つまり t の入力の運動は「視界 v_t を見た後に取った一歩」で、予測の正解 v_{t+1} を決める一歩である。元論文の loader（`x['self_motion'] = self_motion[:, t]`）と同じ対応。
  - 大きさは 1（動いた一歩）か 0 だけ。**0 は眠りの一歩で、全体の 8.25〜8.32%**（`a1_source`＝3 と完全に一致）。
- **結論：そのまま使える**（収集し直す必要はない）。ただし「運動が零なら隠れている」とは区別できない（眠りも零）。§3 の印の案につながる。

## 3. 設計の案（2026-10-19。**草野さんの確認待ち。試し学習はこの案で行う**）

| 項目 | 案 | 理由 |
|---|---|---|
| 運動の入力の形 | **元論文と同じ**：`self_motion` の 2 次元（動いた一歩は単位ベクトル、眠りは 0）を加工せずに入れる | 元論文（v4）の exp1 と同じ入力にして、運動の積み上げ（位置の追跡）と自他の揃いが戻るかを、v4 と同じ条件で見るため。大きさは快・不快（[−1, 1]）と同じ程度 |
| process-1 の入力 | **[運動 2, 快・不快 8, 隠れの印 1] の 11 次元** | 快・不快は v11 と同じ（自分の視界から計算、マスク前） |
| 隠す区間 | **v11 の補強案 (i) と同じ作り**：t=0 は見せ、t=1 から「見える区間」と「隠れた区間」を交互に（見える区間から）、それぞれの長さは 5〜15 の一様な整数。エピソードごとに `init_state` で CPU の乱数から引く。隠れる割合は約 48%（t≥1） | 基準案どおり。(i) で実装と性質（隠れる割合 0.479）を確かめてある。視覚のマスク・dropout は CUDA の乱数なので影響しない |
| 隠したことの印 | **入れる**（1 次元、隠れている間 1、ほかは 0） | 確認の結果、運動が零のフレームは眠り（8.3%）にもある（§2）。印がないと、「動いていない（眠り）」と「動きが分からない（隠れ）」が同じ入力になり、隠れている間に「快の高い方へ動いている」と推し量る理由がぼやける。印は入力の 1 次元で、部品や損失は足さない |
| 快・不快を隠すか | **隠さない**（運動だけを隠す） | 隠れている間、動きを推し量る手がかりは快・不快だけにしたい（それがこの設計の狙い）。両方を隠すと、見積もりは記憶だけに頼る別の検査になる（v11 の (i) で試した形） |
| 視覚のマスク | v11・元論文と同じ（t=0 は見せ、t>0 は 0.99） | 変えない |
| process-2 の入力（1 段目） | **11 次元すべて零**（印も 0） | 元論文の exp1（A-2 は静止、om＝0）と同じ。1 段目の A-2 は静止 |
| process-2 の入力（2 段目、案） | **運動の枠 0、快・不快の枠に部品 G の出力 Q2（8 次元、tanh）、印は 1（「A-2 の動きは分からない」）**。印 0 の場合も評価で並べる | A-2 の動きは見えないので、「動きが隠れていて、快・不快だけが分かる」状態（1 段目で隠れた区間に学んだ状態）を他者に当てはめる形にする。印の値は 2 段目の計画の確認事項（§6） |
| 2 段目の process-1 の運動 | **隠さない**（印 0） | 元論文の exp3 と同じ（process-1 には本当の運動）。A-1 自身の動きが process-1 で分かっていれば、G が Q2 に A-1 の動きを流す抜け道（v11 §7.40 の 3）が閉じる |
| 学習の手順 | v11 と同じ（exp1：mse 段 200ep で全部 → l1 段 200ep で Decoder だけ。2 段目は exp3） | 変えない |

- **修正**：試し学習の process-2 の検査（§4 の 5）は、印 0・1 の両方を出す作りだったが、**印 1 の条件でも対照（快・不快を入れない場合）が印 0 になっていた**。これでは「快・不快を入れたこと」と「印を立てたこと」の効果が混ざる。対照も同じ印にそろえた（対照 = [0, 0, 零, 印]）。**主は印 1**、印 0 は補足。ep10 の動作確認以外では、この検査はまだ計算していない（ep150 だけで行う）。
- 理由（草野さん）：1 段目の process-2 に印ありで零を入れると、LSTM が「他者側で印ありなら動かない」と覚えるおそれがある。1 段目は印なしで零なので、その心配はない。
