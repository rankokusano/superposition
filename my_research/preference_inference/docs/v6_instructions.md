## 0. なぜ v6 をやるのか

### v4 / v5 で分かったこと（確定済み、変更しない）

| 問い | 結果 |
|---|---|
| (a) A-1 の視覚予測 | ✅ できる（h¹→self 0.907） |
| (b) A-2 の視覚予測 | ✅ できる（base 段 h²→other 0.95〜0.98） |
| **(c) A-2 の価値予測** | ❌ **できない** |

**(c) が失敗した原因は2つ、いずれも構造的：**

1. **Q値が自他で通約不可能**。A-1 の Q値 std 0.63 に対し A-2 は 0.009。同じ入力欄に乗らない。値域を揃える対照実験（P1.75）で「害」と「非収束」は消えたが、益にはならなかった
2. **位置を流すほうが楽**。VE の入力は A-1 の視覚由来なので、他者の価値を推定するより自分の位置情報を流すほうが視覚予測の損失が下がる。収束した忠実系列（v5_r4_move）で `Q̂²→A-1位置 0.387 ≫ →A-2位置 0.097`

### v6 の狙い

**推定対象を Q値から「報酬パラメータ」に変える。** これは教授のミーティングメモにある「ステップ2」に相当する。

> ステップ2 逆強化学習について調べる。＝＞ ここ研究かも：ステップ1の情報を反映できないか検討する。
> 逆強化学習：何が既知で何が学習か？

**報酬パラメータに変えると、上の2つの問題が同時に解ける見込みがある：**

| v4/v5 の問題 | v6 での解決 |
|---|---|
| Q値が通約不可能 | **報酬は同じ尺度で定義される**。A-1 が (赤+1, 緑−1)、A-2 が (赤−1, 緑+1) なら同じ空間に乗る |
| 位置を流すほうが楽 | **推定対象が4次元しかない**。位置情報を符号化する帯域がない。抜け道が構造的に塞がる |
| VE に推定する動機がない | **報酬を間違えると、そこから計算される Q値が全部狂う**。process-2 の入力が壊れ視覚予測が悪化する。初めて「正しく推定する動機」が生まれる |

### IRL との関係（論文の新規性の軸）

| | 既知として与えるもの | 推定するもの |
|---|---|---|
| 通常の IRL | 他者の状態・行動系列、環境の遷移モデル、特徴量設計 | 報酬関数 |
| **v6** | **A-1 の一人称視覚のみ** | **他者の報酬パラメータ** |

成功すれば「他者の状態も行動も直接観測せず、一人称視覚だけから他者の報酬を推定した」となる。IRL の前提を大きく緩めた主張になる。

失敗しても「報酬レベルまで降りても、視覚予測の損失だけでは他者の価値は推定できない」という、v4/v5 より一段深い境界の主張になる。**どちらでも論文に書ける。**

## 2. v6 の設計

### 2.1 中核のアイデア

**SM への入力形式（8次元プローブQベクトル）は変えない。** 変えるのは「Q値をどこから得るか」だけ。

```
v4/v5:  VE → Q̂²（8次元）を直接出力 → SM

v6:     VE → r̂²（報酬パラメータ 4次元）
            ↓
        報酬条件付き critic Q(s, a, r̂²)
            ↓
        8方向プローブで Q̂²（8次元）→ SM
```

**SM のアーキテクチャは一切変更しない。** v4/v5 との比較可能性が保たれる。

### 2.2 報酬パラメータの定義

4次元ベクトル `r = (w_red, w_green, w_blue, w_cyan)`。各ランドマークの重み。

- **A-1 の真値**：`(+1, −1, 0, 0)`
- **A-2 の真値**：`(−1, +1, 0, 0)`

報酬の計算：`reward = Σ_k w_k · fraction_k`（各ランドマークのピクセル割合の重み付き和）

**現行の報酬関数（`red_fraction − green_fraction`）は、この形式の特殊ケース**であることを確認してください。青・シアンの重みが0なら一致するはずです。

### 2.3 報酬条件付き critic

**これが v6 の新規実装の中心。**

```
現行：Q(s, a)      — A-1 専用、A-2 専用の2つの critic
v6：  Q(s, a, r)   — 報酬パラメータを条件として受け取る単一の critic
```

**学習方法**：SAC の学習中、エピソードごとに報酬パラメータ `r` をランダムにサンプルし、その `r` に従って報酬を計算して学習する。critic には `r` も入力する。

これにより、**1つの critic が任意の報酬パラメータに対する価値を計算できる**ようになります。

**superposition の思想との整合**：A-1 が「自分の価値計算機構を他者に流用する」形になります。元論文の「同じモジュールで自他を処理する」を、**価値計算のレベルまで拡張**したことになる。これは論文の主張として書ける。

### 2.4 通約可能性が構造的に保証される

**同じ critic に異なる `r` を入れるだけ**なので、出力の値域は構造的に揃います。

v4/v5 では A-1 の critic と A-2 の critic が別物だったため値域が桁違い（0.63 vs 0.009）でしたが、**v6 ではこの問題が設計レベルで消えます。**

これは P1.75（対称サニティ）で人工的に揃えたものを、**自然な形で実現**することに相当します。

### 2.5 Visual Encoder は価値入力の下で学習し直す（v5 と同じ）

**結論：v6 でも Encoder をスクラッチ学習してください。元論文の Encoder を凍結流用してはいけません。**

**理由：**

1. **元論文の Encoder では収束しない可能性が高い。** v5 の実験で、元論文の Encoder（運動入力レジームで学習）を凍結したまま価値入力で学習すると **3シードとも収束しませんでした**（R3-stay_400 0/3）。Encoder を価値入力の下で学習し直すと収束します（v5_base_mse、trans@27）。
   **収束しなければ S4 の判定（`true_r < zero` か）も信頼できません。実験そのものが成立しません。**

2. **v6 も入力は価値**です。運動用に組織化された Encoder を使うのは原理的に不整合です。

3. **v5 の Encoder をそのまま流用することもできません。** v5 の Encoder は「A-1 専用 critic から出たプローブQ」を入力とする条件で学習されました。v6 では critic が `Q(s,a,r)` に変わるため、**プローブQ の値そのものが変わります**。

**v5 で判明した代償（承知の上で進める）：** Encoder を価値入力で学習すると、自己側（収束・視覚損失・予測画像・h¹ 組織化）は改善しますが、**他者側は悪化**します（h²→other 0.86 → 0.64、場所マップが2次元 → 片軸、Fig.5 マージン 0.091 → 0.025）。

v6 は他者の報酬推定が目的なので、これはハンデです。ただし**収束しないよりはましです**。S4 の結果を解釈する際、この留保を必ず併記してください。

### 2.6 比較対象

**主たる比較相手は `v5_r4_move`** です。

| | 推定対象 | Encoder | critic |
|---|---|---|---|
| v5_r4_move | Q値（8次元） | 価値入力で学習 | A-1 専用 `Q(s,a)` |
| **v6** | **報酬（4次元）** | 価値入力で学習 | **条件付き `Q(s,a,r)`** |

Encoder の条件が揃うので、**違いは「推定対象」と「critic の形式」だけ**になります。これが最もきれいな比較です。

v4 の P0-4（元論文 Encoder + Q値 + 専用 critic）との比較は、**3要因が同時に違う**ので補助的な扱いにしてください。

### 2.7 VE'（報酬推定モジュール）の構造

```
入力：ov_enc（A-1 の視覚を Encoder-2 に通したもの）
内部：LSTMCell（時間統合。報酬推定は観察の蓄積を要するため）
出力：4次元 → tanh → r̂²
```

**LSTMCell を使う理由**：報酬の推定は「この他者はこれまでどう動いてきたか」の蓄積を要します。緑に向かい続けるのを見て初めて「緑が好きらしい」と推定できる。瞬間の視覚だけでは原理的に無理です。

元論文の MG が LSTMCell を持っていたことも確認済み（v4 実装差分の調査）。

**出力を tanh で拘束**すること（v4 の教訓：無拘束だと std=53、min=−481 まで爆発した）。

## 3. 実験の段階（ゲート）

**各段の判定基準を満たすまで次に進まないこと。**

### 3.0 全体構成（元論文・v4・v5 との対応）

| 段 | 元論文 | v4 | v5 | **v6** |
|---|---|---|---|---|
| critic | なし（RL 不使用） | A-1/A-2 専用 `Q(s,a)` ×2 | 同左 | **条件付き `Q(s,a,r)` ×1** |
| base(MSE) | `exp1_mse_1000`<br>運動入力・**Encoder 学習** | （元論文を流用） | `v5_base_mse`<br>Q値・**Encoder 学習** | **`v6_base_mse`**<br>条件付きQ値・**Encoder 学習** |
| base(L1) | `exp1_l1_1000`<br>Encoder 凍結 | `R3-stay`（Encoder 流用） | `v5_base_l1` | **`v6_base_l1`** |
| 生成段 | `exp3_1000`<br>**MG**（運動生成） | `P0-4`<br>**VE**（Q値生成） | `v5_r4_move` | **`v6_ve`**<br>**VE'（報酬推定）** |

**各段で何を学習するか**（全条件共通）：

| | base(MSE) | base(L1) | 生成段 |
|---|---|---|---|
| Visual Encoder | 学習 | 凍結 | 凍結 |
| Shared Module | 学習 | 凍結 | 凍結 |
| Decoder | 学習 | **学習** | 凍結 |
| Integration / FPM | 学習 | 凍結 | 凍結 |
| 生成モジュール | なし | なし | **学習（これだけ）** |

**データ**：base 段は `r3_stay`（A-2 静止、既存）、生成段は `r2_a1random_a2rl`（A-2 移動、既存）。**新規のデータ収集は不要**です（条件付き critic の学習用データを除く）。

### S1：報酬条件付き critic の学習

**内容**：`Q(s, a, r)` を学習する。報酬パラメータをランダムサンプルしながら SAC を回す。

**判定基準**：
- critic 健全性チェック（ノイズ画像・4隅・行動変化に対する Q の応答。`action_std > 0.05` かつ `state_std > 0.05`）
- **報酬条件への応答**：`r = (+1,−1,0,0)`（A-1 の報酬）と `r = (−1,+1,0,0)`（A-2 の報酬）で Q値の空間分布が**明確に異なる**こと。前者は赤の近くで高く、後者は緑の近くで高い
- **値域の一致**：両条件で Q値の std が同オーダー（v4 では 0.63 vs 0.009 だった）

**この段で失敗したら v6 全体が成立しません。** 必ず確認してから進むこと。

### S2：base 段（MSE）— Encoder を含めて学習

**内容**：`r3_stay` データ、条件付き critic からのプローブQ を process-1 入力、process-2 は零ベクトル。**Encoder を含む全モジュールを学習**（pretrain なし、スクラッチ）。400ep。

**判定基準**：
- **収束**（§4.2 の基準）。v5_base_mse は trans@27 で収束した
- 視覚損失が v5_base_mse（fp_other 20.1、self_vision 12.05）と同水準以下
- `h¹→self` が v5（0.796）と同水準以上

### S3：base 段（L1）

**内容**：S2 から pretrain、decoder のみ学習、200ep。元論文 `exp1_l1` の凍結リストに準拠。

**判定基準**：収束、4軸R² が v5_base_l1 と同水準以上。

### S4：オラクル実験【最重要ゲート】

**内容**：VE を使わず、**A-2 の真の報酬パラメータ `(−1,+1,0,0)` を直接**条件付き critic に与えて Q̂² を計算し、SM の process-2 入力にする。

**なぜ最重要か**：v4/v5 では「A-2 の真の Q値を入れると、何も入れないより視覚予測が悪化する」という結果でした（`true_q2 − zero = +0.00441`）。**正解を入れると損をする設計だった。**

v6 では**正解を入れると得をする**はずです。そうでなければ設計が破綻しています。

**判定基準**（v4 と同じ4条件アブレーション）：

| 条件 | 期待 |
|---|---|
| **true_r**（A-2 の真の報酬から計算した Q̂²） | **最も良い** |
| zero（零ベクトル） | 中間 |
| wrong_r（A-1 の報酬 `(+1,−1,0,0)` を誤って使う） | 悪い |
| constant | 悪い |

**`true_r < zero` が成立しなければ、S5 以降は無意味です。** その場合は設計に戻ってください。

**併せて測定**：
- 4軸 R²（h¹→self / h¹→other / h²→self / h²→other）
- `h²→self` が上昇するか（v4 では base 0.06 → VE 段 0.53〜0.63 に上昇＝位置優先の症状）

### S5：VE' による推定

**内容**：VE に報酬パラメータを推定させる。**教師信号は視覚予測損失のみ**（v4 と同じく、`r̂²` への直接教師は与えない）。

**判定基準**：
- **`r̂²` と A-2 の真値 `(−1,+1,0,0)` の相関**。特に赤成分が負、緑成分が正になるか
- **`true_r` アブレーションとの比較**：VE の推定が、真値を入れた場合（S2）にどれだけ近づくか
- `Q̂²→A-2位置` > `Q̂²→A-1位置`（v4 では逆転していた）
- 方向 cos_sim が正（v4 では −0.80 / −0.38）

### S6：観察の時間発展

**内容**：エピソード内で `r̂²` の推定精度がどう変化するかを測定。

**期待**：観察を続けるほど推定が正確になる（t=0 では情報がないので chance、t が進むと真値に近づく）。

⚠️ **Phase 3 の教訓（位置交絡）に注意**：A-2 が緑へ向かう以上、**時間が経つと位置が選好を露わにします**。「観察で推定が良くなった」が「位置が分かっただけ」でないことを示す統制が必要です。

**必須の統制**：A-2 の位置のみを入力とするベースライン推定器を組み、`r̂²` がそれを上回るかを見る。上回らなければ位置の読み取りにすぎません（`v4_experiment_log` の Phase 3 撤回の節を参照）。

## 4. v4/v5 から引き継ぐ運用上の教訓

**以下はすべて v4/v5 で高い代償を払って学んだことです。必ず守ってください。**

### 4.1 エポック数は400以上、学習曲線を全記録

Q値入力は運動入力より収束が遅く、**「長い停滞 → 急激な相転移」型**のパターンを示します。

| | 収束 |
|---|---|
| 運動入力（元論文） | ep 50〜80 で滑らかに収束 |
| 価値入力（v4） | **ep 170〜290 で相転移**。200ep では 0/3 収束 |

**200ep では判定できません。** 学習曲線を全エポック記録し、収束判定（下記）を適用してから評価すること。

### 4.2 収束判定基準（v4 で確定した基準をそのまま使う）

対象：`feature_prediction_other`（train ログ）。E=総エポック、W=最終20%（≥30ep）、B=バーンイン後（ep ≥ 0.1E）。

**収束** = 以下の両方を満たす：
1. **水準**：`mean(fp_other over W) ≤ 1.25 × min(fp_other over B)`
2. **後半の非上昇**：`|OLS slope over W| × |W| ≤ 0.10 × min(B)`

**判定は必ず `min(B)` の絶対値とセットで読むこと**（相転移シードは 6〜32、未相転移は 40〜55 で分離）。

### 4.3 評価の再現性

- 評価ループで `torch.manual_seed` / `np.random.seed` / `random.seed` を固定
- **同一チェックポイントを2回評価して bit-identical になることを確認**
- 使用シードを結果 JSON に記録
- **late-5**（最終5チェックポイントの平均 ± inter-ckpt sd）で報告。単一チェックポイントは使わない

### 4.4 データ収集

- **シード固定**（データセット名の MD5 から生成、HDF5 属性に記録）。bit-identical な再現を確認してから本収集
- **視覚は uint8 で保存**（float32 だと4倍。8.2GB → 2.1GB）
- **Q値・報酬パラメータをデータセットに焼き込まない**。critic チェックポイント + 視覚系列から都度計算する
- **A-2 の視覚も保存**（評価で真値を計算するのに必要）

### 4.5 critic 健全性チェック（必須）

SAC は critic が崩壊することがあります（全入力に対し同じ値を返す）。**critic を学習するたびに必ず確認**：

- ノイズ画像・4隅・中心・行動変化に対する Q の応答
- `action_std > 0.05` かつ `state_std > 0.05`

v4 で、崩壊した critic に気づかず進みかけた事例があります。

### 4.6 シードは最終主張で3つ

途中のゲート判定は単一シードで構いませんが、**論文に載せる数値は3シード**。収束したシードのみで mean±sd を出し、**収束率も併記**すること。

### 4.7 評価データセットの扱い

- **共通プロトコル**（全条件を同じデータで評価）＋ **in-distribution**（各モデルの訓練データ）の**二重報告**

## 8. この設計で失敗しうる点（先に想定しておく）

**正直に言えば、成功する保証はありません。** 以下は事前に想定される失敗モードです。

1. **S1 で条件付き critic が学習できない**。報酬パラメータを条件に取ると学習が不安定になる可能性
2. **S2 で `true_r` が `zero` を上回らない**。報酬レベルでも、位置を流すほうが視覚予測に有利かもしれない
3. **S3 で VE が定数を出す**。4次元では位置を符号化できないが、「常に A-1 の報酬を出す」（自己投影）に収束する可能性はある
4. **S4 で位置交絡**。Phase 3 と同じ罠

**2 が最も重要です。** ここで失敗したら、「視覚予測の損失だけでは他者の価値は推定できない」という主張が、報酬レベルでも確認されたことになります。**それ自体が v4/v5 より強い結果**なので、失敗として扱わず記録してください。
