## 1. 目的と仮説

- **v12 で分かったこと**：自分の経験から生まれた「快の高い方へ動く」見込みは、共有モジュールの中で動きとして積み上がり（G3）、他者側に A-2 の本当の快・不快を入れると経験ありのモデルだけが A-2 を好きな色の方へ動かす（G5）。しかし他者用の部品は、三つの試み（正式・b・c）のどれでも好みを表さず、位置を伝える近道を選んだ。
- **三層の分析**：層1（抜け道）は 2段目 b で、層3（位置が視覚から取れる）は 2段目 c でふさいだが、それでも表さなかった。残った層2（好みを正しく伝えても予測の改善が小さい。1段目で自分も半分ランダムに歩いて身につけた見込みが弱い傾向にとどまる）が決定的だったと考えられる。
- **v13 の目的**：層2をふさぐ。1段目で A-1 が好みに従う割合を 50% から 80% に上げ、「快の高い方へ動く」見込みを強くする。
- **仮説**：見込みが強くなれば、(1) G3 の g と G5a の傾きが v12 より大きくなり、(2) 2段目の部品にとって好みを伝える利点が大きくなるので、Q2 と A-2 の本当の快・不快の相関が正になり、T2・T5 が合格の形になる。
- **うまくいかない場合**：G3・G5 は強くなるが、2段目は v12 と同じ「位置を流す形」のまま。→「見込みの強さだけでは足りず、課題の作り（好みが他者の予測に必要な情報になること）も要る」と結論づける。
- **ジャーナルの観点**：v12 の G5 は正の結果だが弱い（1ステップ 0.1〜0.2 歩、はっきりしているのは1組）。v13 で G5 が強くなれば、主の貢献（自分の見込みが他者の予測に使われる）の根拠が強まる。

## 2. 作業場所と運用の約束（v12 と同じ）

1. **GPU0 は使わない**。使う GPU は起動前に報告する。
2. **v11・v12 のコード・データ・結果は変えない**。v13 のコードは新しいファイル（または子クラス、設定ファイル）として足す。結果は `data/result/v13/` と `data/result/v13_*`。
3. 作業場所（worktree とブランチ）を最初に報告し、v12 の結果を上書きしないことを確認する。
4. **事前登録は計算の前に**実験ログに書いてコミットする。結果を見た後に加えた確認は「事前登録外」と明記する。
5. 評価は同じチェックポイントを2回流して **bit-identical** を確かめる。
6. 図は**目視で確かめてから**報告する。
7. 記録とコミットと push は区切りごとに行う。報告にはコミットの番号を書く。
8. 判定は事前登録どおりに適用し、合格・不合格をそのまま記録する。判定上の合格でも効果が小さい、ほかの指標が支えない、組によって向きがそろわない、などの注意は判定と並べて書く。
9. 起動直後・途中・終わりの確認を報告する。
10. 報告は、何が分かったか → 根拠の数値 → 判断してほしいこと、の順で、平易な日本語で書く。
11. 前の報告を訂正するときは、ログに訂正として残す。
12. 学習と評価は、コンテナの中で切り離して（setsid・nohup など）起動し、Claude Code の接続が切れても止まらないようにする。

## 4. 段階

### 4.1 準備
- 経験なしのモデルの再利用：v11 のデータの乱数の設計（2条件で初期位置・A-2 の位置・眠りの時刻を共通のキーで揃える）が 80% 版のデータでも保てるかを確かめる。保てれば、1段目は経験あり 80% の3シードだけ（3本）を学習し、関門と2段目は v12 の経験なしと組にする。保てなければ、経験なしも含めて6本。
- データ収集：1段目の経験あり 80% 版（train 3000、test 300、v11 と同じ作り）を CPU で作る。関門 6.1 と同じ確認（赤から 5 以内にいる割合など）を出し、v11 の 50% 版（約 33%）と並べる。
- 事前登録：v12 の1段目の事前登録（ログ §17・§24・§26）と2段目の事前登録（§28）を土台に、v13 の事前登録を書く。判定は v12 と同じ基準。§1 の「仮説」と「うまくいかない場合」を入れる。§5 の一から学習版の扱いも入れる。

### 4.2 1段目の本番

- 判定：5点中3点以上で信頼区間が 0 を含まなければその組は「満たす」、3組中2組以上で合格。

## 5. 一から学習版（E1・E2 の結果しだい）

- **訂正（2026-10-23、v12 ログ §53 の草野さんの判断 1 による）**：E1・E2 の mse 段 ep100 の値を見て、「E2 の結果に関わらず、v12 の作りの一から学習版（v13 の一から学習版を含む）は回さない」と決めた。この節の「判断の基準」「回すもの」「時間」は、**v12 ログ §53 の決定により回さない**（元の記述は残す）。v13 の結果は凍結版だけで報告する。
- **判断の基準**：E2（v12 の作りを Encoder も含めて一から、本番の規模）の自他の揃いが 0.7 以上に育ち、かつ G2・G3 が凍結版と同じ形で出ていれば、一から学習版を回す。
- **回すもの**：v13 の一から学習版（80%、Encoder も学習）を優先。経験あり 1〜2シードと、対になる経験なし（E1 が経験なしの運動だけなので、v12 の作りの経験なしを1本足す）。3組は要らず、「凍結と同じ結果が出るか」の確認として1〜2組。
- **扱い（事前登録に書く）**：凍結版を主の結果とし、一から学習版は補足として報告する。一から学習版が凍結版と同じ形なら「Encoder の凍結は結果に影響しない」と言え、最大の限界が消える。違う形なら、違いを記述し、凍結版を主のままとする。
- **時間**：1段目 約18時間、2段目 約8時間。E1・E2 の結果（10/23 夕方）の後に起動すれば 10/26〜27 に結果。
