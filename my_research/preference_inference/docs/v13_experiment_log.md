## 1. 経験なしのモデルを再利用できるか（2026-10-22 20:00〜20:20。学習の本番の前）

**結論：再利用できる。1 段目は経験あり 80% の 3 シード（3 本）だけを学習し、関門と 2 段目は v12 の経験なし（`v12_s1_random_*`）と組にする。**

理由は、データの側と学習の側の両方で、2 条件の違いが「経験ありのデータの中身」だけになることを確かめたため。

**A. データの側（コードの読み取り）**：`simulation/collect_data_v11.py` と `v11core/rule_agent.py` では、乱数が次のように分かれている。
- エピソード n の初めに python の `random` と numpy の乱数を md5(`v11_s1/<split>/<n>`) で設定し直す（2 条件で共通のキー）。→ A-1 の初期位置・最初の目標・A-2 の位置が決まる。
- 配置の列は別の `RandomState(md5('v11_s1/layout'))`。
- 方式の抽選（規則かランダムか）は専用の `RandomState(md5('<key>/<split>/<n>/a1_mix'))` で、起きている一歩ごとに `rand()` を 1 回引き、`< p_rule` なら規則の番。**割合 p_rule を変えても、引く回数と値は変わらない**（50% 版で規則の番だった一歩は、80% 版でも必ず規則の番になる）。
- 眠りの抽選は python の `random` だけを使い、起きている一歩のたびに 1 回。規則の一歩・方式の抽選・RandomAgent の目標（numpy）は `random` を消費しない。→ 眠りの時刻は条件・割合によらず同じになる（v11 §7.1）。
- したがって 80% 版でも、同じエピソード番号で、配置・初期位置・A-2 の位置・眠りの時刻が経験なしと一致するはず。
- 80% 版の収集は、v11 の収集の関数をそのまま読み込み、データ名と p_rule = 0.8 だけを足す薄い包み `simulation/collect_data_v13.py` で行う（キーは `v11_s1` のまま）。

**B. データの側（実データでの確認）**：確認用の先頭 3 エピソード（`data/result/v13/gate61/check_mixed80_{a,b}.h5`）で、
- 2 回の収集の全 8 配列が bit-identical。
- 配置・初期位置・A-2 の位置（全時刻）・眠りのフレーム（`a1_source` = 3）が `v11_s1_random` の先頭 3 エピソードと一致（v11 の 50% 版とも一致）。
- 50% 版で規則の番だった一歩は、80% 版でもすべて規則の番。
- 全 3300 エピソードでの確認は §2（関門 6.1 の 2 と同じ確認に「眠りのフレームが一致」を足したもの）。

**C. 学習の側**：
- 学習の乱数（初期値、バッチの順番、運動を隠す区間 `make_schedule` の `torch.randint`）は torch の乱数とシードだけで決まり、データの中身には依らない（データの大きさは同じ 3000 × 101）。

  - ep0（初期値）：44 個の重みがすべて一致。
  - **ep1：44 個の重みと最適化の状態（22 個）がすべて bit-identical**。
- したがって、v13 の経験あり s の学習は、v12 の経験なし s と同じ初期値・同じバッチの順番・同じ隠す区間で進む。v12 の経験あり s とも同じ（データだけが違う）なので、§3.4 の v12 との比較も同じシードで対にできる。

- **作りからの予想（2026-10-24 草野さんの指示で追記）**：NS では process-2 の快・不快の入口の重みが 1 段目で一度も学習されないので、**NS で G5 が出ないことは作りからほぼ予想どおり**になる。したがってこの対照は、重ね合わせの仮説を新たに試す実験というより、**「他者側へ届く道が共有モジュール以外にないこと（統合部・Decoder など別の道から G5 の効果が生まれていないこと）の確認」**として位置づける（論文での位置づけ）。

  1. **パラメータが増える（＋39%）**：自分側の予測が良くなる／変わる可能性。→ 自分側の指標（下の 19.3 B）が v13 と同程度であることを確かめる。G5 の量は process-2 の入力への反応なので、容量の差は直接は効かない。

  4. **経験なしの NS も新たに学習する必要がある**（v12 の経験なしは共有のモデルなので組にできない）：経験あり・なし × 3 シード ＝ 6 本。
  5. 同じシードでも、モデルの作りが違うので、初期値・乱数の流れは v13 と一致しない（共有モジュールの初期化の後に別の LSTM の初期化が入る）。v13 と NS の比較は同じシードでの対ではなく、組の数え方で並べる。**（§21 で訂正：実装では process-2 の LSTM を写しで作るので乱数を使わず、同じシードの v12・v13 と初期値・乱数の流れが一致する。v13 と NS は同じシード・同じエピソードで対にして比べられる。）**
