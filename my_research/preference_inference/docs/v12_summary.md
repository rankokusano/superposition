## 1. 問いと設計（要約）
- **問い**：自分が好みに従って動いた経験があると、他者の動きの傾向から他者の好み（価値）が分かるようになるか。
- **v11 から変えたこと**：
  - process-1 の入力を「運動（元論文と同じ 2 次元）＋ 方向ごとの快・不快（8 次元）＋ 隠れの印（1 次元）」にした。
  - 運動は 5〜15 ステップの区間で交互に隠す（隠れる割合 約 48%）。**運動が隠れた区間では、快・不快を区間の最初の一歩の値に保つ**（快・不快の変わり方から自分の動きが読めてしまう抜け道をふさぐ）。

  - 2 段目の process-2 は「運動 0・印あり・快・不快の枠に部品 G の出力 Q2」。process-1 は 2 段目では運動を隠さない。
- **設計の経緯**（試し学習、ログ §4〜§16）：一から学習すると自他の書き方の揃いが戻らない（v12 本体 0.18〜0.27、元論文と同じ作りでも v11 のデータでは 0.48、v4 0.80）→ Encoder を凍結（P-b）。快・不快を止めないと積み上がりが出ない（P-b）→ 快・不快を止める（P-c）。

## 8. 三層の分析と v12 の結論（推測を含む。ログ §40・§46 A、草野さんの整理 2026-10-22）
- **事実**：T3 で、生成した Q2 は A-2 の本当の快・不快（D6）より予測をずっと良くする（正式・b とも。他者側の特徴予測の誤差：零 約 0.30、D6 0.25〜0.28、生成 0.13〜0.18）。この課題では、A-2 の好みを正しく伝えることが A-2 の予測にとって最善の手ではない。
- **三つの層**：
  - **層 1（抜け道）**：部品の出力に、1 段目では使われない自由な枠（範囲 2〜5 など）があり、別の情報の通り道になる。→ **2 段目 b でふさいだ**。
  - **層 2（好みを伝えても改善が小さい）**：共有モジュールの「快の高い方へ動く」見込みは弱い傾向にとどまる（G5a の動きは 1 ステップあたり 0.1〜0.2 歩）。A-2 も半分ランダムに歩くので、好みを正しく伝えても予測の改善は小さい（D6 を入れても誤差は 0.30 → 0.26〜0.28）。→ ふさいでいない。
  - **層 3（位置が視覚から取れる）**：A-2 の位置は視覚から取れ、好みより予測に役立つ。→ **2 段目 c でふさいだ**（A-2 を隠す）。
- **結論（推測）**：層 1 は b で、層 3 は c でふさいだが、どちらでも部品は好みを表さなかった。したがって、**層 2（好みを正しく伝えても予測の改善が小さい。共有モジュールの見込みが弱い傾向にとどまる）が決定的だった**と考えられる。部品が好みを表さないのは、予測を良くするという目的に対して合理的な選択だった、と読める。
- **元論文との対比（考察、推測。草野さんの整理 2026-10-22）**：元論文で部品（Motion Generator）が他者の運動を正しく生成できたのは、部品が書ける枠が運動の枠だけで、共有モジュールがそれを運動としてしか読まないため、「位置を直接伝える近道」が存在せず、運動を推し量ることが予測を良くする唯一の道だったからだと考えられる。本研究では、部品が伝えるべき情報（好み）が予測に効く情報（位置）を弱くしか決めず、かつ位置を直接書ける枠（自分側で使われない範囲 2〜5）があったため、**近道と本道が別れ、近道の方が得だった**。2 段目 b は枠を、2 段目 c は視覚からの位置をふさぐ試みだったが、残った「好みが位置を弱くしか決めない」こと（層 2）が決定的だった。
- 1 段目の結果（価値と行動・色の結びつき、自分側・他者側の積み上がり）はすべて合格しており、「自分の経験から『快の高い方へ動く』見込みがネットワークの中にでき、それを process-2 経由で他者に当てはめられる」ところまでは言える。言えないのは、「部品が他者の動きを見て、その好みを快・不快の形で推し量る」ところである。

## 10. 主張できること・できないこと

**主張できること**
1. 自分が好み（赤）に従って動いた経験があると、予測学習するネットワークの中に、快・不快と行動・色の結びつきができる（M1(c)・M1(d)・色の基準、運動が隠れた一歩で 3/3 組。v11 と同じ）。
2. 運動を隠し快・不快を保つと、経験ありのネットワークは予測を「赤の方へだけ」進め続ける（入力停止の積み上がり、3/3 組）。経験なしは 4 色の方へ同じように進む。
3. process-2 に A-2 の本当の快・不快を入れると、経験ありのネットワークは予測の中の A-2 を A-2 の好きな色の方へ動かす（G5a 3/3 組、G5b 2/3 組。強さは組でそろわず、s1・s2 は弱い）。自分の経験からできた見込みを、他者側に当てはめる仕組みが共有モジュールにある。
4. 他者の動きを見て好みを快・不快の形で推し量る部品（G）を学習させても、正式・b・c の三つの試みのどれでも、好みを表す形は出なかった。部品は、予測に役立つ別の情報（範囲 2〜5、範囲ごとの強さ）を流した。
5. 他者側の内部状態（h²）と Q2 には A-2 の好みの情報があるが、経験の有無で差がなく、観察だけで得られるものと考えられる（事後の分析）。

**主張できないこと**
1. 「自分の経験から他者の好みが分かるようになった」とは言えない（2 段目の主はすべて不合格）。
2. 「自他を同じ形で表す性質が価値の経験から生まれた」とは言えない（v12 では Encoder を凍結して与えた）。
3. 層 2 が決定的だったこと（§8）は推測で、見込みの強さを操作して確かめてはいない。
4. 2 段目 c の T2 の逆向きを「自分の好みの押しつけ」と読むことは、事後の分析で支持されなかった（3 組、CI が広い）。

## 11. 限界の一覧
1. **自他を同じ書き方で表す性質は、v12 では学んだものではなく与えたもの**（Encoder を v4 の重みで凍結）。言えるのは「自他を同じ形で表す土台がある上で、価値の経験が他者の好みの理解を生むか」まで（v10 の B3-frozen と同じ限界）。Fig.5 で取り出した A-2 の視点の画像は、凍結した Encoder と共通の Fig.5 の Decoder を使うので、v12 の全モデルで同じ画像になる（予測画像の目視、2026-10-22）。v12 の Fig.5 が成り立つのは学習の結果ではなく、凍結による。
2. G5 は組によって強さがそろわず、s1・s2 は合格の点でも CI の下限が 0 に近い（§2 の注意 1）。副の B1 の読み取りでは s0 だけが合格の形。
3. 2 段目 b・c と案 A は、正式の結果を見たあとの設計で、探索として扱った（c は新しい仮説の事前登録だが、正式の主ではない）。
4. A-2 の行動は「50% は好きな色の方へ、残りはランダム」の規則で、好みを知ることの利点が小さい課題である（層 2 の一因）。結論はこの課題の作りに依存する。
5. 予測画像から A-2 の位置を読む読み取り（G5a・B3・§51）は、読めないフレームがあり（主の読み取りで 0.78〜0.98）、読み取り方で値が変わる（B1 の読み取りとの差）。
6. 組の数は 3〜4 で、組の間のばらつきが大きい（主の見分けの向きが組でそろわないことが多い）。
7. 三層の分析と、層 2 が決定的という結論は推測で、見込みの強さや好みの必要性を操作した検証はしていない。

## 13. 今後の課題（草野さんの整理 2026-10-22）
1. **見込みを強くする条件**：（手がかり）2 段目 c の組 s1 の経験ありにだけ、好みの方向へのわずかな形があった（②のセットの隠れているフレームで、符号の一致 0.66、Q2 と P_A2 の相関 +0.14〜+0.18、② T5 は隠した test で 5/5。ただし値は D6 の 1/10 ほどで、ほかの組にはない。**判定には影響しない記述**、ログ §52）。見込みを強くすれば、この形が育つ可能性がある。共有モジュールの「快の高い方へ動く」見込みが弱い傾向にとどまったことが決定的だったと考えられる（§8）。1 段目で自分がより強く好みに従う（規則で動く割合を上げる、好みの強さを変える）など、見込みを強くしたときに 2 段目で部品が好みを表すかを見る。
2. **好みが他者の予測に必要な情報になる課題**：A-2 の行動が好みでほぼ決まる（ランダムの割合が小さい）、好みが時間とともに変わる、A-2 が長く見えない、など、好みを知らないと予測できない課題の作り。2 段目 c（A-2 を隠す）は層 3 をふさいだが、層 2 が残っていたので、両方を同時に満たす課題が必要。
3. 自他を同じ形で表す性質も、価値の経験と一緒に学べる条件（v11・v12 の Fig.5 の分析：運動以外の入力で Encoder を学習すると揃いが崩れる）。
   - **E1・E2（考察のための確認、ログ §53、事前登録外）**：自他の揃いが、入れ替えのある環境でも本番の規模の一から学習で生まれるかを確かめる。E1 は元論文と同じ作り（運動だけ）を v11 のデータで、E2 は v12 の作りを Encoder も含めて一から、どちらも本番の規模（3000 エピソード、mse 段 200 → l1 段 200 エポック）で学習する。試し学習（150 エポック、1000 エピソード）では (P-a) 0.48、v12 本体 0.18〜0.27 で、v4 の 0.80 に届いていない。結果はログ §53 に追記する（2026-10-22 起動）。
4. **案 2：快・不快の表し方を、全部の枠が使われる形にする**（v7 ログ §7.4 の「ランドマークをアリーナの内側に置く案」、v12 の設計の議論 ログ §34）。今の環境ではランドマークがアリーナの角にあり、赤・緑は範囲 0・1・6・7 にしか写らないので、快・不快の範囲 2〜5 は 1 段目で常に 0 になる。この使われない枠が、2 段目で部品が位置などの別の情報を流す通り道になった（層 1、§8）。ランドマークを内側に置けば、目標の向きが場所で変わり、8 つの範囲すべてが快・不快の値をとる。部品の出力を限る（2 段目 b）のではなく、自分側でも全部の枠が使われる形にして、枠の抜け道そのものをなくす。環境が変わるので、Encoder・Decoder を含めて 1 段目から学習し直す必要がある。
