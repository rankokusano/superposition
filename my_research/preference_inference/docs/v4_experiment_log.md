## 1. 研究の目的（不変）

### 1.1 何を問うているか

他者の価値（欲求・選好）の理解が、**いかなる前提から最小限に創発しうるか**を構成論的に示す。

自己の一人称視覚を予測するという単一の学習目的のみを与えられたネットワークが、副産物として他者の行動価値に対応する内部表現を形成しうるかを検証する。

**目指さないもの**：他者の報酬を高精度に推定するアルゴリズム（それは逆強化学習が既に解いている）。問うのは、**IRL が前提として要求するもの——他者を価値主体とみなす枠組みそれ自体——がどう獲得されうるか**である。

### 1.2 元論文との関係

Noguchi, Iizuka, Yamamoto & Taguchi (2022) *Scientific Reports* 12:2859

元論文は、A-1 の視覚と**運動指令** `m_t` から次の視覚を予測する学習だけで、A-2 の位置・視点・運動を表現する内部状態が創発することを示した。鍵は process-1 と process-2 が**同一の Shared Module（LSTM）を共有**する点。

**本研究はこの入力を行動価値 `Q(s,·)` に置き換える。**

| | 元論文 | v4 |
|---|---|---|
| process-2 の入力が必要な理由 | A-2 の**運動**が観測できない | A-2 の**価値**が観測できない |
| それを埋めるモジュール | Motion Generator (MG) | **Value Estimator (VE)** |
| process-1 の入力 | 実際の `m_t` | 実際の `Q¹(s,·)` |
| process-2 の入力 | 生成した `m̂²` | 生成した `Q̂²` |

**VE は MG の一対一の置き換え。** 構造は元論文と同一のまま、扱う量が運動から価値に変わる。

### 1.3 なぜ Q値なのか

- **運動指令** = 「何をしたか」。外から観察可能
- **Q値** = 「何にどれだけ価値を感じているか」。**観察不可能**で、しかも**選ばれなかった行動の価値**（反実仮想）を含む

他者の Q値を表現するとは、「その他者が**実行しなかったが実行しえた選択肢**をどれだけ望んでいたか」を表現すること。ミラーニューロン理論への既知の批判（Hickok 2009：観察された運動の共鳴では目標・意図の帰属を説明できない）に対する、構成論的な回答になる。

元論文自身が Limitation として「他者の信念や意図といった内面の推論は獲得されなかった」と明記しており、本研究はそこに直接取り組む。

## 4. 確定した設計判断と、その理由

### 4.1 MG は R3 以降のアーキテクチャから削除する

**根拠**：元論文の `SuperpositionNetworkMotionGeneration.forward()`（root `model/model.py:120-141`）は

```python
om = self.motion_generator_module(ov_enc)
ss, os = self.superposition_module(sv_enc, sm, ov_enc, om)  # om が process-2 の入力
```

MG は **process-2 のモーション入力を供給するためのモジュール**であり、評価用デコーダではない。したがって VE はその一対一の置き換えであり、**両方を持つ理由がない**。

**v3 の誤り**：`ov_enc → MG → VE → SM` という直列構成にしていた。MG は SM に接続されず直接の損失も持たないため、**運動を予測するよう訓練されたことが一度もなかった**（R² = -576000 の真因）。この直列は v3 独自の変更で、元論文由来ではない。

**各ゲートでの構成**

| 段 | process-2 の入力 | MG | VE |
|---|---|---|---|
| R2 | MG 出力 `m̂²` | あり（元論文構成） | なし |
| R3 | 正規化後の零ベクトル | **なし** | なし |
| R4 | **`Q̂²`（VE 出力）** | **なし** | あり |

運動の診断は、**凍結した h² から A-2 の真の運動を予測する事後プローブ**として外部化する。

### 4.2 プローブQベクトル

**仕様**：
- K=8、単位円上に等間隔 `(cos(2πk/8), sin(2πk/8))`
- 静止 (0,0) プローブは追加しない
- 正規化：**tanh((Q-μ)/σ)**、μ・σ は **A-1 の実データのみ**から算出
- process-1 / process-2 で**同一の正規化統計**を使用

**なぜスカラーではなくベクトルか**：スカラー Q には方向成分がなく、LSTM が経路積分できない。元論文の内部表現は経路積分の産物なので、その根拠が失われる。K方向の値があれば argmax/重心で方向が復元できる。

**プローブが同時に解決する問題**：

| 問題 | 解決理由 |
|---|---|
| サンプリングノイズ（変動係数23%） | プローブは固定なので Q値が状態の決定論的関数になる |
| 分布シフト（ランダム行動 vs 方策行動） | どの方策で動いても `Q(s, a_probe)` は同じ |

**「A-1 の経験のみから導出する共通統計」という定式化が重要**。A-1 が知り得る情報だけで正規化するので、superposition の主張（自己の機構で他者を解釈する）が守られる。

**tanh を選んだ理由**（実測にもとづく）：

| | A-1 std | A-2 std |
|---|---|---|
| tanh | **0.629** | 0.0090 |
| 線形クリップ `(Q-μ)/(3σ)` | 0.333 | 0.0581 |

線形クリップは A-2 の分散を6倍改善するが、**A-1 の分散を半分に落とす**。R3 で使うのは process-1 のみ（process-2 は零ベクトル）なので、A-1 の分散を最大化すべき。また元論文の `m_t` が (-1,1) をフルに使っていたことと値域が一致する。

**A-2 の潰れは正規化では解決しない問題**（A-2 の Q値レンジ幅1.76 が A-1 の5.54 の1/3しかない）。R4 で正面から扱う。

### 4.3 静止の意味論

正規化後の**零ベクトル**（全方向の Q値が等しい＝方向的選好なし）を静止の表現とする。

元論文の「速度ゼロ＝動いていない」と意味が一貫し、base 学習から R4 への移行で意味論が断裂しない。**v3 はここで「価値ゼロ」という別の意味を入れてしまっていた。**

### 4.4 報酬を連続値にした理由

**カバレッジのためではない**（密報酬はむしろ点アトラクタを作る）。理由は**Q値の空間的情報量**。

しきい値報酬（緑>50px で +1.0）だと、A-2 が実際にいる場所で **Q値が平坦**になる。実測：

```
x=-9固定、yを振る：
y=-9: green= 96   y=-1: green= 52  ← green>50 の平坦な満足領域
y=-7: green=121   y= 1: green= 35  ← ここで red>50 に転換
```

`x=-9, y∈[-9,-1]` が「green>50 かつ red<50」を満たす平坦領域で、この中のどこにいても報酬が同一。角へ向かう勾配がない。

**R4 の評価は「Q̂² と A-2 の真 Q値の相関」なので、推定対象が定数では実験が成立しない。**

### 4.5 確率的行動を採用する理由

決定論化（`tanh(mean)`）を一度指示したが**撤回した**。

当初の理由は「Q¹ のサンプリングノイズを消すため」だったが、**プローブQベクトルの採用でこの理由は消滅**（`Q(s,a_probe)` は方策の確率性と無関係）。再現性もシード固定で担保済み。

そして実測が決定論化の害を示した：

| | A-2 std |
|---|---|
| v3（確率的、0.15x） | 4.95 / 5.08 |
| 決定論的、1.0x | **2.33 / 1.65** |

**確率性はカバレッジに貢献していた。** 教授のメモにも「確率εで探索、1-εで行動価値が高い方に行く」とあり、これが当初の想定だった。現行 ε=0.1。

### 4.6 データセットに Q値を焼き込まない

保存するのは `self_vision`, `other_vision`, 位置、運動、シード。**Q値は critic チェックポイント + 視覚系列から都度計算する。**

v3 は `a1_q_values` を HDF5 に焼き込んでいたため、正規化もプローブ化も試せず作り直しになった。critic の forward pass は環境シミュレーション + レンダリングに比べて桁違いに安い。

### 4.7 視覚データは uint8 で保存

元画像は 0〜255 の整数で、モデル入力直前に `scale_vision(v) = v*2-1` で正規化される。**保存時点で uint8 なら情報は一切失われない。**

float32 → uint8 で **8.21GB → 2.06GB**（1/4）。v3 から引き継がれていた無駄で、「v3 と同一だから異常なし」という判断では見つからなかった。

### 4.8 SM の部分転移

`sm` の次元が 2（運動）→ 8（プローブQ）に変わるため `weight_ih` の形が合わないが、**全部を捨てる必要はない**：

- `weight_ih_l0` の**最初の64列（視覚入力の重み）は次元不変でコピー可能**
- 新しい8列（Q値入力）のみランダム初期化
- **`weight_hh`（再帰重み）と `bias` は次元不変で全部コピー可能**

LSTM のパラメータの大半は `weight_hh` と視覚側 `weight_ih` なので、部分転移でほぼ全ての学習内容を引き継げる。

**注意**：この実装時に「66列コピー（旧行動用2列を Q値用に誤流用）」というバグが混入した。1エポックも完了しないうちに発見・修正済みで、完了済みの結果には影響していない。

## 5. 実験結果の変遷

### 5.1 4軸 R²（位置回帰、Ridge）

| 実験 | h¹→self | h¹→other | h²→self | h²→other |
|---|---|---|---|---|
| **exp1_l1**（元論文再現） | 0.9772 | 0.0373 | 0.0774 | 0.9725 |
| **exp3**（MG付き、Cycler） | 0.9635 | 0.0129 | 0.0716 | 0.7122 |
| v3（Q値スカラー＋RL A-2、崩壊） | 0.9339 | 0.4283 | **0.8812** ❌ | 0.6799 |
| R2（A-2 をRL化、MG付き） | 0.9658 | 0.4929 | 0.3421 | 0.8811 |

| R3-A-cycler（統制） | 0.8219 | **0.9062** ⚠️ | 0.0713 | 0.9538 |

### 5.2 R2 の評価：条件付き通過

**当初のゲート基準 `h²→self < 0.15` は未達（0.3421）。しかし基準自体を見直した。**

理由：R2 の失敗原因が **MG の学習失敗**と特定され、**MG は R3 以降存在しない**ため。exp3 の 0.0716 を再現することに意味がない（exp3 の土俵には MG があり、v4 の最終形にはない）。

R2 の当初の目的（v3 の逆転が Q値化のせいか A-2 方策のせいかの切り分け）は達成された。

### 5.3 R3-A の評価：通過

`h¹→self = 0.9086 > 0.90` で通過。**教授のステップ1「Q値で予測画像が出るようにする」に相当。**

`h²→self = 0.0910` が exp1_l1 水準（0.0774）まで改善したのも重要で、**R2 の漏れが MG 由来だった**ことの裏づけ。

**部分転移の効果はなかった**：0.9086 vs 0.9095（転移なし版）、0.5849 vs 0.5820。差は誤差範囲。
→ **SM は exp1_l1 の学習内容をほとんど使っていない**。入力が `m_t` から Q値に変わった時点で、事実上ゼロから学習し直しているに近い。

**残る懸念**：`h¹→other = 0.5849`。元論文水準（0.01〜0.04）の15倍以上。process-1 に他者情報が漏れている。
→ R5（自己投影バイアス）を測る際、process-1 に他者情報が混入していると投影を測る土台が弱くなる。**R4/R5 の解釈時に留意すること。**

### 5.4 R3-A-cycler 統制実験：RL方策仮説を棄却

**仮説**：`h¹→other` の上昇は A-2 が RL 方策で動いている（A-1 の視覚に反応する）ためではないか。Cycler なら A-1 と独立なので改善するはず。

**結果は真逆**：`h¹→other` が 0.5849 → **0.9062** に上昇。

さらに Cycler 条件では**自他分離そのものが崩れている**：

```
h¹→self  0.8219  <  h¹→other  0.9062   ← h¹ が自分より他者を良く表現
```

**解釈**：Cycler は決定論的スクリプトで軌道が完全に予測可能なため、視覚予測タスクとして A-2 の位置は極めて有用な情報になる。両プロセスがこぞってそれを符号化する。

exp3 でこれが起きなかったのは、process-1 の入力が実際の運動 `m_t` だったため。`m_t` は A-1 自身の変位そのものなので LSTM は経路積分に使うしかなく、h¹ は A-1 の位置を保持する以外に選択肢がなかった。

**Cycler は統制実験として役目を終えた。以後使用しない。**

### 5.5 R3'（Probe-Q アブレーション）：通過

**問い**：h¹ は Q値を「価値の方向構造」として使っているのか、単なる「状態の識別子」として使っているだけか。

推論時のみの操作（追加学習なし）：

| 条件 | h¹→self | 低下幅 |
|---|---|---|
| baseline | 0.9092 | — |
| rotate90（2つ循環シフト） | 0.6721 | -26.1% |
| shuffle（固定ランダム置換、大きさ保存） | 0.6382 | -29.8% |
| **critic_swap（A-2 の critic に差替え）** | **0.5927** | **-34.8%** |
| constant（各時刻の平均値に置換） | 0.5877 | -35.4% |

h²系列（0.0902 / 0.8994）は全条件で完全に不変 → 操作が process-1 側に正しく限定されていることの確認。

**critic_swap が決定的**：同じ8方向・同じ軌跡・同じ正規化定数のまま、**価値関数の中身だけ**を変えて -34.8%。入力の並びも次元も変えていないので、置換感度では説明できない。

→ **h¹ は Q を「Q値っぽい形をした何か」ではなく、A-1 自身の価値構造に依存して使っている。** 位置コード疑惑は晴れた。

### 5.6 経路積分については未確定

**実装上の発見**：`p_mask_vision_self` は `sv_enc`（エンコード後の視覚特徴）のみをマスクし、`q1_vec` はマスク前の生の `sv` から毎回計算される（`model.py` L356-364）。exp1_l1 の `m_t` も常時マスクなしで供給される設計と対称であり、バグではない。

**結果として「視覚を完全に遮断して Q のみにする」実験は R3-A に対しては原理的に実現できない**（Q が毎ステップ生の現在フレームを見ているため）。

参考値（`p_mask_vision_self=1.0`）：

| | h¹→self |
|---|---|
| r3_a_direct（Q駆動） | 0.8342 |
| exp1_l1（`m_t` 駆動） | 0.5463 |

これは「maskable な sv_enc パスへの依存度」の比較として読める。

**直接検証**（LSTM 再帰を使わず、各時刻の Q ベクトル単体から位置を Ridge 回帰）：

| | R² |
|---|---|
| Q単体（単一時刻、再帰なし） → 位置 | **0.5989** |
| h¹（LSTM 再帰後） → 位置 | 0.9086 |

**単一時刻の Q だけで 0.60 読める。** 報酬源が赤と緑の2つあるため、2つの距離から位置がかなり絞れる（「Q値が距離センサとして機能する」問題は実在した）。

一方 +0.31 の上乗せがあり、**再帰処理が実質的な役割を果たしている**。ただしそれが真の変位積分か時間的平滑化かは未確定。

**この点は無理に決着させない。** Q値入力では単一時刻でも位置情報が 0.60 得られ、再帰統合で 0.91 に達する——事実として記述すれば足りる。元論文とは経路積分の必要性が構造的に異なるため、同じ土俵での比較自体が適切でない可能性がある。

## 7. 未解決の懸念

### 7.1 `h¹→other` の漏れ（未解決のまま R4 へ）

R3-A で 0.5849。元論文水準（0.01〜0.04）の15倍以上。

**原因は特定できていない。** 棄却された候補：
- A-2 が RL 方策だから → Cycler でむしろ悪化（§5.4）
- MG が悪さをしている → MG 除去後も残存
- 部分転移が効いていない → 転移してもしなくても同じ（§5.3）

**残る有力な解釈**：Q値入力には、h¹ に自己位置の保持を強制する力が `m_t` ほど強くない。`m_t` は変位そのものなので経路積分に使うしかないが、Q値は状態の関数なので h¹ が自己位置を保持しなくても予測が成立する。結果として h¹ の容量に余裕が生まれ、予測に有用な他者情報も取り込む。

**R5 への影響**：「Q̂² が A-1 自身の選好に引かれるか」を測る際、process-1 に他者情報が混入していると投影バイアスの解釈が弱くなる。R5 の結果を見る際に留意すること。

### 7.2 MG と価値駆動方策の原理的緊張

RL エージェントは報酬を最大化するので、目標へ向かい続けるのが正しい振る舞い。実測：

```
A-1 (RandomAgent):  std_x 0.677  std_y 0.678
A-2 (RL, R2):       std_x 0.254  std_y 0.0154  ← 参照値の1/44
exp3 A-2 (Cycler):  std_x 0.690  std_y 0.690
```

**MG が学習するには運動が全方向に散る必要があるが、価値に従う方策は運動が単調になる。** 元論文が Cycler という人工的な決定論方策を使っていたのは偶然ではなく、MG が学習可能であるために必要だった。

**これは論文に書ける知見**：価値ベースに置き換えると MG の前提が崩れる ＝ v4 が VE を採用する積極的な理由。

### 7.3 A-1 と A-2 の Q値域の乖離

```
A-1 seed0: [0.075, 4.032]  分散 0.842
A-2 seed0: [3.118, 4.380]  分散 0.082
```

幅が3倍、中心も重ならない。tanh 正規化下で A-2 の分散は 5.5% まで縮小する。**R3 では process-2 が零ベクトルなので影響しないが、R4 で VE が学習可能かは要検証。**

不可の場合の対処案：
- A-2 の critic 再学習（報酬スケールを上げれば Q レンジは広がる）
- A-2 の報酬設計の見直し
- **VE の入力を `ov_enc` ではなく `h²` にする**（h² には A-2 位置情報が R²=0.90 で存在する。元論文の MG が `ov_enc` 入力だったのは MG の設計上の都合で、VE も同じにする必然性はない）

### 7.4 A-1 の緑嫌悪が R5 を妨げる可能性

A-1 は緑に −1.0 のペナルティを持つため、共有モジュールが「緑＝悪い」を強く学習する。**R5 で「VE が緑を正の価値として出す」ことが構造的に困難な可能性がある。**

R5 で分化が観測されなかった場合、これが交絡要因になりうる。

### 7.5 到達度の非対称（未解明）

環境は完全対称であるにもかかわらず：

```
A-1: Red 内1.5 に 65.5%
A-2: Green 内1.5 に 1.8%
```

実測では緑ピクセルのピークが y=-7（121px）で角の y=-9（96px）より高く、**視覚的ピークと実座標がずれている**。A-2 が帯状に留まるのはこれで説明できるが、赤側でも同じずれがあるはずなのに A-1 は角に到達しており、噛み合わない。

### 7.6 critic 崩壊のリスク

SAC の既知の失敗モード。実測で A-1 は 2/3、A-2 は 1/3 が健全だった。

**critic を再学習するたびに健全性チェックを必須とする**：ノイズ画像・4隅・行動変化に対する Q の応答を見て、`action_std > 0.05` かつ `corner_std > 0.05` を満たすこと。

一度、崩壊した critic（全入力に対し Q≈1.65 の定数出力）に気づかず進みかけた。プローブQベクトルが全部同じ値なら SM への入力が定数になり、**何を学習しても意味のない実験**になっていた。

### 7.7 データ収集クラッシュ（原因未特定）

空き42GB に対し理論値8.21GB の収集がディスク不足でクラッシュした。RAM は無罪（RSS フラット）、コードにも異常なし。消去法で「他プロセスによる圧迫」としたが直接証拠はない。**uint8 化で必要量が2.06GB に下がったため実害は消えたが、原因は未特定。**

### 7.8 A-2 の Q値分散不足（診断の因果誤り→再訂正、学習に直接影響していた）

**発覚**：2026-08-20、R4 着手前の§8.2項目2の確認作業（v4_experiment_log.md §8.2 参照）。
**訂正1（2026-08-21）**：停止判断を撤回し実験再開。A-2 の真 Q 値はネットワークへの入力に一切使われず（学習信号は視覚予測誤差のみ、A-2 の真 Q 値は評価時の事後相関チェックにのみ登場）、「真 Q 値の分散が小さいから VE が学習しない」という因果は成立していなかった。VE の学習可否を決めるのは Q̂² が視覚予測に寄与するかどうかであり、A-2 の真 Q 値の統計的性質ではない、と判断した。
**訂正2（2026-08-21、R4評価後）**：**「分散不足は評価の感度の問題であり学習には影響しない」という訂正1の結論も誤りだった。** R4を実際に実装・学習・評価した結果、Q̂²をA-2の真Q値（std=0.0092）に置き換えて推論すると視覚予測損失が real（0.1435）より悪化し、何も入れない zero（0.1480）すら上回った（true_q2=0.1492、§5.7・§7.9項目4）。これは分散不足が**学習結果に直接影響していた**ことの直接証拠——VEはSMの凍結重みが受け入れやすいA-1寄りの値域に最適化され、A-2の真の値域を出力すると損をする構造だった。**正しい結論は「分散問題はR4の成立を直接妨げる」。** 訂正1は「真Q値が学習ループへの入力として使われない」という設計上の事実としては正しいが、そこから「だから分散は問題にならない」と結論したのが誤りだった——分散不足は直接の入力としてではなく、SMとの分布整合性を通じて間接的に、しかし決定的に学習結果を左右していた。
以下の分析（3手段の失敗理由、報酬増幅率48倍 vs 4倍の発見）自体は有効な知見として残る。詳細は `docs/r4_a2_q_variance_blocker_report.md` 冒頭の追記、およびR4の全結果は§5.7・根本原因の特定は§7.9を参照。

**根本原因の再診断（重要）**：当初「A-2 の報酬変動幅が小さい（緑ピクセル96〜121px/1024）ことが原因」と想定していたが、実測で**否定された**。A-1/A-2 それぞれの実際の訪問状態での報酬 std を測定した結果：

| | 報酬 std | Q std | Q/報酬増幅率 |
|---|---|---|---|
| A-1 | 0.0196 | 0.9482 | 48.3倍 |
| A-2 | **0.0430**（A-1の219%） | 0.1721 | **4.0倍** |

A-2 の瞬間報酬の変動幅は A-1 より大きい。にもかかわらず Q 値の変動幅は A-1 の 1/5.5 しかない。**「報酬が平坦だから Q が平坦」という説明は誤り。**

**増幅率の説明（訂正、2026-08-21）**：当初「価値最大化方策（A-2）は自己修正収束するため長い割引地平線が均され、ランダム方策（A-1）にはその収束がないため増幅率が大きい」と記録したが、**この説明は不正確だった**。SAC の学習中は A-1 も A-2 も自分自身の方策（価値最大化方策）で行動しており、ランダム歩行（RandomAgent）はデータ収集段階でのみ使われる。「方策の違いが増幅率を生む」という当初の因果は成立しない。

**より正確な説明の候補（未検証の仮説）**：A-1 の std=0.9482 は「価値最大化方策で学習した A-1 の critic に、ランダム歩行（RandomAgent）データ上の状態を入力して計算した値」であり、**訓練分布（A-1自身の価値最大化方策の訪問分布）と評価分布（RandomAgentの訪問分布）がずれている**。一方 A-2 は自分自身の方策で動いたデータ（`collect_data_r2.py`の`a2_actor.sample()`）上で評価しており、訓練分布と評価分布が一致している。ランダム歩行はアリーナ全域を回るため critic にとって訓練時にあまり訪れなかった領域を多く含み、Q値が（分布外入力に対する不安定な外挿として）ばらつきやすい可能性がある。増幅率の差は方策の違いではなく、評価分布が訓練分布と一致しているか否かの違いによる可能性がある。

**検証方法（記録のみ、今すぐ実施しない）**：A-1 の critic に、A-1 自身の価値最大化方策で動いたデータ上の状態（RandomAgentではなくA-1自身のactor.sample()によるロールアウト）を入力してQ値を計算し、その std を測る。これが 0.9482 より小さければ、上記の分布ミスマッチ仮説が支持される。

**詳細レポート**：`docs/r4_a2_q_variance_blocker_report.md`（選択肢4つの整理。GAMMA変更案は§7.9・§8.2で具体化。現在は保留、§8.4のR3-stay/R4-move検証を優先）。

**状態**：R4 実装・学習・評価は完了したが不成立と判定（§5.7）。根本原因の候補としてA-2のcritic設計（GAMMA=0.99による長期地平線平滑化、§7.9）に加え、より上流の設計問題（R3-Aの時点でA-2が動いているにもかかわらずprocess-2入力が零ベクトルだったこと、§8.4）も新たに浮上。GAMMA変更は保留し、まずR3-stay/R4-move（§8.4）でこの上流問題を検証する。

**Revisit at**：R3-stay/R4-move の結果が出た時点。それでも解決しなければGAMMA変更（§8.2）に戻る。

**GAMMA見積もり（既存データからの近似、critic再学習なし）**：

r2_a1random_a2rl の A-2 実データ（other_vision由来の実測報酬）から、各GAMMAでの割引報酬和 `G_t = Σ_{k=0}^{T-1-t} gamma^k * r_{t+k}` を直接計算し、「現在位置からG_tがどれだけ説明できるか」をRidge回帰（入力=`other_position`の2次元、出力=`G_t`）で評価した。

| GAMMA | 生G_tのstd | 位置からのRidge適合後std | 適合R²（位置がGを説明する力） |
|---|---|---|---|
| 0.99（現行） | 2.618 | 0.789 | 0.091 |
| 0.95 | 0.715 | 0.114 | 0.026 |
| 0.90 | 0.335 | 0.181 | 0.292 |
| 0.80 | 0.178 | 0.145 | 0.663 |
| 0.50 | 0.081 | 0.074 | 0.843 |

**方法上の注意**：生G_tは単一軌道のモンテカルロ推定値であり、SAC方策のサンプリングノイズをそのまま含む。GAMMA=0.99の生G_t std（2.618）が実際に学習済みのcriticの生Q std（0.172）よりずっと大きいのはこのため——実際のcriticはE[G|s]（状態条件付き期待値）を学習するので、このノイズは平均化されて消える。したがって上表の**絶対値は上振れした見積もり**であり、GAMMAを下げるほど「現在位置」が将来の割引報酬和を説明する力が強まるという**R²の推移（0.091→0.026→0.292→0.663→0.843）こそが方向性の指標**になる。

**結論**：GAMMA=0.8前後が有望な候補（R²=0.663への急増）。ただしこれは確証ではなく、実際のcriticの挙動（ニューラルネットは単純な線形Ridge回帰より滑らかに平均化する傾向がある）は再学習しないと確定しない。**GAMMA変更は保留中**——§8.4のR3-stay/R4-move検証を先に実施し、それでも解決しなければ再開する候補として残す。

### 7.9 R4不成立の根本原因特定：A-1/A-2のQ値域の本質的な乖離

**発覚**：2026-08-21、R4評価後のユーザーによる原因切り分け依頼。4項目の検証で原因を特定。

**項目1：MG(元論文)とVE(v4)の実装差分** — 完全に同一構造（`ov_enc`(64次元) → `LSTMCell(64→128)` → `Linear(128→出力次元)` → `tanh`）で、出力次元（MG=2, VE=8）以外に差はない。パラメータ数もMG≈99,586、VE≈100,360とほぼ同等。SMへの接続方法（process-2の"motion"枠）、損失への関与（直接教師信号なし、視覚予測のみで間接学習）も同一。**入力パイプラインの違いはQ̂²がA-1状態を符号化する原因にはなり得ない。**

**項目2：元論文でのMG出力・A-1実運動・A-2実運動の値域比較**

| | mean | std | range |
|---|---|---|---|
| MG出力 | (-0.002,-0.003) | (0.488,0.505) | [-1,1] |
| A-2の真の運動 | (-0.003,0.001) | (0.577,0.577) | [-1,1] |
| A-1の真の運動 | (0.000,-0.001) | (0.678,0.680) | [-1,1] |

3者ともほぼ同じ値域（std 0.49〜0.68）。運動は物理量として両エージェントで自然に一致する。

**項目3：v4でのQ̂²・A-1のQ1・A-2の真Q2の値域比較**

| | mean | std | range |
|---|---|---|---|
| Q̂²（VE出力） | -0.047 | 0.503 | [-1.00,1.00] |
| A-1のQ1 | 0.042 | 0.630 | [-1.00,0.99] |
| A-2の真Q2 | ≈0.87 | **0.0092** | [0.68,0.995] |

Q̂²はA-1のQ1に酷似し、A-2の真Q2とは全く異なる値域。**元論文（項目2）と違い、v4ではA-1とA-2のQ値がそもそも同じ空間に乗っていない**（Q値は各エージェント固有の報酬関数から生まれる量のため）。

**項目4：Q̂²をA-2の真Q値に置き換えた場合の視覚予測損失（決定的証拠）**

| 条件 | self_vision L1損失 |
|---|---|
| real（VE出力） | 0.1435 |
| zero | 0.1480 |
| **true_q2（A-2の真Q値、std=0.0092）** | **0.1492** |
| constant_mean | 0.1499 |

A-2の正解Q値を入れると、何も入れない(zero)より予測が悪化する。**SMの凍結重みがA-1寄りの値域に最適化されているため、VEは「正解を出すと損をする」構造にあり、これがQ̂²がA-1状態を符号化する方向に最適化された直接の理由。**

**結論**：これはVEの設計問題ではなく、上流（A-2のcritic設計）の問題。A-2のQ値の値域をA-1と同じオーダーに揃える必要がある。§7.3で記録していた懸念（A-1/A-2のQ値域の乖離、tanh正規化下でA-2の分散が5.5%まで縮小）が、R4という具体的な形で実際に学習を妨げることが実証された。

**対応案**：A-2のGAMMA（割引率）を下げる。GAMMA=0.99の長い地平線が「価値最大化方策の収束後の似た将来」で占められ、出発点の価値差を薄めている（§7.8の増幅率分析と同根）。報酬もA-1も変更不要。既存データでの近似検討は§8.2参照。

**Revisit at**：GAMMAを下げたA-2 critic再学習・再検証の結果が出た時点。

### 7.10 R3-A/R4間でh¹が完全一致する理由、exp1_l1_1000/exp3_1000間でh¹が変化する理由

**確認**：2026-08-21、ユーザーからの質問に対する実装確認。

**R3-A→R4でh¹→self/h¹→otherが完全一致（0.8805/0.5704）する理由**：`SuperpositionModule`は`self`と`other`で別々のLSTM状態（`state['self']`, `state['other']`）を保持し、同一の`nn.LSTMCell`を異なる入力で2回呼ぶ実装（`model/modules.py`）。h¹（`ss`）の計算は`self.lstm(cat([sv_enc, q1_vec]), (sh,sc))`のみに依存し、`ov_enc`やprocess-2側の入力（R3-Aでは零ベクトル、R4ではQ̂²）を一切参照しない。かつSM自体がR4で完全凍結されているため、process-1側の入力（`sv_enc`, `q1_vec`）が同一である限りh¹の計算は数値まで完全に同一になる。**ユーザーの理解で正しい。**

**exp1_l1_1000→exp3_1000でh¹が変化する（僅かだが実在する）理由**：exp3もSM・vision_encoder等を全て凍結しており（freeze list確認済み）、アーキテクチャ上はh¹がMGの出力（`om`）を参照しない点はR3-A/R4と同型。したがって変化の原因はMGの追加そのものではなく、**評価に使うデータセットの違い**（exp1_l1_1000は`self_random_other_stay_1000`のみ、exp3_1000は`self_random_other_stay_1000`+`self_random_other_clockwise`+`self_random_other_counter_clockwise`を結合した`self_random_other_stay_periodic_1000`）。同じ「ランダムに動くA-1」でも収集回・エピソード構成が異なるため、回帰に使うサンプル分布が変わり、h¹→self/otherの数値がわずかに変動する（0.9667→0.9579等）。**ユーザーの理解で正しい。**

### 7.11 評価スクリプトの状態汚染バグ（教訓として記録）

**発覚**：2026-08-21、R4の4条件アブレーション評価（`analyze/r4_ve_eval.py`）の実装時。

複数の推論条件（real/zero/constant_mean/true_q2）を**同一タイムステップ内で同じモデルインスタンスに対して順番に**呼び出す実装だったため、`SuperpositionModule`の内部LSTM状態（`self.state`）が各条件の`forward()`呼び出しのたびに上書きされ、2番目以降の条件が直前の条件の出力で汚染された状態から計算されていた。4条件が独立した時系列として評価されていなかった。

**修正**：条件ごとに独立したstateスナップショットの辞書を保持し、各条件の`forward()`呼び出し前後で`model.superposition_module.state`を該当条件のスナップショットに退避・復元する形に変更。修正前後で`real`条件自身の損失値が変化した（0.1262→0.1435）ことからも、バグが実際に数値へ影響していたことが確認できる。

**教訓**：ステートフルなRNNモジュールを持つモデルで、同一タイムステップ内に複数の「if-this-then-that」条件を順に評価するスクリプトを書く際は、モジュールの内部状態が呼び出しごとに上書きされることを必ず確認し、条件ごとに独立した状態を明示的に管理すること。

### 8.4 R3-stay / R4-move：R4不成立のより上流の原因を検証する

**発案**：2026-08-21、R4不成立の原因についてユーザーが提起。値域の不一致（§7.9）よりさらに上流に、R3-Aの設計自体の矛盾があるという仮説。

**検証したい問題**：R3-A は「A-2 が動いているのに process-2 の入力が零ベクトル」という矛盾した状態で学習していた。

元論文の構造を整理すると：
- **exp1_l1**：A-2 静止。process-2 の入力は定数。h² は静的な表現を持つ（h²→other = 0.9932）
- **exp3**：A-2 が動き出す。定数入力では予測が合わなくなる → この「予測が合わなくなる」という圧力が MG を駆動する

一方 v4 では R3-A の時点で A-2 が既に動いており（`r2_a1random_a2rl`、A-2はRL方策で移動）、process-2 の入力を零ベクトルのまま200エポック学習した。結果 h²→other = 0.9578 という高い値が出ている——**h² は、静止を意味する入力のまま、視覚だけで動く A-2 を追えるようになってしまった。**

すると R4 で VE を足しても必要とされない。h² は既に十分予測できているので、VE には「他者の価値を生成せよ」という圧力がかからない。余った自由度で予測に役立つ別の情報（A-1 の状態）を流し込んだ——これが今回の失敗の、値域の問題より上流にある可能性のある説明。

**設計（元論文との対応）**：

| 段階 | 元論文 | v5 |
|---|---|---|
| base | exp1_l1（運動、A-2静止） | **R3-stay**（Q値、A-2静止） |
| 生成 | exp3（運動、A-2移動、MG） | **R4-move**（Q値、A-2移動、VE） |

**実施項目**（各段階で個別に報告。まとめて走らせない）：
1. A-2静止データを新規収集（`r3_stay`等の名前）。A-1は現行と同じRandomAgent、A-2はエピソードごとに位置をランダム初期化して静止。A-2視覚も保存、Q値は焼き込まない、シード記録要件は現行と同じ。
   - 報告：A-2の静止位置の分布（アリーナ全域に一様か）、データサイズ、シード、保存フィールド一覧
2. R3-stayを学習：Q値入力、A-2静止、process-2は零ベクトル、pretrain元はexp1_l1_1000。「Q値版のbase学習」に相当。
   - 報告：4軸R²、視覚再構成誤差。**次に進む前に必ず報告し、進行の可否を確認すること**
3. R4-moveを学習：R3-stayからpretrainし、A-2が動くデータ（`r2_a1random_a2rl`）でVEを学習。
   - 報告：4軸R²、視覚予測損失の4条件比較（real/zero/true_q2/constant_mean）、Q̂²からA-1位置・A-2位置への回帰R²（現行R4は0.434/0.084——これが逆転するか）、Q̂²の統計・真Q値との相関・方向構造

出力先はR3-A/R4-existingと分離し、比較のため両方残す。

**判定基準**：R3-stayの4軸R²を元論文exp1_l1_1000（h¹→self=0.9667, h¹→other=0.0613, h²→self=0.0472, h²→other=0.9932）と比較。h²→otherは高いことが期待される（静止したA-2の位置をh²が表現している健全な状態）。**大きく異なる場合はQ値入力でのbase学習が元論文と同等に機能していないことになるため、そこで一旦停止して設計を見直す。**

**R3-stay 200エポック時点の結果（2026-08-22）**：

| | h¹→self | h¹→other | h²→self | h²→other |
|---|---|---|---|---|
| exp1_l1_1000（元論文） | 0.9667 | 0.0613 | 0.0472 | 0.9932 |
| R3-A(1000pretrain) | 0.8805 | 0.5704 | 0.0988 | 0.9578 |
| R3-stay（200epoch） | 0.7476 | 0.4125 | 0.0528 | 0.9492 |

h²→self（0.0988→0.0528、元論文0.0472に接近）とh¹→other（0.5704→0.4125）は両方とも改善方向に動き、A-2静止という設計判断自体は正しい方向であることを示した。ただしh¹→otherは元論文の6.7倍とまだ大きく乖離しており、部分的な改善に留まる。

一方、視覚再構成誤差は全面的に悪化した（自他分離の改善と矛盾するように見える）：

| | self_vision | feature_prediction_self | feature_prediction_other |
|---|---|---|---|
| exp1_l1_1000 | 6.31 | 0.96 | 6.24 |
| R3-A(1000pretrain) | 11.22 | 13.39 | 21.34 |
| R3-stay（200epoch） | 17.97 | 13.09 | 53.31 |

**学習曲線を確認したところ、単純な学習不足が濃厚と判明**。R3-A(1000pretrain)の`feature_prediction_other`はepoch10(42.05)からepoch160(49.06)まで160エポックかけてゆっくり悪化し続け、epoch170で突然38.36→180で30.48→200で21.34と、最後の30〜40エポックで急激なブレイクスルー（2.3倍改善）が起きていた（`self_vision`も同じepoch170で14.7付近の長い停滞から一気に11.2まで低下）。R3-stayの同指標はepoch10〜200まで一貫して45〜67の範囲でノイズ状に上下するのみで、この種のブレイクスルーが一度も起きていない。h¹→self=0.7476がR3のゲート基準（0.90）を下回っていることとも整合する。

**対応**：`config/exp/r3_stay_400.yml`（max_epochs=400のみr3_stay.ymlと異なる）で再学習中。収束（ブレイクスルーの発生）を確認してから4軸R²を再評価する。r3_stay.yml（200epoch版）はこの学習不足だった参照として残す。pretrain効果の検証・no-pretrain比較・視覚データ分散比較（当初依頼の項目2〜4）は、学習不足の可能性が高いため保留。

**より広い含意（2026-08-22）**：R3-Aがepoch170でようやくブレイクスルーしていたなら、**200エポックというR3-A/R4の学習量設定自体が際どかった**ことになる。R3-A（200epoch時点のh¹→self=0.8805等）もR4の全結果も、収束値ではなく「ブレイクスルー直後、まだ落ち着いていない状態」を見ていた可能性がある。過去のR3-A/R4の結果は、この前提のもとで再解釈が必要。

**R3-A(400epoch)の対照実験**：R3-stay-400の結果次第で実施を判断する（今すぐは不要）。本流はR3-stay→R4-moveでありR3-Aに戻る計画ではないが、R3-stay-400が良い結果を示した場合に「A-2静止という設計」の効果か「400エポックという学習量」の効果かを切り分けるための対照条件として位置づける。R3-Aもepoch170でブレイクスルーしていたため、400まで伸ばせば改善する可能性がある。

**元論文（exp1_l1_1000 / exp3_1000）の収束確認（項目3の結果）**：`analyze/plot_training_curve.py`で全4条件（r3_stay, r3_a_direct_1000pretrain, exp1_l1_1000, exp3_1000）のtrain/eval曲線を重ね書きして確認した（`data/result/baseline_v4/r3stay_r3a_paper_comparison_training_curve.png`）。

**元論文の2条件（exp1_l1_1000・exp3_1000、運動入力）は、200エポックよりずっと早く（おおむね epoch 50〜80 まで）滑らかに収束しており、R3-A/R3-stayで見られた「長い停滞→急激なブレイクスルー」パターンは一度も現れなかった。** exp1_l1_1000のfeature_prediction_otherに至ってはepoch10の時点で既にほぼ最終値（6.24〜6.27の範囲でepoch10〜200まで実質フラット）。

**これ自体が知見**：Q値入力モデル（R3-A, R3-stay）は運動入力モデル（元論文）より収束が明確に遅く、かつ収束パターンの質そのものが異なる（滑らかな単調減少 vs 長い停滞後の急激な相転移）。Q値は状態の関数であり運動指令のような直接の物理的手がかりを持たないため、SMが有用な使い方を見つけるまでに探索的な学習過程を要すると考えられる（未検証の追加仮説）。

**注意（過度な期待をしないための留保）**：R3-stayのfeature_prediction_other曲線は、R3-Aが見せた「緩やかに単調悪化してから急落する」という規則的なパターンとは異なり、45〜70の範囲で不規則に上下するノイズ状の挙動を示している（上記の同じ画像で確認可能）。R3-stayが同種のブレイクスルーに近づいているのか、それとも異なる（ブレイクスルーに至らない）力学にあるのかは、曲線の形だけからは判断できない。400エポックの結果を実際に見るまで断定しない。

**GAMMA変更との関係**：GAMMA変更（§7.8, §8.2）は保留し、R3-stay/R4-moveの結果を見てから判断する。値域が揃ってもVEに圧力がかからなければ意味がない。逆にR3-stay/R4-moveで構造が正されれば、GAMMAを変えずに学習が成立する可能性もある。

## 9. 運用ルール

1. **複数の変更を同時に入れない**。1ゲートにつき1変更
2. **Q値をデータセットに焼き込まない**
3. **A-1 / A-2 の選好設定を変えない**（Red / Green 固定）
4. **A-2 の速度スケールを A-1 と変えない**
5. **正規化を stage ごとに変えない**。全 stage で同一
6. **VE の出力を無拘束にしない**。必ず tanh で値域を拘束
7. **R3 以降で MG をモデル構成に残さない**
8. **VE の入力に MG の出力を含めない**
9. **シードを固定しないまま実験を回さない**
10. **位置回帰（`regression.py` / `regression_v3.py`）とランドマーク識別（`regression_fixed.py`）を混同しない**
11. **critic を再学習したら必ず健全性チェック**
12. **元論文の資産を確認してから独自実装を検討する**
13. **§3.2 の削除禁止資産に手を触れない**
14. **`my_research/step3/` は別研究ライン。触らない**

## 10. 評価ハーネス（各ゲートで記録）

1. **位置回帰 R²（4軸）**：`analyze/regression_baseline_v4.py`
2. **視覚再構成誤差**（h¹ / h² それぞれ）
3. **A-1 / A-2 位置分布**：mean, std, ヒートマップ
4. **A-1 / A-2 運動分布**：std, ヒストグラム ← §7.2 の教訓
5. **Q値の統計**：正規化前後の mean/std/percentile
6. **A-2 の運動プローブ**：凍結 h² から真の運動を予測する事後プローブの R²
7. **R4 以降**：Q̂² の統計とヒートマップ、A-2 真Q値との相関
8. **学習曲線の全エポック確認（必須、2026-08-22追加）**：`analyze/plot_training_curve.py --exp_config <name>`。最終エポックの数値だけを見て「収束した」と判断しない——§8.4で発見した通り、Q値入力モデルは「長い停滞→急激なブレイクスルー」という、運動入力モデル（元論文）にはない収束パターンを示すことがある。最終値だけ見ていると、実際には学習不足なのを「性能が悪い」と誤診断しうる。少なくとも train/eval 両方の self_vision・feature_prediction_self・feature_prediction_other の3指標を、実験開始から終了まで通しでプロットし、後半で傾向が変化していないか目視確認すること。

すべて `data/result/` 配下に JSON 保存し、**実験ID・git commit hash・シードをセットで記録**すること。
